A Workspace is the durable, named Axocoatl identity for an authorized project
directory. A Session is durable work and conversation created inside that
Workspace. Onboarding does not create this directory or modify it into an
Axocoatl project; **Open workspace…** authorizes an existing folder after the
app starts. Start with one Agent and a disposable or clean Git repository until
you know the tool and sandbox behavior you want.

This guide uses the workbench's native Ollama or OpenRouter Agents. If you configured
Claude Code or Codex to write, [Your first fix](/start/first-fix/) runs that program
headless; the workbench team onboarding created uses your reviewer's native model.

## Before you open the folder

Run the repository's own checks once and inspect Git:

```sh
git status --short
```

Know the command that should decide whether a change is acceptable—for example
`cargo test`, `npm test`, or `pytest`. Axocoatl can detect common project
metadata, but the repository remains the authority.

## Create the Session

<Steps>

1. After [onboarding with `--start none`](/start/onboard/#recommended-setup) and a
   ready doctor result, start `axocoatl dev` from any directory and leave that terminal
   open. If onboarding already started it, or the Always-On Service runs, use that
   daemon instead of starting another. Open its `Sign in:` link. It uses the current
   user's configuration and data root. To print the link again, run `axocoatl url`;
   the browser keeps the sign-in for 30 days. The first screen checks what a Session needs, as
   `axocoatl doctor` does: while something fails, a checklist names each step
   left with its exact command (Podman's machine, the Ollama version and cloud
   mode, a model to pull), and the status pill in the rail reads **N setup steps
   left** until it reads **ready**; select it to see the checklist again. Without
   Podman or its machine, **Create session** stays blocked with the fix. The New
   Session dialog checks Podman again when it opens, and **Create session** waits
   for that check, at most ten seconds. `axocoatl dev` also logs a warning at
   start when native Sessions will refuse the configured Ollama server.
2. From the Workspace switcher, choose **Open workspace…** and navigate to the
   repository. Folders that are Git repositories carry a **git** mark. The
   dialog starts in your home folder, but Axocoatl does not open the home
   folder, a folder above it, or a folder that contains Axocoatl's own
   directories as a Workspace unless you type that folder's name to confirm;
   Axocoatl's own directories never open.
3. Confirm or edit the Workspace name. The canonical path remains visible as
   secondary context; renaming the Workspace never renames the folder.
4. With that Workspace selected, choose **New session** beside **Sessions** and
   give the Session its own work-item name.
5. Keep **Single agent** for the first run and select a configured Agent. With
   the [default team](/start/onboard/#default-team), keep **Lead**.
6. Leave **Exposed ports** empty unless the task needs Preview. A root
   `package-lock.json` can suggest the curated Node 20 image. A devcontainer's
   exact image is shown as repository input and may require arbitrary-image
   trust; under E2B, clear it because the daemon-global template is the runtime.
7. Review the proposed project setup. A command such as `npm ci` is shown but
   remains unchecked and unexecuted until you approve that exact command. You
   may edit it or explicitly continue without a setup command. If the daemon
   defaults an exact devcontainer command to checked, that policy is visible;
   your checked or unchecked reviewed choice wins.
8. Wait for the Session environment to report **Ready**.
9. For a native Session, Send reads **Set budget** until the Session's team and
   budget are applied; it opens **Team & budget**. Its limits come filled in from
   the built-in `fix` loadout: 4 activations, 400 provider and tool invocations
   and 4,000,000 tokens per Agent, $0 of cost for a local Ollama model (a hosted
   model gets the loadout's $10 cap), and an expiry 24 hours from now. Switch to
   **Edit** to review or change them, then **Preview** and **Apply**; nothing is
   approved until you do. With the default team, Lead's panel also offers Scout and
   Reviewer as read-only helpers. Lead works alone unless you select **Let this Agent
   delegate to helpers**; their limits come filled in too (3 activations, 120
   invocations, 1,500,000 tokens each), within Lead's. Preview refuses a token limit
   a turn cannot use and names the minimum: each model call reserves the model's
   whole context plus its output, and a turn with tools needs a call and the one
   after it, for example 73,728 tokens for a 32,768-token context and 4,096 output
   tokens. An expiry must be within a year.
10. Send a bounded first request from Conversation.

</Steps>

New data roots use native execution; use local Podman for their repository tools
and required checks. Select a reviewed local Ollama profile or
an eligible OpenRouter-credit profile for this first Session; the other provider
adapters remain on compatibility paths. [Providers](/configure/providers/) lists
the exact requirements. A successful `doctor` check does not replace Team review.

A useful first prompt is:

```text
Inspect this repository without changing files. Identify its purpose, the command
used for its automated checks, and the three files most relevant to a small first fix.
Report any uncertainty explicitly.
```

Then ask for a small change:

```text
Fix the smallest verified issue you found. Run the repository's documented check
command, summarize the result, and do not commit.
```

## Verify the result

The accepted result is not just the final prose. Check the workbench:

1. Expand tool calls in Conversation to see the commands and files used.
2. Open **Files** to inspect the edited file.
3. Open **Source Control** and select **Last turn** to isolate paths touched by
   the most recent Agent turn.
4. Run the repository check in Terminal if the Agent did not, or repeat it
   independently.
5. Commit only after you have reviewed the actual diff.

<Aside type="note" title="Axocoatl does not commit the normal result for you">
Agent edits remain in the Session working tree. Keeping an Attempt also applies
its delta without committing. Source Control exposes stage, unstage, discard,
hunk review, branch checkout, and commit as deliberate user actions.
</Aside>

## If creation fails

- Run `axocoatl doctor` and resolve what it reports for Podman. When local Podman
  cannot run the Session yet (no Podman machine, for example), **Create session**
  saves nothing and says what to run; it starts a stopped machine itself.
- Confirm the selected Agent exists in the active user configuration (or the
  explicit file passed with `--config`).
- An image outside Axocoatl's curated presets is rejected unless
  `sandbox.allow_untrusted_images: true`.
- Session startup never installs Podman or creates its VM; `axocoatl onboard` does,
  after asking, where it can (Homebrew on Apple silicon, or a package manager it knows
  on Linux; otherwise it names the installer). Run it, or follow the `doctor` guidance,
  then retry.
- With `sandbox.network: none`, the local image must already contain Axocoatl's
  required repository commands; offline startup cannot download missing tools.
- E2B uses one daemon-global template and rejects a per-Session or devcontainer
  OCI image. Clear the image or switch the daemon to Podman.
- A detected repository setup command is only a proposal. Open **Review setup**
  and approve the exact command or explicitly continue without one.

## Open the workbench from another computer

The workbench listens only on the loopback address of the computer that runs
`axocoatl dev` or the [Always-On Service](/operate/service/), and answers only requests
that reach it there. On a Linux server or VM without a desktop that you reach over SSH,
forward its port from the computer whose browser you use:

```sh
ssh -N -L 8080:127.0.0.1:8080 you@server
```

Keep the same port number on both ends: 8080, or the `server.port` the server's
configuration sets, because the sign-in link names it. Then run `axocoatl url` on the
server and open the link it prints in that browser. Previews open on `*.localhost`
names at the port the browser used, which browsers send to the loopback address, so they
reach the server through the same forward. While the forward runs, a program on your
computer can reach that port as a program on the server can; the sign-in link is what
lets a browser in, so keep it private.
