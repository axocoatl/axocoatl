Axocoatl publishes release binaries for Linux and macOS 11 or newer on x86_64 and aarch64.
Windows runs through WSL2; there is no native Windows binary.
The Linux archives target GNU libc 2.35 or newer. They do not run on
musl-based distributions such as Alpine; use the Cargo or source path there.

## Install the binary

<Tabs syncKey="install">
  <TabItem label="Release binary">
    ```sh
    curl -fsSL https://axocoatl.ai/install.sh | sh
    ```

    The installer resolves the latest GitHub release, downloads the tarball for
    the current OS and architecture, and requires its matching SHA-256 file.
    A missing, malformed, or mismatched checksum stops installation. The script
    also stops before download when Linux does not report GNU libc 2.35 or
    newer, or when macOS is older than version 11. It installs to
    `/usr/local/bin` when writable and otherwise to `~/.local/bin`.
  </TabItem>
  <TabItem label="Cargo">
    ```sh
    cargo install axocoatl-cli
    ```

    Building from crates.io requires Rust 1.88 or newer.
  </TabItem>
  <TabItem label="Source checkout">
    ```sh
    git clone https://github.com/axocoatl/axocoatl
    cd axocoatl
    cargo build -p axocoatl-cli --release
    ./target/release/axocoatl --version
    ```

    The root package is not the CLI. Keep the explicit `-p axocoatl-cli`.
  </TabItem>
</Tabs>

All three paths install one `axocoatl` executable. Cargo and source builds compile
the host application and include Axocoatl's prebuilt Linux process supervisor for
its sandbox. There is no separate supervisor installation or startup download.
The [supervisor source](https://github.com/axocoatl/axocoatl/tree/main/crates/axocoatl-exec)
and [explicit rebuild instructions](https://github.com/axocoatl/axocoatl/blob/main/docs/EXEC_SUPERVISOR_BUILD.md)
are available for contributors who want to rebuild those embedded bytes.

Verify that your shell can find the binary:

```sh
axocoatl --version
axocoatl --help
```

If installation used `~/.local/bin`, add it to your shell path:

```sh
export PATH="$HOME/.local/bin:$PATH"
```

The binary is installed once for the current user or system. The next command,
`axocoatl onboard`, creates user-level Axocoatl configuration and data; it does
not create a repository or Workspace.

## Runtime prerequisites

`axocoatl onboard` sets these up, asking before each change; see
[Set up Axocoatl](/start/onboard/). What it needs:

- **Rootless Podman**, for every Session and every `axocoatl run`. On macOS Podman runs
  containers in a Linux virtual machine; onboarding installs Podman with Homebrew
  (`brew install podman`) and creates and starts the machine:

  ```sh
  podman machine init --cpus 6 --memory 8192 --disk-size 60
  podman machine start
  ```

  Axocoatl is tested with this size of machine (onboarding uses half the computer's
  processors and memory when that is less); the Claude Code and Codex images and your
  project's checks run inside it, while Ollama runs on the Mac itself. A rootful
  machine (Podman Desktop's default) does not work for `axocoatl run`; onboarding
  offers to switch it to rootless. On Linux, Podman runs containers directly and needs
  no machine: install Podman 4.3 or later (4.9 is tested; Ubuntu 22.04's 3.4.4 does not
  work), for example `sudo apt-get install -y podman`, and give your user a range of
  subordinate ids (`sudo usermod --add-subuids 100000-165535 --add-subgids
  100000-165535 $USER && podman system migrate`) if it has none.
- **A writer and a different reviewer model**: Claude Code (a Claude Pro or Max plan),
  Codex (a ChatGPT plan or an OpenAI API key), a local Ollama pair, or OpenRouter
  credits. Claude Code and Codex write but do not review, so they need a reviewer on
  Ollama or OpenRouter.
- **Ollama**, for local models: Ollama **0.40.6 or later** on this computer with its
  cloud features disabled. Later 0.40 releases are accepted; a later 0.x release (0.41
  or later) is accepted once the contract probes pass on each model. Onboarding
  installs it (`brew install ollama && brew services start ollama` on macOS;
  `curl -fsSL https://ollama.com/install.sh | OLLAMA_VERSION=0.40.6 sh` on Linux),
  turns the cloud features off where the running server reads them, and pulls the
  models.

Local models need memory. With 48 GB, `qwen3-coder:30b` (18.6 GB) writes and
`gpt-oss:20b` (13.8 GB) reviews, one at a time; with 96 GB or more the reviewer is
`gpt-oss:120b` (65.4 GB), the one Axocoatl has measured. No local pair has been tested
below 48 GB; there onboarding suggests OpenRouter for the reviewer, or for both.
They are large downloads. A fix run needs a context of at least 16384 tokens, and
Ollama gives a model 4096 on computers with less than about 23 GiB of graphics memory;
onboarding then offers to set `OLLAMA_CONTEXT_LENGTH=32768` for the Homebrew or
systemd Ollama service and restart it (for the app or an `ollama serve` you run, it
says what to set). Native
Sessions run only GGUF models: on Apple silicon, Ollama pulls the MLX variant of some
models, which Axocoatl refuses; `ollama pull --runner llamacpp <model>` (an
undocumented Ollama flag) pulls the GGUF one.

## Windows through WSL2

<Steps>

1. In an administrator PowerShell, install WSL2 and reboot when requested:

   ```powershell
   wsl --install
   ```

2. Open the Linux distribution and install Podman. On Ubuntu:

   ```sh
   sudo apt-get update
   sudo apt-get install -y podman
   ```

3. Run the release installer **inside WSL2**, then continue with
   [user-level onboarding](/start/onboard/).

</Steps>

`axocoatl dev` runs inside WSL2. Open the sign-in link it prints
(`http://localhost:8080/?token=…`) in the Windows browser; WSL2 normally
forwards that loopback port to the host.

<Aside type="caution" title="The default sandbox still needs Podman">
Installing the Axocoatl binary does not install or start Podman; `axocoatl onboard`
does, after asking. Without a ready Podman runtime, `doctor` fails, and neither
Sessions nor `axocoatl run` can use the default local sandbox. A deliberately
configured E2B Cloud backend is the separate remote option for workbench Sessions.
</Aside>
