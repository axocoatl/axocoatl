# Providers

Axocoatl supports six provider ids. Each agent picks its own
provider and model, so you can route cheap, high-volume steps to a local model
and reserve a frontier model for the one step that needs it.

## The six providers

The five hosted/OpenAI-compatible adapters are registered at daemon bootstrap
when their config block is present and their key is non-empty. Ollama is created
per agent from its configured `base_url` and does not use an API key.

| `provider:` value | Backend |
|---|---|
| `ollama` | A local or remote Ollama endpoint |
| `openai` | OpenAI — or compatible implementations (see below) |
| `anthropic` | Anthropic Claude |
| `gemini` | Google Gemini |
| `mistral` | Mistral |
| `openrouter` | OpenRouter (`openrouter.ai/api/v1`) |

OpenRouter reuses the OpenAI client pointed at `openrouter.ai/api/v1` with the
provider id `openrouter`, so you select it with `provider: openrouter`.

## Configuring a provider

Each provider block carries an `api_key`. Use `${ENV_VAR}` interpolation — the
value is read from the environment (or your `.env`) at load time, and keys are
held as secrets that never appear in debug output.

```yaml
agents:
  - id: assistant
    name: "Assistant"
    provider: anthropic
    model: claude-sonnet-4-6

providers:
  anthropic:
    api_key: "${ANTHROPIC_API_KEY}"
```

Ollama is the exception — it takes a `base_url`, not a key:

```yaml
providers:
  ollama:
    base_url: "http://localhost:11434"
```

## Per-agent provider + model

`provider:` and `model:` are set **on each agent**, not globally. A shared
provider is registered once; each agent's configured `model` is sent as a
per-request override, so two agents on the same provider can run different
models.

```yaml
agents:
  - id: triage
    provider: ollama          # cheap, local — high-volume classification
    model: llama3.2
  - id: synthesizer
    provider: anthropic       # frontier — the one hard step
    model: claude-sonnet-4-6

providers:
  ollama:
    base_url: "http://localhost:11434"
  anthropic:
    api_key: "${ANTHROPIC_API_KEY}"
```

This cheap-local-plus-frontier pattern is the point of per-agent selection:
the easy steps can use a local model while the frontier step uses a hosted one.
See the [`multi-provider`](https://github.com/axocoatl/axocoatl/tree/main/examples/multi-provider)
example for a runnable mock with a cost breakdown.

## OpenAI-compatible servers (LM Studio, MLX, vLLM)

The `openai` provider honors a configurable `base_url`. When set, requests go
to that endpoint instead of `api.openai.com`, so it can target compatible
implementations such as **LM Studio, MLX/oMLX, and vLLM** while still using
`provider: openai`. The URL must include the API-version suffix the server
expects (usually `/v1`).

```yaml
agents:
  - id: local
    provider: openai
    model: "your-local-model-name"   # sent per-request to the server

providers:
  openai:
    api_key: "${LOCAL_API_KEY}"      # many local servers accept any non-empty value
    base_url: "http://localhost:1234/v1"   # e.g. LM Studio
```

Because the agent's `model` is sent per request, one OpenAI-compatible provider
block can serve several agents each running a different local model.

## One-target rate-limit fallback

A hosted provider can declare one `fallback` target as `provider` or
`provider:model`. If the primary request returns a rate-limit error before a
stream is established, Axocoatl retries that request once against the target.
It does not traverse a chain, and non-rate-limit or mid-stream errors do not
switch providers.

```yaml
providers:
  openai:
    api_key: "${OPENAI_API_KEY}"
    fallback: "anthropic"
  anthropic:
    api_key: "${ANTHROPIC_API_KEY}"
```

## Local-only

Point an agent at `ollama` with a loopback `base_url`, supply no hosted-provider
keys, and set `sandbox.network: none` to block session-tool egress. Do not add
remote MCP servers, webhooks, web search, or an E2B session when you need a
local-only run. The embedding model may download once before inference. See the
[`local-only`](https://github.com/axocoatl/axocoatl/blob/main/examples/configs/local-only.yaml)
config in the examples gallery.

## Verification boundary

The repository tests provider request/response and tool-call adapters with mock
HTTP fixtures. A live provider also depends on valid credentials, a model id the
account can access, and that provider's current API behavior. The project does
not publish an exact live-parity guarantee across every provider, model, and
product surface.
