Source Control is the evidence boundary between an Agent's account of the work
and the repository state you will keep. Open **Files**, then choose **Source
Control** in the explorer column.

## Choose a review scope

| View | What it shows |
| --- | --- |
| **All** | Every changed path in the Session working tree |
| **Last turn** | Current changed paths matching those attributed to the most recent durable Session turn |
| **Staged** | Changes currently in the Git index |
| **Not staged** | Working-tree changes not in the index |

Last turn filters the repository's current Git status and diff by the path names
attributed to the latest durable turn. For a native turn those paths come from the
repository captures recorded before and after each Agent activation, the same
attribution receipts and **Keep as PR** use, and they are read again from the
Session's history after the daemon restarts. It is useful for narrowing review,
but it is not a frozen per-turn diff. A later edit to an attributed path can appear in
the view, and a reverted change no longer appears. If several actors edit the
same path, Last turn cannot separate their hunks by author.

Git also cannot represent every external side effect. A tool may have changed a
path outside the authorized repository or touched a remote system.

## Inspect and stage

<Steps>

1. Select **Last turn** and open each changed file.
2. Read the diff in the editor, including deletions and generated files.
3. Stage a whole file with **+**, or expand its hunks and stage only the
   accepted changes.
4. Switch to **Staged** and review the exact commit candidate.
5. Enter a commit message and commit the staged changes. Use **Stage all +
   commit** only when every working-tree change belongs in the commit.

</Steps>

The same controls can unstage a file or hunk without changing its working-tree
content. Branch checkout is available from Source Control; inspect status first
and do not switch across unresolved work you do not intend to carry.

## Who a commit is by

A commit you make from Source Control is yours. Its author and committer are the
`user.name` and `user.email` that Git on your computer uses for that repository
(the repository's own setting, else your global one), the same identity **Keep as
PR** commits with, and it is dated in your time zone. The line under the commit
box shows it: **Commits as Your Name &lt;you@example.com&gt; · not signed ·
repository hooks don't run**.

- With no name or email set, the workbench refuses to commit and says so. Set them
  in a terminal with `git config --global user.name "Your Name"` and
  `git config --global user.email you@example.com`.
- A repository that signs its commits (`commit.gpgSign`) is refused too: the
  sandboxed Git cannot reach your signing key. Commit from your terminal there.
- The repository's hooks (`pre-commit`, `commit-msg`) do not run for a commit made
  here. Run them yourself, or commit from your terminal, when they matter.
- When Git refuses a commit, the workbench shows Git's own message and nothing is
  committed. With nothing staged, it says nothing was committed.

Commits Axocoatl makes for itself, such as a Ways baseline and the attempt refs
under `refs/axo/`, are by `Axocoatl <agent@axocoatl.local>`. Axocoatl never writes
an identity into your repository's configuration.

## A folder that is not a Git repository

Reading Source Control never turns a folder into a Git repository. In a folder
that is not one, Source Control says so and offers **Initialize Git here**, which
runs `git init` and nothing else: nothing is staged or committed, and no identity
is written. Stage and commit afterwards as usual.

## Discard carefully

Source Control can discard one unstaged hunk, one file, or all unstaged files.
The all-files action includes untracked files and keeps staged work intact.
These are destructive Git operations and the workbench asks for confirmation.

<Aside type="danger" title="Discard is not an undo service">
Discarded unstaged content may be unrecoverable. Inspect the diff, copy any
needed material elsewhere, and confirm the exact scope before proceeding.
</Aside>

## After keeping an Attempt

**Keep this one** applies an uncommitted delta to the main Session working tree.
Use this sequence before committing it:

```sh
git status --short
git diff --check
```

Then run the check used during comparison from the main Session, review **All**
and **Last turn**, and stage only the intended result. The Last turn view is the
current diff filtered to attributed paths, not an archived copy of the candidate
diff. Keep does not merge an Attempt branch into your project history and does
not commit automatically.

## When Last turn is empty

An empty Last turn can be correct when the last turn made no file changes. When
Axocoatl cannot tell what part of the last turn changed (an activation's capture
is missing or too large to compare), Last turn says so instead of reporting no
changes; review **All**. If you expected edits:

- confirm the turn reached a durable terminal state;
- switch to **All** to check for older or unattributed working changes;
- inspect `git status --short` in Terminal;
- review the turn's tool calls for work outside the repository or an error
  before write completion.
