Two tools let an Agent look at the app a Session is building:

- `browser` opens a URL in a fresh headless Chromium, runs a short list of steps
  (click, fill, press, wait, expect text), and returns the page's accessibility
  snapshot, console errors and failed requests as text. Each step comes back with the
  Playwright line that does the same thing, so the Agent can paste it into a test.
- `browser_check` runs one Playwright test file against the app, with one worker and
  no retries, and returns each test's status and first error. Use it to confirm that a
  reproduction fails for the reason it reports.

Both run in a container of their own, not in the Session container and not on your
computer.

## Set up

<Steps>

1. Build the browser image once:

   ```sh
   axocoatl browser install
   ```

   This builds `localhost/axocoatl-browser:pw1.60.0` with Podman: Node 22 (a pinned
   image digest), Playwright 1.60.0 from a lock file, and Playwright's headless
   Chromium. The build downloads all three; that is network access you start, on your
   computer. `axocoatl doctor` reports whether the image is present.

2. Add a `browser` block to the configuration. Its presence turns the tools on:

   ```yaml
   browser: {}
   ```

3. List the tools for each Agent that should have them. The `tools` list is exact, so
   an Agent that does not list a tool is never offered it:

   ```yaml
   agents:
     - id: qa-lead
       tools: [read_file, list_dir, grep, glob, write_file, edit_file, bash, browser, browser_check]
   ```

4. Restart the daemon, then start (or restart) the Session. A Session container
   started before `browser:` was configured has no socket volume for the browser and
   the tools say so.

</Steps>

The full block, with its defaults:

```yaml
browser:
  image: localhost/axocoatl-browser:pw1.60.0
  allow: []                 # declared hosts, same entries as sandbox.egress.allow
  private_destinations: []  # private ranges allow entries may reach
  snapshot_max_bytes: 16384 # 1024-65536
  timeout_secs: 120         # 10-170, per call
  max_parallel: 2           # 1-4 calls at once per Session
```

The browser tools need local Podman: `browser` with `backend: e2b` is a configuration
error. A different `image` should be pinned by digest (`image@sha256:…`); `validate`
and `doctor` warn about a tag.

## How the browser reaches your app

The app under test is whatever listens on the Session's exposed ports, at the same URL
the Agent uses inside the Session: `http://localhost:<port>`. Start it the way you
always do, for example `npm run dev` in the Terminal pane.

- The browser container has no network interface other than loopback.
- Inside it, Axocoatl listens on `127.0.0.1:<port>` and `[::1]:<port>` for each exposed
  port and forwards each connection to a Unix socket that the Session container serves
  from its own `127.0.0.1:<port>`. Any other `localhost` port refuses the connection.
- The app must listen on `127.0.0.1` or `0.0.0.0` inside the Session. An app that
  listens only on `::1` is not reached.
- The forwarder runs inside the Session container. If something in the Session stops
  it, the next browser call starts it again.

## Declared hosts

With an empty `allow`, the browser reaches only the Session's exposed ports. Every
other request fails, and the result lists it under `network.blocked`.

Hosts the app needs from outside, such as a font or an API, go under `allow`, with the
same entries as [`sandbox.egress.allow`](/reference/config/#sandbox): presets, host
names, `*.` subdomain wildcards and IP ranges.

```yaml
browser:
  allow:
    - host: fonts.gstatic.com
    - host: api.example.test
      ports: [443]
```

Chromium reaches those hosts only through Axocoatl's egress proxy, which runs as a
sidecar container for the Session and asks the daemon about every connection. The
daemon checks the host against `browser.allow` before anything resolves it, resolves
allowed names on your computer, refuses loopback, link-local and other special
addresses, refuses private addresses unless `private_destinations` lists their range,
and writes each decision to the Session's network record before answering. Each call
gets its own proxy credential, passed to the driver on its standard input and revoked
when the call ends. The Session's own `sandbox.egress` list does not apply to the
browser, and `browser.allow` does not apply to the Session.

`browser.allow` must be empty with `network: none`. To put the sidecar on a specific
Podman network, set `sandbox.egress.sidecar_network`.

Chromium sends a proxy credential only after the proxy asks for one, so each call's
first request through the proxy appears in the record as refused with
`no_credential`, followed by the same request with the call's credential.

<Aside type="caution" title="The proxy cannot see inside TLS">
A declared host that serves many sites, such as a CDN, can be used to reach those
sites.
</Aside>

## What the tools return

Results are text. No screenshot reaches the model.

`browser` takes a `url`, up to 40 `steps`, `snapshot` (`aria`, `text` or `none`) and an
optional `viewport`. A step's `target` is one of `role` (with an optional `name`),
`label`, `text`, `testid` or `css`, and `nth` picks one of several matches. There is no
step that runs script in the page. Only `http` and `https` URLs without a user name or
password are opened. The result has the final URL, title and status, each step's
outcome, time and Playwright line, the snapshot (cut to `snapshot_max_bytes`), console
errors, page errors, dialogs, and failed, refused and HTTP-error requests.

`browser_check` takes the repository `path` of a test file, or its source as `script`,
plus an optional `grep` and `base_url` (by default the app on the Session's first
exposed port). Tests import `test` and `expect` from `@playwright/test`, and
`page.goto('/')` opens `base_url`. The result has each test's title, line, status, time
and first error with its location and source snippet, and the counts.

## What leaves the repository

`browser` sends nothing from the repository. `browser_check` sends the test file it runs
and the source files that file imports by a relative path (`.ts`, `.js`, `.mjs`, `.json`
and the like, at most 32 files and 1 MiB), read without following symbolic links and
never from Axocoatl's own directories. They are written to a fresh directory in the
browser container's memory-backed `/tmp` and removed when the run ends. The test runs
there with the browser container's network: the Session's exposed ports and the
declared hosts, nothing else.

## What is recorded

Each call adds a `browser` event to the Session's
[network record](/reference/http-api/#session-network-record): the tool, the tool call,
activation and Agent, the URL and final URL, the status (or the test status), how many
requests were blocked, the egress credential's tag when declared hosts were used, and
the time. Connections to declared hosts appear as `open` and `close` events under the
call's `browser` binding. Connections to the app under test do not pass the proxy; the
tool result summarizes them.

A `browser` call keeps a screenshot of the page as the call left it, and a failing
`browser_check` keeps its first failing test's screenshot, beside the record. The
event names it by its SHA-256, and
`GET /api/sessions/{id}/network/screenshots/{sha256}` returns it. A Session keeps at
most 2000 screenshots of up to 1 MiB each.

## Helpers and reviewers

A read-only helper or required reviewer gets the browser tools only when its own
template lists them. They are not write tools, so a helper that lists them can still
take delegated work. The browser can change the app's state, through the app, but not
the repository's files.

## Limits

- `network: egress` Sessions are not available in this build, so the browser runs with
  `bridge` and `none` Sessions.
- The browser container keeps running until the Session stops, and is removed with it.
- Each call starts a fresh browser; nothing carries over between calls except what the
  app itself stores.
