A loadout is one YAML file that says everything a run needs: its Agents, their roles and
models, the required checks with their timeouts, an optional required reviewer, the hosts
the Session may reach, its budgets and the prompt. [`axocoatl run`](/reference/run/) runs
one headless against the running daemon and exits with a code a script can act
on. Settings displays loadouts; nothing in the workbench runs one.

Five loadouts are built in:

| Id | What it runs | Parameters |
| --- | --- | --- |
| `fix` | One writer, the repository's check command as a required check, and a required review by another model for up to 3 rounds. The writer answers every finding with accept or reject and a reason. | `writer_model`, `reviewer_model` (both required) |
| `fix-claude-code` | `fix` with the [Claude Code CLI](/configure/external-agents/) as the writer, from the `claude-code` recipe image, with the token `axocoatl connect claude-code` stores. | `reviewer_model` (required), `writer_model` (default `anthropic:sonnet`) |
| `fix-codex` | `fix` with the [Codex CLI](/configure/external-agents/) as the writer, from the `codex` recipe image, with an OpenAI API key or a ChatGPT sign-in. | `reviewer_model` (required), `writer_model` (default `openai:gpt-6.1-sol`), `credential` (default `auto`) |
| `qa` | One browser explorer. Every finding needs a Playwright reproduction, which the host re-runs on the build under test and, when given, a clean reference build. Areas it did not reach are listed as not covered. | `explorer_model` (required), `target_url` (default `http://localhost:3000`), `reference_url` |
| `audit` | Opt-in: runs only when named. A planner splits the scope into 2 to 8 areas, the host gives every file of the repository to one area, one read-only worker per area reads its files in parallel with a fresh context (a worker that leaves files unread is asked again, up to twice), and an integrator merges the findings. | `planner_model`, `worker_model`, `integrator_model` (all required) |

[Fix, QA and audit runs](/workbench/fix-qa-audit/) describes each one, and
[External agents](/configure/external-agents/) the two with an external writer. The
built-in ids are reserved: a user loadout cannot use them (see
[Where loadouts live](#where-loadouts-live)).

## Run one

```sh
cd ~/src/my-app
axocoatl run fix --task "Paging skips the last item when the total is a multiple of the page size" \
  --model writer=ollama:qwen3-coder:30b \
  --model reviewer=ollama:gpt-oss:20b \
  --junit axocoatl-junit.xml --record run.axorecord.jsonl
```

`qwen3-coder:30b` (19 GB) and `gpt-oss:20b` (14 GB) each fit a 48 GB Mac as onboarding
judges a model's size (at most about 0.65 of memory), and a fix run calls them in turn;
`gpt-oss:20b` as reviewer has not been measured. `gpt-oss:120b` (65 GB), the reviewer we
measured, needs a machine with roughly 96 GB of memory or more.

`--model writer=…` is the same as `--param writer_model=…`. A model value is
`provider:model`, split at the first `:`, so `ollama:qwen3:32b` and
`openrouter:anthropic/claude-sonnet-5.5` both work. The provider must be one your
configuration defines and that native Sessions accept; see
[Providers](/configure/providers/). Every flag, the exit codes, the JUnit file and the
record bundle are in the [`axocoatl run` reference](/reference/run/). A data root an
earlier Axocoatl used needs `axocoatl session upgrade --confirm` before its first run;
see [Before the first run](/reference/run/#before-the-first-run).

## Where loadouts live

- **Built-in loadouts** are compiled into Axocoatl. Their exact text is shown in
  Settings and by `axocoatl loadouts show fix`.
- **Your loadouts** are `*.yaml` and `*.yml` files directly in a `loadouts` directory
  next to the configuration file the daemon started with: on macOS
  `~/Library/Application Support/Axocoatl/loadouts/`, on Linux and WSL2
  `$XDG_CONFIG_HOME/axocoatl/loadouts/` or `~/.config/axocoatl/loadouts/`. With
  `--config /path/to/axocoatl.yaml` it is `/path/to/loadouts/`.

The daemon reads that directory each time loadouts are listed and each time a run is
admitted, so a new or changed file needs no restart. It reads at most 128 files, in name
order, each a regular file (a symbolic link is refused) of at most 64 KiB. A file that
does not parse or validate, or that reuses a built-in id, is still listed, with its path
and the error, and cannot run.

A file whose `id` is a built-in's (`fix`, `fix-claude-code`, `fix-codex`, `qa` or
`audit`), whatever the file is called, is not used, and Axocoatl does not choose between
it and the built-in: while the file declares that id, a run of the id is refused (exit
code 3), naming the file, and the built-in's row in `axocoatl loadouts list` and Settings
carries the warning `user_loadout_uses_builtin_id`. To keep running your file, give it
another id (such as `my-fix-claude-code`) and run that id; to run the built-in, remove the
file. Earlier versions of these docs showed a `fix-claude-code` loadout to write
yourself; that id is now built in.

Each loadout has a digest: the SHA-256 of its exact bytes. A run's record keeps the exact
text it ran, so editing the file later never changes what a finished run says it ran.

Check a file without the daemon:

```sh
axocoatl loadouts validate ~/Library/Application\ Support/Axocoatl/loadouts/py-fix.yaml
```

## The sandbox of a loadout Session

A run creates a Session for the repository, in a Workspace found or created for its
path. That Session always runs:

- under `network: egress`, or `network: none` when the loadout asks for it. Its egress
  lists are the daemon's own `sandbox.egress` lists plus the loadout's `egress` and
  `routes`, and the routes its external Agents and e2e checks need, for this Session
  only. A loadout cannot replace a route your configuration already has for a host: the
  two must be the same, or the run is refused. A request that one of the loadout's
  routes refuses gets a 403 whose hint says to change the loadout's route, or, for the
  route Axocoatl adds for an [external writer](/configure/external-agents/), says whose
  route it is; it never points at a `sandbox.egress.routes` entry your configuration does
  not have;
- with the `hardened` workload: Agents' commands, setup commands and required checks
  run as the non-root `writer_user`, read-only Agents as the non-root `helper_user`, and
  tool calls and checks under the supervisor's seccomp filter in a Landlock domain of
  their own. Readiness provisioning and the container's first process still run as root.
  See [Workload users](/configure/sandboxes/#workload-users).

Your global defaults do not change: `sandbox.network` stays what you set (`bridge`
unless you changed it), and other Sessions keep it. A loadout cannot ask for `bridge`
or for the `image` workload. When the host cannot provide `egress` and the `hardened`
workload, for example under rootful Podman or with `backend: e2b`, the run fails with
exit code 5 and says why; it never falls back to a weaker setting.

Read-only Agents, every Agent of an audit and the required reviewer among them, read
the repository as `helper_user`, through a read-only view of it that reads every file
whatever its mode, so a repository only you may enter, such as one made by `mktemp -d`
or under `umask 077` (mode `0700`), works as well as one made by `git clone`. Outside
the repository they read only what any user may (see
[Sandboxes](/configure/sandboxes/#workload-users)). A run with such an Agent checks in its
Session container, through that view, that they can enter and list the repository;
when they cannot (a repository another user owns, or a container or kernel that cannot
give the view), the run ends with exit code 5 before its first turn and says why.

A loadout with a `detected` check runs in Axocoatl's image of the repository's language
(Node.js, Python, Rust or Go), detected from its files.
Before the first model call the run installs the repository's dependencies, such as
`npm ci` or `pip install -e '.[test]'`, with only that language's package registries
open, and probes the check command. A check whose program is missing ends the run with
exit code 3. See [Repository toolchains](/configure/toolchains/). `--setup`, or else the loadout's
`environment.setup`, replaces the detected install. Without a toolchain (`--toolchain
none`, or a loadout that names its `image`), a run approves only `--setup` or
`environment.setup` and nothing detected.

## Settings shows loadouts; it does not run them

**Settings → Loadouts** lists the built-in loadouts and yours, with kind, version, an
opt-in badge, warnings, and the error and path of a file that cannot be used. Selecting
one shows its YAML (read-only), its parameters and its graph: one node per Agent, check
and reviewer, and for an audit one node for the area workers, with the order the host
runs them in. The graph is drawn in a read-only lattice that cannot be dragged, connected,
edited or run. Settings shows the exact `axocoatl run` command to copy instead.

A Session a run created shows a **Loadout** badge, such as `fix@1`, and a **Run outcome**
panel: verdict and exit code, checks with their test cases, review rounds,
adjudications, findings, everything not covered, warnings, usage, a summary of the
network record, **Download record** and [Keep as PR](/workbench/keep-as-pr/).

## Write a loadout

A loadout for a Python repository: one writer limited to `src/` and `tests/`, the test
suite as a required check, and a required review by a parameter model.

```yaml
schema: axocoatl.loadout/1
id: py-fix
version: 1
name: Python fix
description: One writer, the unit tests, and a review by another model.
kind: custom
params:
  writer_model:   { kind: model, required: true, description: provider:model of the writer }
  reviewer_model: { kind: model, default: "ollama:gpt-oss:20b", description: provider:model of the reviewer }
agents:
  - id: writer
    role: writer
    model: { param: writer_model }
    tools: [read_file, list_dir, grep, glob, write_file, edit_file, bash]
    writes: ["src/**", "tests/**"]
    max_output_tokens: 4096
checks:
  - name: unit
    run: { argv: [python3, -m, unittest, -v] }
    timeout: 5m
review:
  model: { param: reviewer_model }
  rounds: 2
  tools: [read_file, list_dir, grep, glob]
budgets:
  agent:    { activations: 3, invocations: 200, tokens: 2000000, cost_usd: 5 }
  reviewer: { activations: 2, invocations: 60, tokens: 600000, cost_usd: 1 }
  wall_clock: 45m
prompt: |
  {task}
environment:
  image: docker.io/library/python:3.12-slim
```

Run it with `axocoatl run py-fix --task "…" --model writer=ollama:qwen3-coder:30b`.

### Fields

Unknown fields are refused everywhere in the file.

| Field | Type | Rules |
| --- | --- | --- |
| `schema` | string | Exactly `axocoatl.loadout/1`. |
| `id` | string | 1-64 lowercase letters, digits or `-`, starting with a letter. Not a built-in's: `fix`, `fix-claude-code`, `fix-codex`, `qa` or `audit`. |
| `version` | integer | The loadout's own version, from 1. Shown as `id@version`. |
| `name`, `description` | string | `name` must not be empty. |
| `kind` | `fix`, `qa`, `audit` or `custom` | Selects how the run is driven; see [kinds](#kinds). |
| `opt_in` | boolean | Marks the loadout opt-in: Settings and `axocoatl loadouts list` show a badge. Nothing runs a loadout by default; each run names the one it runs. |
| `params` | map | Parameters a run supplies; see [parameters](#parameters). |
| `agents` | list | 1 to 8 Agents; see [Agents](#agents). |
| `checks` | list | 0 to 16 required checks with unique names; see [checks](#checks). |
| `review` | map | The required reviewer; see [review](#review). |
| `egress` | map | `allow` and `private_destinations`, the same entries as [`sandbox.egress`](/reference/config/#sandbox). |
| `routes` | list | Routes with the same fields as [`sandbox.egress.routes`](/reference/config/#sandboxegressroutes). A `credential` names a `credentials` entry or a secret stored with [`axocoatl secret set`](/configure/external-agents/#store-the-credential). |
| `budgets` | map | `agent` (limits of each Agent without its own `budget`), `reviewer` (required with `review`: the reviewer's limits for all rounds of one turn) and `wall_clock` (such as `60m`). Limits are `activations` and `invocations`, each at least 1; `tokens`, enough for one model call of each Agent and the reviewer; and `cost_usd`, 0 to 10,000. Validation refuses `tokens` below 2048 plus the output bound (`max_output_tokens`, 8192 when unset). Before a run starts, each budget is checked against what one call of its model needs, and a budget that does not hold it is refused, naming the budget and the minimum (exit code 3): for an Ollama model, its loaded context plus the output bound; for an OpenRouter model, the 4,096-token prompt allowance a call reserves at least (within the model's `context_length` in OpenRouter's public catalog, which admission reads) plus the output bound and the reasoning allowance of its effort, not the whole context window, since a call reserves its own request; for an [external program](/configure/external-agents/#what-a-run-costs)'s model in Axocoatl's pinned table, the most one call of the program can use. |
| `prompt` | string | The turn's request. Must contain `{task}`; may also use `{repo}`, `{target_url}` and `{reference_url}`. |
| `sandbox` | map | `network: egress` (the default) or `none`, and `workload: hardened`. `bridge` and `image` are refused; `none` refuses `egress.allow`, `routes`, an external Agent (it needs a route) and Agents that list `web_search`, `web_fetch`, `browser` or `browser_check`. |
| `environment` | map | `image` (a curated or trusted image) or `recipes` (the image [`axocoatl recipe build`](/configure/external-agents/#build-the-image) built from exactly those recipes; a run builds one that is missing, or with `--no-build` is refused naming the command), not both; `setup`, the exact setup command a run approves; and `toolchain`: `detected`, `node`, `python`, `rust`, `go` or `none` (see [Repository toolchains](/configure/toolchains/)). A toolchain among the `recipes`, such as `[claude-code, python]`, names it too. `toolchain` and `image` are exclusive unless `toolchain` is `none`. |
| `qa` | map | `qa` kind only: `target_url`, `reference_url`, `repro_dir`, `fail_on_findings` (default `true`). |
| `audit` | map | `audit` kind only: `min_areas`, `max_areas` (2 ≤ min ≤ max ≤ 8), `fail_on_findings` (default `false`). |

### Agents

| Field | Rules |
| --- | --- |
| `id` | 1-32 lowercase letters, digits or `-`, starting with a letter; unique. |
| `role` | `writer`, `explorer`, `planner`, `worker` or `integrator`. |
| `model` | `{provider, model}`, or `{param: name}` naming a `model` parameter. An external program's model names the provider whose API it calls: `anthropic` for `claude-code`, `openai` for `codex`; any other is refused. |
| `runtime` | `native` (the default), `claude-code` or `codex`. An external program runs only as the writer; see [External agents](/configure/external-agents/). |
| `credential` | External writers only: the stored credential its route sends, written out or as `{param: name}` naming a `text` parameter. For `codex`, `codex-openai` (the default when left out: an OpenAI API key; 1.5.0 stores none through a sign-in, see [Codex with an OpenAI API key](/configure/external-agents/#codex-with-an-openai-api-key)) or `codex-chatgpt` (your ChatGPT sign-in, from `axocoatl connect codex`); for `claude-code`, only `claude-code-oauth`. `auto` takes, when the run is admitted, the first of these that is stored (for Codex, `codex-openai`, else `codex-chatgpt`), and refuses the run (exit code 3) saying how to connect when none is. Any other name, or one on a native Agent, is refused. The run records the credential it sent: in its manifest, a `note` line `axocoatl run` prints as it starts, and the Outcome's notes. See [Choose the Codex credential](/configure/external-agents/#choose-the-codex-credential). |
| `tools` | Required for a native Agent; the exact tool list. Ignored for an external program. |
| `writes` | Paths the Agent may change. Left out, every path, which only a writer may do. `[]` is read-only; planners, workers and integrators must be `[]`. |
| `instructions`, `max_output_tokens`, `reasoning_effort` | As for an [Agent template](/configure/agents/#define-an-agent). |
| `budget` | This Agent's limits, in place of `budgets.agent`. |
| `depends_on` | Other Agents of the loadout whose accepted answer this Agent needs. |

### Checks

Each check is `{name, run, timeout}`. `name` is 1-32 lowercase letters, digits or `-` and
is the test case name in the JUnit file. `run` sets exactly one of:

- `argv: [..]`, an exact argument list;
- `shell: "…"` or `shell: {param: name}`, run as `sh -c`;
- `detected: true`, the repository's check command: `--check`, else a `Check command:`
  line in the root `AXOCOATL.md`, else one detected from its files (see
  [The check command](/configure/toolchains/#the-check-command)); a run with none is a
  usage error (exit code 3), and so is one whose check cannot start in the run's image;
- `e2e: {args, model_route, model}`, the [e2e check](/configure/e2e-check/).

`timeout` is a duration such as `90s`, `3m` or `1h`: three minutes when left out, at
most 30 minutes. Checks run as [required checks](/configure/agents/#required-checks):
on the exact final files, between two captures, on the writer's allowance.

### Review

`review` is `{model, rounds, tools, instructions, max_output_tokens, adjudicate}`:
`rounds` 1 to 3; `tools` only from `read_file`, `list_dir`, `grep`, `glob` and
`workspace_knowledge`. The reviewer runs as a
[required review](/configure/agents/#required-review): the host asks it to number its
findings and asks the writer to answer each one it sends back with accept or reject and a
reason. In a `fix` loadout, `adjudicate` (default `true`) records each answer as an
adjudication, and an unanswered finding makes the run need attention; with `false`, or in
a `custom` loadout, the answers are not recorded or checked.

When the reviewer's model is the writer's model, validation warns
(`same_model_reviewer`), and the warning is repeated in the API, Settings, Team and
budget, the run output and the record. It is a warning, not a refusal. See
[why](/workbench/fix-qa-audit/#fix).

### Parameters

`params` maps a name (1-32 lowercase letters, digits, `-` or `_`, starting with a letter)
to `{kind, required, default, description}`. `kind` is `model` (`provider:model`), `text`
or `url` (`http://` or `https://`). A required parameter has no default. Fields that
accept `{param: name}` take a parameter of one kind: `agents[].model` and `review.model` a
`model`; `agents[].credential`, `checks[].run.shell`, `checks[].run.e2e.model` and
`environment.setup` a `text`; `qa.target_url` and `qa.reference_url` a `url`. A parameter
with a default needs no value: `fix-claude-code` and `fix-codex` run with only
`--model reviewer=…`.

A run gives values with `--param name=value` and `--model role=provider:model`. An
unknown parameter name is refused, so a typo never runs with a default, and a missing
required one is a usage error (exit code 3).

### Kinds

| Kind | The validator requires |
| --- | --- |
| `fix` | Exactly one Agent, a writer; a `review`; at least one check; no `qa` or `audit` section. |
| `qa` | Exactly one Agent, an explorer that lists `browser` and `browser_check` and whose `writes` is exactly `["<repro_dir>/**"]`; a `qa` section; no review and no `audit` section. |
| `audit` | Exactly one planner, one worker and one integrator, none of which lists `write_file` or `edit_file`; an `audit` section. |
| `custom` | At most one writer; no `qa` or `audit` section. Runs as one turn. |

<Aside>
A loadout describes a run; it does not widen what Axocoatl allows. A run goes through the
same Team and budget review, grants, write scopes, checks, review and network record as a
Session you drive in the workbench.
</Aside>
