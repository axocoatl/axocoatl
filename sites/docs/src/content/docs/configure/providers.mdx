Each Agent selects a provider and model. Credentials and provider endpoints
live under `providers:` in the active YAML configuration. `axocoatl onboard`
creates the current user's configuration; it does not create a project or a
repository-level `.env` file.

## Provider adapters

| `provider:` | Adapter |
| --- | --- |
| `ollama` | Ollama at a configured local or remote endpoint |
| `openai` | OpenAI, or an OpenAI-compatible endpoint via `base_url` |
| `anthropic` | Anthropic Messages API |
| `gemini` | Google Gemini |
| `mistral` | Mistral Chat API |
| `openrouter` | OpenRouter through its OpenAI-compatible endpoint |

The onboarding wizard offers Ollama and OpenRouter for native Sessions.
OpenAI, Anthropic, Gemini, and Mistral are configured manually for their
supported compatibility paths.

New data roots use native Session execution, whose enforced budget boundary supports
reviewed local Ollama profiles and eligible OpenRouter-credit profiles. The remaining
adapters serve their existing compatibility paths; an API-compatible endpoint alone
does not establish native budget enforcement.

## Configure a compatibility hosted provider

The direct Anthropic example below configures compatibility execution. For a new
native Session, use [OpenRouter](#configure-openrouter) or [Ollama](#configure-ollama)
instead. OpenRouter onboarding masks the credential prompt and writes a supplied
key to the owner-only user configuration (`0600` on supported Unix hosts). For
manual compatibility configuration, the environment-placeholder form below keeps
the key out of YAML; its value must be present in the process that starts Axocoatl.

The following is the equivalent manual YAML form:

```yaml
agents:
  - id: coder
    name: Coder
    provider: anthropic
    model: claude-sonnet-4-6

providers:
  anthropic:
    api_key: "${ANTHROPIC_API_KEY}"
```

For the placeholder form, export the value in the environment that starts
Axocoatl:

```sh
export ANTHROPIC_API_KEY=replace-me
```

Axocoatl interpolates `${NAME}` before parsing YAML and wraps configured secret
fields so debug formatting does not reveal them. That does not protect a
secret committed in plaintext, exposed by shell history, or logged by an
external server.

Axocoatl does not create or load a `.env` file. Use process-environment or
service-manager injection when you choose a placeholder rather than the
owner-only user configuration.

## Configure OpenRouter

Use your normal OpenRouter API key and OpenRouter credits. Onboarding asks you to
confirm that the account has no connected BYOK provider keys. BYOK is not supported
by native Session execution. No separate account or management key is required.

```yaml
agents:
  - id: coder
    name: Coder
    provider: openrouter
    model: anthropic/claude-sonnet-5.5
    sampling:
      max_tokens: 4096
      reasoning_effort: medium   # optional; the model's own default otherwise

providers:
  openrouter_billing: credits
  openrouter:
    api_key: "${OPENROUTER_API_KEY}"
```

This declaration must match the account's billing configuration. Do not connect
BYOK provider keys while using this execution path; Axocoatl cannot prevent changes
made in your OpenRouter account.

Before Send, review **Team & budget**. Axocoatl reads the model's entry in OpenRouter's
catalog and its endpoints, selects the cheapest qualifying endpoint that accepts the
Agent's sampling settings and fits its budget, and retains its capabilities, context
and output limits, prices and, for a reasoning model, its reasoning contract. Every
request pins that endpoint, disables automatic retries and fallbacks, and carries its
prompt, completion and per-request price ceilings as `max_price`. The retained contract
is checked again before each request; a changed or unsupported profile is refused
before inference.

### What each request reserves

Each request reserves a bound computed from that exact request, not the endpoint's
context window:

- **Prompt:** the byte length of the request body Axocoatl sends, plus 4,096 tokens for
  the provider's chat template and tool preamble, plus the reasoning tokens of earlier
  tool turns it sends back (see below), at most the endpoint's prompt limit. A token of
  these models' byte-level tokenizers covers at least one byte of text, so the request's
  bytes bound the tokens of its own text; the allowance covers what the provider adds.
- **Response:** the call's output limit (`sampling.max_tokens`) plus its reasoning
  allowance. The sum is sent as `max_tokens`. OpenRouter documents that on most
  providers this caps reasoning and visible output together; a provider that does not
  count reasoning against `max_tokens` can bill past the reservation, and that call is
  then refused as a breach after it was billed, with its spend kept.
- **Cost:** the prompt bound at the endpoint's highest input price, the response at its
  highest output price, and any per-request fee. The input price is the highest of the
  prompt, cache read and cache write prices; the output price is the higher of the
  completion and internal reasoning prices. When an endpoint has price tiers, such as a
  higher rate above 272,000 prompt tokens, the highest tier is used.

If the approved allowance cannot cover a request's reservation, the request does not
start. OpenRouter's final usage and billed cost settle the reservation: only they stay
charged, and the rest is available to later requests. Reasoning tokens are output: they
count toward the call's output, its tokens and its cost. A response whose usage exceeds
its reservation is refused and its reported spend is kept. A missing final response
stays unknown and does not release the reservation.

A request's prompt grows with the Session, so its reservation does too; the smallest
call (no request bytes, only the template allowance and the response allowance) must fit
the approved budget for Team & budget to admit the Agent. Without `sampling.max_tokens`,
the response allowance takes at most half of the Agent's whole-call token capacity.

Because later calls reserve more than earlier ones, an Agent asks for its final answer
while it can still pay for this call and the one after it, with that one's prompt grown
by this call's whole response and as much again for the tool results. A lead starts a
helper only when, after the helper's limits, it can still pay for the call that reads
the helper's answer: the lead's latest call grown by the reasoning it sends back, the
turn it returned and the answer.

An Agent's own `token_budget` with `abort` counts the whole response too: before each
call it reserves the estimated input, including reasoning tokens sent back, plus the
output limit and its reasoning allowance. When it derives the output limit from what
is left, it picks the largest output whose response still fits, and refuses the call
when not even the smallest response fits.

### Reasoning models

For a model whose catalog entry describes reasoning, Axocoatl sends the documented
`reasoning` setting with every call: `sampling.reasoning_effort` when the Agent sets it
(`max`, `xhigh`, `high`, `medium`, `low`, `minimal` or `none`), otherwise the model's own
default effort. An effort the model does not list is refused by name, and so is `none`
for a model whose reasoning is mandatory.

The reasoning allowance follows OpenRouter's share of `max_tokens` for each effort (95%
for `max` and `xhigh`, 80% for `high`, 50% for `medium`, 20% for `low`, 10% for
`minimal`), so the visible output keeps `sampling.max_tokens`: `high` adds four times the
output limit, `medium` once, `low` a quarter. It is never less than OpenRouter's
1,024-token minimum reasoning budget while reasoning is on, and `none` adds nothing.
With `max_tokens: 4096` at `high`, each call may produce 20,480 tokens.

The sum is never cut to fit. Team & budget refuses, by name, an output limit and effort
whose sum passes the endpoint's own output limit (8,192 at `xhigh` asks for 163,840 on
an endpoint that allows 128,000), or whose streamed text could pass the 1 MiB a Session
keeps of one response, counted at 10 bytes per token (5,300 at `max` is 106,000 tokens).
Without `sampling.max_tokens`, the derived output stops below both.

When a reasoning model calls tools, its reasoning blocks are kept on the tool call and
sent back unmodified with the tool results, as OpenRouter documents for tool use, so the
model continues the same line of reasoning. They stay in the Session's history.

### What a request never asks for

Some endpoints also price features such as web search or image input. A native request
cannot start them: it sends text and function tools only, no OpenRouter server tools,
no `modalities` or `web_search_options`, an exact model id (a `:online` id is refused),
and it turns the web plugin off explicitly, which overrides an account default. A
response that reports a server tool, web citations, or image or audio output is refused.
`max_price` leaves out image and audio prices: OpenRouter filters endpoints on their
listed image and audio prices even for a text request, so a zero cap there would
refuse every call to a model that lists them. An account setting that forces the web
plugin with **Prevent overrides** is incompatible with this execution path.

The request also turns OpenRouter's context compression off, which endpoints of 8,192
tokens or less use by default and an account can turn on: the model sees the exact
conversation the Session recorded, including the reasoning it sends back, never one
with messages dropped from the middle.

A request never opts into a service tier. Tier endpoints such as `openai/flex`,
`openai/fast` or `google-vertex/flex` trade latency, availability or price, serve only a
request that asks for them, and are never selected; `:nitro` and `:floor` model ids,
which opt into them, are refused. A response that reports a tier other than the
standard one is refused.

Eligible endpoints need an exact tag (a provider tag such as `openai` qualifies when no
regional or other variant shares it; tier endpoints do not count, because a provider
tag never selects them), text output, tool calling, `max_tokens`, `reasoning` for a
reasoning model, every sampling setting the Agent sends (`temperature`, `top_p`,
`response_format`), and prices Axocoatl can bound. An endpoint that charges for
anything else is refused, and the error names the component; a sampling setting no
endpoint accepts is named too. Dynamic router aliases and custom OpenRouter endpoints
are unsupported. A model Axocoatl cannot run says why when Team & budget is applied.

## Configure Ollama

Native execution requires a loopback Ollama **0.20.6** server that reports
cloud-disabled mode and a local GGUF completion model. Axocoatl checks the exact
model identity, loaded context, and capabilities during Team review and before
inference. Other versions, remote routing, and a generic compatible server do
not satisfy this native contract. The broader Ollama adapter remains available
for compatibility execution.

```yaml
agents:
  - id: local-coder
    name: Local coder
    provider: ollama
    model: qwen2.5-coder:14b

providers:
  ollama:
    base_url: "http://localhost:11434"
```

`axocoatl doctor` treats a configured Ollama endpoint as a required check: the
endpoint must respond, be a loopback address, report Ollama 0.20.6 and its cloud
features disabled, and have the configured Agent models present. To disable
Ollama's cloud features, add `{"disable_ollama_cloud": true}` to
`~/.ollama/server.json` of the user that runs Ollama, or start the server with
`OLLAMA_NO_CLOUD=1`, then restart it; see
[Configure Axocoatl](/start/onboard/#ollama).

Some Ollama-served models return a requested tool call as response text instead
of the structured field. Axocoatl recovers only complete, bounded calls whose
names were actually offered in that Ollama request. The selected effective
route must still be Ollama; response text from other providers remains text
because Axocoatl cannot safely invent their native call ids, signatures, or
content-block sequence.

## Use a compatibility endpoint

For compatibility execution, the `openai` adapter honors `base_url`. Include the API-version suffix expected
by the server, commonly `/v1`.

```yaml
agents:
  - id: local-compatible
    name: Local compatible model
    provider: openai
    model: your-model-id

providers:
  openai:
    api_key: "${LOCAL_MODEL_API_KEY}"
    base_url: "http://localhost:1234/v1"
```

This can target implementations such as LM Studio, MLX/oMLX, or vLLM when
their API behavior matches what the adapter uses. A non-empty key may still be
required by Axocoatl even when the local server ignores its value.

## Select models per Agent

Provider registration is shared, but the Agent's configured `model` is sent on
each request. Agents using the same provider may therefore target different
models.

```yaml
agents:
  - { id: triage, name: Triage, provider: ollama, model: llama3.2 }
  - { id: implement, name: Implement, provider: openai, model: gpt-5 }
```

Native Sessions retain exact approved models. Conversation displays those models
read-only; change them through **Team & budget**, then preview and apply the revised
team. Compatibility Sessions allow a per-turn model override within the Agent's
provider. That override does not supply another provider's credentials.

## Configure one rate-limit fallback

A hosted provider may specify one fallback as `provider` or `provider:model`:

```yaml
providers:
  openai:
    api_key: "${OPENAI_API_KEY}"
    fallback: "anthropic:claude-sonnet-4-6"
  anthropic:
    api_key: "${ANTHROPIC_API_KEY}"
```

Axocoatl retries once only when the primary request is rate-limited before a
stream is established. It does not traverse a fallback chain and does not
switch providers for non-rate-limit or mid-stream failures.

This fallback applies to legacy Session and global Agent execution. Native Sessions
require their retained primary route and reject configured OpenRouter fallbacks. Explore several ways
uses each Way's configured primary provider/model directly for now; a rate limit fails that
Way so its retained provider/model and cost evidence cannot silently describe the wrong route.

For a plain-text-only history, that choice is per call. Once a response starts a
tool exchange, Axocoatl records and pins the exact selected slot, provider, and
model for every request that still carries that native transaction—including
later user turns and a restored Session. This prevents provider-native call ids,
thought signatures, or thinking blocks from crossing APIs. Removing the complete
transaction during context compression removes the pin. Missing, conflicting, or
stale route markers fail closed; start a new Session or restore the matching
provider/model configuration instead of forcing incompatible history through a
different endpoint.

If the primary is rate-limited before streaming and a fallback has a smaller
known context limit than the already prepared request, Axocoatl fails locally
instead of sending an oversized fallback call. Custom or otherwise unknown model
IDs are not assigned invented limits or feature flags; their compatibility is
validated by the configured endpoint.
