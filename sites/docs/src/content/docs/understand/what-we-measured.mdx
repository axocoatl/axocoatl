Axocoatl makes claims about results only from measurements. This page states them
once, with the setup and the limits, so you can judge how far they reach. The
[claims ledger](https://github.com/axocoatl/axocoatl/blob/main/docs/CLAIMS.md) maps every
public number to its evidence, its model and the harness it ran in, and lists the claims
we withdrew.

## The benchmark

- **Pre-registered.** Six Python maintenance tasks were frozen on 2026-09-22, before
  any run.
- **Withheld tests.** Each result is scored by 25 tests the agents never see; they are
  not in the repository the agents work on.
- **Models.** The writer is qwen3-coder 30B, running locally. The stronger reviewer is
  gpt-oss 120B, also running locally.
- **Runs.** One run per task, at temperature 0.

## Results

{/* measured: axocoatl-1.1.0 2026-10-01 */}

**Through Axocoatl 1.1.0** (release build, native Sessions, tools in a rootless Podman sandbox, host-run checks):

| Setup | Withheld tests passed | Tokens vs. one pass | What happened |
| --- | --- | --- | --- |
| One Agent, one pass | 17 / 25 | 1× | The writer works once and stops. |
| The same writer with a Required review by gpt-oss 120B (local), up to 2 rounds | **19 / 25** | 2.6× | 15 defects reported, 14 real. One task went from 1/4 to 4/4; the writer also applied the one false alarm, which cost a test on another. 6 real findings came in the last round, after which Axocoatl stops revising. |

**Where extra tokens help** (same tasks, a plain agent loop without Axocoatl):

| Setup | Withheld tests passed | Tokens vs. one pass | What happened |
| --- | --- | --- | --- |
| One pass | 17 / 25 | 1× | |
| The same Agent reviews its own work | 17 / 25 | 3.5× | Final files byte-identical to one pass. |
| A fresh reviewer on the same model | 17 / 25 | 2.3× | It approved every change, including three with real defects. |
| The same model writes its own tests (4 of 6 tasks run) | one more test | 9–15× | When its tests failed it often rewrote the tests, not the code. |
| A stronger reviewer (gpt-oss 120B) | 20 / 25 | 3.3× | 9 real defects, 2 false alarms. |

Axocoatl's token counts are higher than the plain loop's for the same work (a larger
context is re-sent on every call), so compare tokens within a table, not across them.

## What it shows

Extra tokens helped when they bought a stronger model's judgment, not more looks from
the same model. A second pass by the same model, whether as itself or as a fresh
reviewer, cost more and changed nothing; the fresh reviewer agreed with the writer even
where the writer was wrong. Having the same model write its own tests gained one test at the
highest token cost. A stronger reviewer moved the score the most, for fewer tokens than self-review, and it
was not free of mistakes: its false alarms are why the lead should check each finding against the
requirements before acting on it.

## How this maps to Axocoatl

Each Agent template names its own provider and model, so the Agent that writes and the
Agent that reviews need not share one. Make a stronger model the team's
[required reviewer](/configure/agents/#required-review), and the host runs it on the
exact result after your [required checks](/configure/agents/#required-checks) pass,
sends its findings back to the lead, and records every step in the Session. The
reviewer can be a bigger local model through Ollama, as measured here, or a hosted model
through OpenRouter, which we have not measured. The built-in
[`fix` loadout](/workbench/fix-qa-audit/#fix) runs this pattern headless and warns when
the reviewer is the writer's model.
[Set up cross-model review →](/configure/cross-model-review/)

<Aside>
None of this says the default team, a lead with helpers, beats a single Agent. In our
evaluation before 1.1.0, a single Agent was as accurate as the lead with helpers and used
the fewest tokens, and one Agent remains the cheaper choice for small tasks. See
[What helpers cost](/understand/coordination/#what-helpers-cost).
</Aside>

## One agent or several, on the same model

These studies ran Claude Opus as Claude Code subagents, on the host, outside Axocoatl.
They are not Axocoatl results, and Axocoatl's own runs of the same setups have not been
measured. They are why the built-in [loadouts](/workbench/fix-qa-audit/) have one writer
or one explorer, and why `audit` is opt-in.

{/* measured: claude-code-subagents single-vs-multi 2026-10-06 */}

**One agent against a planner, parallel workers and an integrator** (pre-registered;
the same model and effort for every agent; up to 5 paired runs per kind of work):

| Work | Quality, several agents against one | Wall-clock time | Tokens |
| --- | --- | --- | --- |
| Fits in one context: 40 research questions, independent modules, a coupled feature change | the same: both scored 100% | 1.6× to 4.9× as long | 4× to 5.5× |
| Larger than one context: an audit of 5.2 to 5.7 million characters of source, 150 planted defects | recall +11 points (99% against 87%; interval +4 to +19), precision −8 points | about the same | about 3× |

The audit row is a sensitivity analysis, not a pre-registered result: the study's
pre-registered exclusion rule excluded 9 of its 10 attempts, and these figures put them
back.

{/* /measured */}

{/* measured: claude-code-subagents qa 2026-10-04..06 */}

**QA of a web app** (each finding needed an executable reproduction):

| App | Setup | Recall | Precision | Tokens |
| --- | --- | --- | --- | --- |
| 16 planted bugs, 5 runs each (exploratory) | one explorer | 97.5% | 98.8% | 1× |
| | one explorer and a verifier (the verifier removed nothing) | 100% | 100% | |
| | a lead and two scouts | 98.8% | 95.7% | 2.1× |
| 66 planted bugs (pre-registered; 10 and 5 runs) | a lead and three scouts against one explorer | +2.3 points, not significant (p = 0.77) | | +31% |

{/* /measured */}

Several agents paid off only where one agent could not hold the work, and there they
traded precision and tokens for recall. Where one agent could hold it, they cost more and
took longer for the same result.

## An earlier result: the coordination design we removed

Axocoatl's first design had Agents coordinate through notes and failed checks left on
shared files, with no Agent in charge. We built it during 1.1.0 development and measured
it against a single Agent: a single Agent that reviewed its own work matched the best
team's score at 28–48% of the tokens. We removed that design in 1.1.0 and moved to a
lead that writes, read-only helpers it can delegate to, and checks and review that the
host runs. The [1.1.0 changelog](https://github.com/axocoatl/axocoatl/blob/main/CHANGELOG.md)
lists what was removed.

## Limits

- **One run per task, at temperature 0.** There is no estimate of run-to-run variance; a
  repeated run could differ by a test or more.
- **Six tasks, 25 tests, one language.** All tasks are Python maintenance work.
- **Two local models.** Other writers, reviewers or hosted models may behave differently,
  and a reviewer stronger than the writer is the comparison, not any particular model.
- **Tokens, not time or money.** In the review benchmark, token multiples are relative to
  one pass on the same tasks; we did not measure its wall-clock time and make no speed
  claim for review.
- **Claude Code subagents are not Axocoatl.** The one-agent-or-several and QA studies
  used one model, Claude Opus, in Claude Code. They describe those setups, not Axocoatl
  or other models, and their results have not been reproduced through Axocoatl.
- **Hosted reviewers.** No reviewer through OpenRouter has been measured.
