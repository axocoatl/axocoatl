Normal commands load the current user's configuration independent of the
current directory:

- macOS: `~/Library/Application Support/Axocoatl/config.yaml`
- Linux/WSL: `${XDG_CONFIG_HOME:-$HOME/.config}/axocoatl/config.yaml`

`axocoatl onboard` creates this file without creating a project, repository,
Workspace, Session, or `.env` file. Validate it before restart:

```sh
axocoatl validate
axocoatl dev
```

A project-local configuration is an explicit advanced override. Axocoatl never
selects a cwd `axocoatl.yaml` merely because it exists:

```sh
axocoatl validate /absolute/path/to/axocoatl.yaml
axocoatl dev --config /absolute/path/to/axocoatl.yaml
```

## Environment interpolation

`${NAME}` expressions are replaced from the process environment before YAML is
parsed. An unset variable becomes an empty string. Axocoatl does not load a
`.env` file automatically. Onboarding uses a masked credential prompt and
writes a supplied key literally to the owner-only user configuration; leaving
the prompt blank keeps the corresponding environment placeholder.

Secret fields use redacting wrappers in debug output, but YAML, shell history,
service definitions, external servers, and backups still need normal secret
handling.

`${...}` is refused inside `credentials` and `sandbox.egress.routes`, before
substitution: those blocks name where a credential lives, and substitution would
copy its value into the configuration. See [Credentials](#credentials).

## How YAML is read

Configuration files and loadouts are read as YAML 1.2, one document per file.
A value means what the field it fills expects:

- A text field takes the value as written: `model: 017`, `name: yes` and
  `label: ~` are the strings `017`, `yes` and `~`, and an empty `key:` is the
  empty string (so an unset `${NAME}` leaves an empty string). A field that
  also takes another form, such as a loadout value that may be
  `{param: name}`, reads a plain number, `true`, `false` or `null` as that
  type: quote text that looks like one.
- A true/false field takes only `true`, `True`, `TRUE`, `false`, `False` or
  `FALSE`. YAML 1.1's `yes`, `no`, `on` and `off` are refused there, not
  guessed.
- A number field takes a plain number: decimal, `0x` hexadecimal, `0o` octal
  or `0b` binary. A leading zero (`017`), underscores (`1_000`) and a quoted
  number (`"8080"`) are not numbers.
- An optional field is unset by `null`, `Null`, `NULL`, `~` or an empty value.
- Anchors (`&name`) and aliases (`*name`) work. `<<` is an ordinary key: merge
  keys are not expanded.
- A field given twice in the same mapping is an error. Where the keys are names
  you choose, a repeated name keeps its last value.

A file that does not parse, or a value of the wrong type, is reported with the
file, the line and column, and for a wrong type the path of the value, such as
`agents[0].token_budget.per_call: invalid type: string "many", expected usize
at line 9 column 17`.

Files written for Axocoatl before 1.3.1, which read YAML with libyaml, read to
the same values. Where YAML 1.2 would read a file differently, Axocoatl reads it
as before: a NEL (U+0085) breaks a line; a continuation line of a quoted string
may be indented less than YAML 1.2 asks, also with a tab; a lone `-` in a list
such as `args: [--input, -]` is the text `-`. Where it cannot, the file is
refused with the line and column rather than read to another value:

- a LINE SEPARATOR (U+2028) or PARAGRAPH SEPARATOR (U+2029) inside a value
  (write it as `\L` or `\P` in a double-quoted string; elsewhere it ends the
  line, as before);
- a byte order mark (U+FEFF) at the start of a value, or at the start of a
  line once the file's content has begun, or a second one at the start of the
  file;
- an anchor or alias name with anything but letters, digits, `-` and `_`;
- text starting with `?` or `:` inside `[...]` or `{...}`: write `? key` or
  `: value` with a blank, or quote the text;
- a comment whose `#` follows the text before it without a blank, such as
  `[a]#c` or `|#c`, and `- ?`: put a blank before the `#` or after the `?`;
- more than 255 lists or mappings inside one another.

An alias names the latest node with its anchor, also when the anchor is
defined again; before 1.3.1 it could name a later one.

## Process data root

The control-plane data root is process configuration, not a YAML key.
`AXOCOATL_DATA_DIR` selects it when set. Otherwise the normal user
configuration uses:

- macOS: `~/Library/Application Support/Axocoatl/data`
- Linux/WSL: `${XDG_DATA_HOME:-$HOME/.local/share}/axocoatl`

An explicit `--config /path/to/config.yaml` uses
`/path/to/data` unless `AXOCOATL_DATA_DIR` overrides it. Neither default depends
on the daemon's current working directory.

On supported Unix hosts, bootstrap retains an opened handle to that root and
acquires an external current lease, the 0.1-compatible in-root lease, and a
directory-inode lock before runtime reconciliation or mutable state reads. If the
resolved root is below a local Podman Workspace, it is masked inside the container.
A Workspace equal to or below that root is rejected. The per-user configuration
directory is treated the same way when the daemon loaded the per-user
configuration file. These controls are automatic
and have no YAML override. See [Data and backup](/operate/data-backup/) and
[Security](/operate/security/).

## Root keys

| Key | Shape | Runtime role |
| --- | --- | --- |
| `agents` | list | Agent identities, providers/models, prompts, tools, budgets, memory, coordination |
| `workflows` | list | Legacy manual graph seed and coordinator/multi-Agent membership metadata |
| `mcp_servers` | list | MCP connections established at bootstrap |
| `providers` | object | Provider credentials, endpoints, native OpenRouter billing declaration, and compatibility fallback targets |
| `server` | object | HTTP bind, auth, CORS, and rate limiting |
| `sandbox` | object | Daemon-global Session backend and trust/network policy |
| `hooks` | list | Experimental parsed configuration; not executed |
| `skills` | list | Event-producing configured Skills |
| `schedules` | list | Legacy fixed-interval Automation seed |
| `proactive` | list | Legacy interval/event Automation seed |
| `web_search` | object/null | Optional Session web-search provider |
| `web_fetch` | object/null | Optional `web_fetch` tool; present enables it for Agents that list it |
| `browser` | object/null | Optional `browser` and `browser_check` tools; present enables them for Agents that list them |
| `consolidation` | object | Idle memory-promotion loop |
| `webhooks` | list | Outbound typed-event delivery |
| `pricing` | map | Per-model input/output rates for Attempt cost reporting; reasoning uses the output rate |
| `credentials` | map | Where the daemon reads each credential that `sandbox.egress.routes` add to requests |
| `run` | object | The writer and reviewer models `axocoatl run` uses when a run names none ([Run defaults](#run-defaults)) |

Omitted collections default empty. The live daemon does not watch this file;
restart it to load durable changes.

## Agents

```yaml
agents:
  - id: coder
    name: Coder
    provider: ollama
    model: qwen3-coder:30b
    system_prompt: Work in the selected repository and verify changes.
    tools: [read_file, list_dir, grep, glob, write_file, edit_file, bash]
    writes: [src/, "*.md"]
    depends_on: []
    role: autonomous
    token_budget:
      per_execution: 20000
      per_call: 8192
      overflow_policy: abort
    sampling:
      temperature: 0
      top_p: null
      max_tokens: 4096
      response_format: text
      reasoning_effort: null
    max_tool_rounds: 200
    memory:
      max_session_messages: 100
      recall:
        passive_inject: true
        top_k: 5
        min_score: 0.15
      core:
        blocks: []
```

Required Agent fields are `id`, `name`, `provider`, and `model`.
`system_prompt` and `token_budget` are optional. `role` defaults to
`autonomous`; other values are `coordinator` and `worker`.

`tools` is exact in a native Session: an Agent is offered only the tools it lists, and an
empty or missing list gives it none. `validate`, `doctor` and daemon startup warn about an
Agent that is not a Worker and lists no tools. A legacy (1.0-format) Session still gives an
Agent with an empty list the baseline tools. See [Agents and budgets](/configure/agents/).

`writes` is optional: up to 64 repository path patterns the Agent may change in a
native Session. Omit it to allow any file; `[]` makes a read-only helper. Absolute paths,
`..` segments, `.git` segments, empty entries, and repeated entries are rejected. See
[Limit which files an Agent may change](/configure/agents/#limit-which-files-an-agent-may-change).

`max_tool_rounds` is optional: the most tool rounds one activation of the Agent may run
in a native Session, from 1 to 1,024. Without it the Agent's grant sets the limit, one
round per invocation it allows, up to 1,024. Other values are rejected. See
[How long an Agent may work](/configure/agents/#how-long-an-agent-may-work).

A Coordinator must be the `entry_point` of exactly one workflow. A Worker in a workflow must
belong to that coordinator-led workflow; a Worker outside every workflow is a helper template
for a native lead. A Worker cannot execute or restart as a standalone Agent.

`token_budget.per_call` defaults to 8192 when the budget block exists and
`overflow_policy` defaults to `abort`. `summarize` is a deprecated alias for
`warn`. An empty core block list creates the standard blocks; a non-empty list
contains `{label, value?, limit?, shared?, description?}` with a default limit
of 2000 characters.

Sampling fields are optional and adapter support varies. `response_format` is
`text` or `json`. `reasoning_effort` is `max`, `xhigh`, `high`, `medium`, `low`,
`minimal` or `none`; any other value is a configuration error. Native OpenRouter sends
it to a reasoning model and sizes each call's reasoning allowance from it; without it,
the model's own default effort is used. A non-reasoning model, an effort the model does
not list, or `none` for a model that requires reasoning is refused when Team & budget
is applied. See [Reasoning models](/configure/providers/#reasoning-models).

## Providers

```yaml
providers:
  openrouter_billing: credits
  ollama:
    base_url: "http://127.0.0.1:11434"
    model: llama3.2
  openai:
    api_key: "${OPENAI_API_KEY}"
    base_url: null
    fallback: "anthropic:claude-sonnet-4-6"
  anthropic:
    api_key: "${ANTHROPIC_API_KEY}"
  gemini:
    api_key: "${GEMINI_API_KEY}"
  mistral:
    api_key: "${MISTRAL_API_KEY}"
  openrouter:
    api_key_secret: openrouter   # written by `axocoatl connect openrouter`
```

Hosted credential blocks need `api_key` or `api_key_secret` (a block with neither is
refused), and accept optional `base_url` and optional one-target `fallback`.
`api_key_secret` names a secret in the data root's secret store (`secrets/<name>`, the
rule of `axocoatl secret set` names) that holds the key, so the key is not in the file;
the daemon reads it when it starts. It holds a name, never the key: a value that reads
as a key (`sk-…`, `AIza…`, or a long run mixing letters and digits) is refused without
being repeated. It cannot be combined with a non-empty `api_key`, and the secrets
other commands own are never sent as a provider key: the receipt signing key,
`claude-code-oauth`, `codex-chatgpt`, and `codex-openai` except as OpenAI's. `axocoatl connect openrouter`
stores OpenRouter's key as `openrouter` after a browser sign-in and writes
`api_key_secret: openrouter`. The OpenAI adapter uses `base_url` for compatible
servers. OpenRouter's runtime endpoint is fixed. Empty hosted keys, and a named secret
that is not stored, prevent that provider from registering (the daemon logs which). For legacy Session and global Agent execution,
fallback is attempted once only for a pre-stream rate limit. Ways use their selected
primary provider directly until effective-route cost evidence can name and price a fallback
honestly. Any retained tool transaction pins the exact selected
slot/provider/model across later turns and restart until the complete transaction
leaves model history. Missing, conflicting, or stale route markers fail closed.
A known smaller fallback rejects an already oversized request locally, while
unknown custom-model constraints remain endpoint-validated.

Native Sessions accept reviewed local Ollama profiles or eligible OpenRouter-credit
profiles, reasoning models included. `openrouter_billing: credits` declares credit
billing with no connected BYOK provider keys; it does not change the account. Native
OpenRouter also rejects custom endpoints and configured fallback. Review the full
[provider requirements](/configure/providers/) before applying **Team & budget**;
YAML token guards do not replace its explicit Session authority.

## Server

```yaml
server:
  host: "127.0.0.1"
  port: 8080
  auth:
    api_keys: []
    bearer_tokens: []
    allow_unauthenticated: false
  cors_origins: []
  rate_limit:
    enabled: false
    max_requests: 100
    window_secs: 60
```

An empty CORS list means same-origin only. With no API key or bearer token, a
loopback listener requires the per-daemon
[local API token](/operate/security/#the-local-api-token), and non-loopback
binding fails. `allow_unauthenticated: true` turns both off; use it only behind
a proxy that enforces authentication. On loopback the Host check against DNS
rebinding stays on, so a proxy on the same host must send `Host: localhost`. The rate-limit values apply per client IP
only when enabled.

## Sandbox

```yaml
sandbox:
  backend: podman
  network: bridge
  allow_post_create_command: false
  allow_untrusted_images: false
  require_resource_limits: false
```

`allow_post_create_command` defaults the exact devcontainer post-create
command to approved only for an unreviewed Session. The browser shows that
default; an explicit per-Session checkbox decision overrides it. It never
preapproves lockfile-detected `npm ci` or an edited command.

Local Podman accepts these exact curated references without
`allow_untrusted_images`:

- `docker.io/library/alpine:3.20`
- `docker.io/library/debian:bookworm-slim`
- `docker.io/library/ubuntu:24.04`
- `docker.io/library/python:3.12-slim`
- `docker.io/library/node:20-slim`
- `docker.io/library/rust:bookworm`

Common Docker Hub aliases canonicalize to those references. Curated means
allowlisted, not audited or guaranteed to contain a project's dependencies.
Before a Session becomes Ready, local Podman verifies the repository commands
Axocoatl itself needs, attempts distro-aware provisioning inside the container,
and removes the container if the probe still fails. Session startup never
installs Podman with a host package manager or creates a Podman VM; it may start
an existing stopped VM.

A root Node project receives a Session-owned Podman volume over root
`node_modules`, masking host-native dependencies while the Workspace remains a
read-write bind mount. Nested package directories are not separately masked.

With `network: none`, use an image that already contains Axocoatl's required
repository commands and do not approve setup that needs downloads. The network
policy prevents in-container provisioning; a Podman image pull is a separate
host operation.

`backend` is `podman` or `e2b`; `network` is `bridge` (the default), `none` or
`egress` for Podman. Any other `network` value, such as `None` or `off`, is a
validation error. Axocoatl rejects `network: none` and `network: egress` with E2B
because the remote backend cannot prove that policy.

`network: egress` gives Session containers only the hosts listed under
`sandbox.egress`, through Axocoatl's egress proxy. Only the `bash` commands of an
Agent that may change files, approved setup commands, readiness provisioning and
terminals get a credential for it; read-only helpers and required checks have no
network. Ways attempts use their Session's proxy. See
[Network egress](/configure/sandboxes/#network-egress) for how it runs and what it
does not cover.

```yaml
sandbox:
  network: egress
  egress:
    allow:
      - npm                      # a preset
      - host: api.example.com    # ports default to [443]
        ports: [443]
      - host: "*.example.org"    # subdomains only, at least two labels after *.
      - cidr: 10.20.0.0/16       # an IP range, for IP-literal destinations
        ports: [8000]
    private_destinations: [10.0.0.0/8]
    sidecar_network: podman      # optional Podman network for the proxy
    max_connections: 128         # 8-256 connections open at once
```

`sidecar_network` names the Podman network the proxy container joins; leave it
unset for Podman's default network. Each allowed name is resolved on your computer
when a connection asks for it, so an entry must name the host the tool connects to.

Presets are `npm`, `yarn`, `pypi`, `crates`, `go`, `github`, `alpine`, `debian`
and `ubuntu`. The `npm`, `crates`, `alpine` and `debian` lists were checked against
the live registries with `npm ci`, `cargo fetch` and readiness provisioning; the
others are not yet verified. If a tool needs a host a preset lacks, the refusal names
it, and you can list that host yourself.

A `host` is a name, never an IP address; use `cidr` for addresses. A range that is
not wholly public must lie inside a `private_destinations` entry, and each
private destination must be wholly private (such as `10.0.0.0/8` or `fd00::/8`).
Loopback, link-local, multicast, documentation and other special ranges are refused,
including IPv4 addresses embedded in IPv6 forms. Validation warns about wildcard
entries, CDN-fronted presets (a tunnel to them can reach other sites on the same
CDN) and hosts that accept uploads (`github`, `npm`, `pypi`, `crates`). Under
another network mode, `allow`, `private_destinations` and `routes` do nothing, and
validation warns about them. The browser's own proxy still uses `sidecar_network` and
`max_connections` there (see [Browser](/configure/browser/)). The Session network
record keeps every event in every mode; `record_max_events`, which capped it in 1.2.0,
is still accepted but ignored, and `axocoatl validate`, `axocoatl doctor` and daemon
start warn that it can be removed. Native repository tools and required checks need local Podman. E2B supports
compatibility execution; it does not implement the native supervised command boundary.
For E2B:

```yaml
sandbox:
  backend: e2b
  e2b:
    api_url: "https://api.e2b.dev"
    api_key: "${E2B_API_KEY}"
    template: base
    domain: e2b.app
    git_token: "${GITHUB_TOKEN}"
```

The E2B defaults shown are applied when their fields are omitted. The backend
and template are daemon-global, not selected independently in the Session
create API. E2B does not honor a per-Session OCI image; such a request is
rejected before a remote VM is created. The selected template must already
contain Axocoatl's required repository commands: readiness verifies them, but
does not package-provision the remote template. E2B also does not provide the
local Preview/exposed-port transport. `git_token` configures GitHub-compatible
token authentication for an origin-scoped helper; other hosts may require a
different credential flow. Ready E2B Sessions retain their exact runtime ID and
remote root: Close pauses, Reopen reconnects, and Delete Session or Change/Rebuild
runtime performs checked deletion.

### sandbox.egress.routes

Routes are hosts whose HTTPS traffic Axocoatl ends on your computer, so it can
check each request and add a credential. They apply under `network: egress`, and
`axocoatl network reload` applies changes to them and to `credentials` to running
Sessions. See [Credentials and routes](/configure/credentials/) for how they work.

```yaml
sandbox:
  network: egress
  egress:
    routes:
      - host: github.com             # one exact name; no wildcard, no IP address
        ports: [443]                 # default [443]
        credential: github           # a credentials entry
        inject: {basic: {username: x-access-token}}   # or {header: Authorization, format: "Bearer {}"}
        for: [agent, terminal]       # agent, terminal, setup; default [agent]
        upstream_ca: ~/.config/axocoatl/registry-ca.pem   # optional, owner-only PEM
        rules:
          - {methods: [GET], path: "/acme/app.git/info/refs", query: {service: git-upload-pack}}
          - {methods: [POST], path: "/acme/app.git/git-upload-pack"}
        env_placeholders: [GITHUB_TOKEN]
        allow_encoded_responses: false
        allow_set_cookie: false      # true passes Set-Cookie on a credentialed route
        max_request_bytes: 1073741824
      - host: registry.npmjs.org
        access: read-only            # GET, HEAD, OPTIONS; or full
```

Validation refuses: a wildcard or IP address as `host`; a host and port listed by
two routes; `credential` naming no `credentials` entry; `inject` without a
credential or a credential without `inject`; `inject` with both or neither of
`basic` and `header`; a `format` without exactly one `{}`; a header Axocoatl or HTTP
controls (`Host`, `Content-Length`, `Connection`, `Proxy-Authorization`,
`Accept-Encoding` and the like); methods that are not uppercase, or `CONNECT`;
paths that do not start with `/` or have `//`, `.` or `..` segments (also before a
`;` parameter, as in `..;`), a segment starting with `;`, escaped or twice-escaped
`/`, `\` or `.`, or a `*` inside a segment; both `access` and `rules`, or neither; a
placeholder Axocoatl sets itself (proxy, certificate, `AXOCOATL_*` and basic process
variables); an `upstream_ca` that is not an owner-only regular file holding a PEM
certificate; `max_request_bytes` outside 1 KiB-1 TiB; and `provider_fetch` other than
`allow` or `refuse`. At most 64 routes, 64 rules per route, 16 methods and 16 query
parameters per rule. It warns when a credentialed route allows every path (a `**` rule,
`access: read-only` or `access: full`), when it passes compressed responses or
`Set-Cookie`, when a route to a model API sets `provider_fetch: allow`, and when a
route's host is also allowed by `allow` or a preset.

`provider_fetch` decides whether the route reads request bodies and refuses those that
ask the model provider to reach other hosts or run tools itself. Unset, it is `refuse`
on a route to `api.anthropic.com`, `api.openai.com`, `chatgpt.com`, `openrouter.ai`,
`generativelanguage.googleapis.com`, `api.mistral.ai`, `api.x.ai` or
`ai-gateway.vercel.sh` and off on any other route; see
[Requests to model APIs](/configure/credentials/#requests-to-model-apis). A refusal does not repeat a value written in a credential's
`env` or `file`, `inject.format` or `inject.basic.username`, where a pasted token may
be.

### sandbox.egress.host_ollama

```yaml
sandbox:
  network: egress
  egress:
    host_ollama:
      port: 11434          # a loopback TCP port on this computer, not the daemon's own
      for: [agent]         # agent, terminal, setup; default [agent]
```

An explicit, opt-in route from Session containers to an Ollama server on this
computer's loopback interface. Off when absent. Under `network: egress`, the processes
`for` names get `OLLAMA_HOST=https://ollama.host.axocoatl.internal:443`. That name never
resolves in DNS: the egress decision point recognizes it, the daemon ends TLS with the
Session's certificate authority and forwards each request over plain HTTP to
`127.0.0.1:<port>`, and every request and response is written to the Session's network
record like any route's. Only loopback is reached; no other host port is.

The route carries only Ollama's inference and model listing, as Ollama 0.20.6 and 0.40.6
serve them: `GET` (or `HEAD`) of `/`, `/api/version`, `/api/tags`, `/api/ps`, `/api/status`,
`/v1/models` and `/v1/models/<model>`, and `POST` of `/api/show`, `/api/chat`,
`/api/generate`, `/api/embed`, `/api/embeddings`, `/v1/chat/completions`,
`/v1/completions`, `/v1/embeddings`, `/v1/responses` and `/v1/messages`. Everything else
gets `403 route_denied`, recorded like any refusal: among it `/api/pull`, `/api/push`,
`/api/create`, `/api/copy`, `/api/delete` and `/api/blobs/…` (a pull or create fetches
from whatever registry the model name names), the account endpoints (`/api/me`,
`/api/signout`, `/api/user/keys/…`) and `/api/experimental/web_search` and
`/api/experimental/web_fetch`, which call `ollama.com`, and the endpoints Ollama 0.40
added: `/api/codex/…` (a proxy to OpenAI and ChatGPT), `/api/balance`, `/api/usage`,
`/api/experimental/model-recommendations`, `/v1/systemone` and `/v1/responses/compact`.
Pull models on this computer with `ollama pull`. The route also reads each request body
and refuses, with `403 provider_fetch_refused`, one that names a cloud model (a tag that
is `cloud` or ends in `-cloud`, such as `gpt-oss:120b-cloud`), which Ollama with its
cloud features on sends to `ollama.com`, prompt included, and does the same for a cloud
model named in the path of `GET /v1/models/<model>`; its OpenAI- and Anthropic-compatible
endpoints get the checks of [Requests to model APIs](/configure/credentials/#requests-to-model-apis)
besides. A local copy of a cloud model (`ollama cp gpt-oss:20b-cloud mygpt`) keeps its
cloud host under a name no check can recognize, so a Session opens the route only when
Ollama on that port reports its cloud features disabled (`GET /api/status`), and
`axocoatl network reload` refuses to turn the route on otherwise. When
`sandbox.network` is `bridge` or `none`, only [loadout](/configure/loadouts/) Sessions,
which always run under `egress`, reach it, and validation warns. Without it, the name is
refused like any unlisted host.

This route is for programs inside the Session, such as a test suite that calls a local
model. Agents' own model calls are made by the daemon and do not need it.

### sandbox.workload

```yaml
sandbox:
  workload:
    mode: auto               # auto (the default), hardened or image
    writer_user: "1000:1000" # numeric uid:gid
    helper_user: "1001:1001" # shares no id with writer_user
```

Which users run commands in a local Podman Session container. `auto` is `hardened`
under `network: egress` and `image` under `bridge` and `none`. `hardened` keeps the
container's first process as root and runs Agents' commands, setup commands,
terminals and required checks as `writer_user`, every process of a read-only helper
as `helper_user`, and readiness provisioning as root; neither user has Linux
capabilities. Agents' tool calls and required checks also run under a seccomp filter
and in a Landlock domain of their own, and under `egress` each connection's record
names the program that opened it. `image` runs every command as the image's own user. Ids run from 1 to
65533, and the helper's uid and gid must differ from both of the writer's. `hardened`
needs rootless Podman: under rootful Podman `auto` falls back to `image` with a
`doctor` warning, and `hardened` refuses to start a Session. `backend: e2b` refuses
`hardened`. See [Workload users](/configure/sandboxes/#workload-users).

## Credentials

```yaml
credentials:
  github: {env: GITHUB_TOKEN}                                # a variable of the daemon
  registry: {file: ~/.config/axocoatl/credentials/registry}  # an owner-only file
```

Each entry is exactly one of `env`, an uppercase variable name, or `file`, an
absolute or `~/` path. A [loadout](/configure/loadouts/)'s route may also name a
secret stored with [`axocoatl secret set`](/configure/external-agents/#store-the-credential):
its `credential` resolves to the entry here first, then to `secrets/<name>` in the data
root (`0600`) when that file exists. Names are 1-64 letters, digits, `_`, `.` or `-`, and are
recorded with each request that used them. Values are never in the configuration:
a plain value is refused without being repeated, and `${...}` is refused before
substitution. The daemon reads a value each time a request needs it; a file must
then be a regular file outside every Workspace, owned by the daemon's user and
readable only by it. At most 64 credentials; validation warns about one no route
uses, and about each stdio MCP server that inherits the daemon's environment while a
credential is read from it (`env`), since that server gets the value too.

## MCP servers

```yaml
mcp_servers:
  - name: local-tools
    transport: stdio
    command: npx
    args: ["-y", "@example/mcp-server"]
    env:
      EXAMPLE_API_KEY: "${EXAMPLE_API_KEY}"
  - name: remote-tools
    transport: streamable_http
    url: "https://mcp.example.internal"
    headers:
      Authorization: "Bearer ${MCP_TOKEN}"
```

Persistent transports are `stdio` and `streamable_http`/`http`. Stdio requires
`command`; HTTP requires `url`. A stdio server inherits the daemon's whole
environment by default, including any provider API keys and any route credential
read with `{env: ...}`. Set
`inherit_env: false` to start it with only `PATH`, `HOME`, `USER`, `LANG`, `LC_*`
and `TMPDIR` (plus `SYSTEMROOT` on Windows) from that environment, then its `env`;
we recommend it for every stdio server. A server added from Settings inherits the
environment. A stdio server still runs on your computer, outside any Session
sandbox, and its traffic is not in a Session's network record. Bootstrap logs
connection failure and continues.
Settings catalog connect/remove changes only the live registry and does not
rewrite this list.

## Skills and inactive hooks

```yaml
skills:
  - id: review-ready
    name: Review ready
    description: Publish review readiness.
    emits: [ReviewReady]

hooks: []
```

Firing a configured Skill publishes each name in `emits` on the event feed; that
is the only source of events that `on_event` triggers and webhooks match. The 1.0
keys `reacts_to`, `agents` and `prompt` were removed in 1.1.0: a config that sets
them still loads, and the daemon warns that they are ignored. A non-empty `hooks`
block is parsed and logs a warning, but it does not execute. Hook entries contain `name`, `type`, optional
`phase`, `tools`, `timeout_secs` (default 30), `url`, and `agent_id`.

## Legacy Automation seed

```yaml
workflows:
  - id: review
    name: Review
    agents: [reviewer, writer]
    entry_point: reviewer

schedules:
  - id: review-interval
    name: Review interval
    workflow: review
    every: 2h
    input: Review outstanding work.
    enabled: true

proactive:
  - id: review-response
    name: Review response
    agent: reviewer
    trigger:
      type: on_event
      event: ReviewReady
    input: Review the current change.
    enabled: true
```

Proactive trigger types are `schedule` with `every`, or `on_event` with
`event`, a name from some Skill's `emits` list. These three sections seed the canonical Automation store only when its
file does not exist. Once created, Settings/API records are authoritative for
Automations. `workflows` still supplies config-owned Session team selections;
editing an Automation does not edit that roster or a native Session's applied team.
A workflow's `htn_methods_file` was removed in 1.1.0; the daemon warns and ignores it.

## Web search, web fetch and consolidation

```yaml
web_search:
  provider: searxng
  searxng:
    managed: true        # Axocoatl runs the SearXNG container; false needs url
    # image: docker.io/searxng/searxng:<tag>   # default: the pinned image
    # url: http://127.0.0.1:8888               # only with managed: false
    engines: []          # keep only these engines; empty keeps SearXNG's defaults
    language: all
    safesearch: 0        # 0-2
    timeout_secs: 15     # 1-60

web_fetch:
  max_bytes: 4194304     # 64 KiB-8 MiB
  timeout_secs: 20       # 1-60

consolidation:
  enabled: true
  idle_threshold_secs: 120
  interval_secs: 1800
```

`web_search.provider: searxng` offers `web_search` to Agents whose `tools` list it,
through a SearXNG instance Axocoatl runs with local Podman (`managed: true`) or one
at `url` (`managed: false`). The `web_fetch` block's presence offers `web_fetch` the
same way. Both run on the host, not in the Session container, and each call in a
native Session is written to the Session's network record. Native Sessions refuse
them under `sandbox.network: none`; under `egress` they run as under `bridge`, and
`sandbox.egress` does not limit them. In attempts made with Explore several ways an
Agent that lists them runs without them. Legacy (1.0-format) Sessions offer
`web_fetch` only to an Agent that lists it, never under `network: none`, and do not
record either tool. See [Web research](/configure/web/) for setup, citations and
what leaves the machine.

`provider: tavily` with an `api_key` still loads for configurations that already use
it, but only legacy (1.0-format) Sessions use it: native Sessions refuse it and
`validate` warns. Any other provider is an error.

## Browser

```yaml
browser:
  image: localhost/axocoatl-browser:pw1.60.0
  allow: []                 # same entries as sandbox.egress.allow
  private_destinations: []  # private ranges allow entries may reach
  snapshot_max_bytes: 16384 # 1024-65536
  timeout_secs: 120         # 10-170, per call
  max_parallel: 2           # 1-4 calls at once per Session
```

A `browser` block turns on the `browser` and `browser_check` tools for Agents whose
`tools` list them; see [Browser](/configure/browser/). `image` defaults to the image
`axocoatl browser install` builds; another image should be pinned by digest, and
`validate` and `doctor` warn about a tag. `allow` and `private_destinations` take the
same entries and rules as `sandbox.egress`, and are reached only through Axocoatl's
egress proxy. `browser` is refused with `backend: e2b`, and `browser.allow` must be
empty with `network: none`; under `network: egress` the browser uses the Session's own
egress proxy, with `allow` as a policy of its own (told apart by credential; see
[Declared hosts](/configure/browser/#declared-hosts)). `axocoatl network reload`
applies changes to `allow` and `private_destinations` to running Sessions. An Agent that lists `browser` or `browser_check`
when no `browser` block is configured is refused when its team is admitted, and so is
an Agent with `writes: []` that lists `browser_check`.

## Webhooks

```yaml
webhooks:
  - name: internal-events
    url: "https://hooks.example.internal/axocoatl"
    events: [ReviewReady]
    secret: "${WEBHOOK_SECRET}"
    headers:
      Authorization: "${INTERNAL_TOKEN}"
    enabled: true
```

`events` names Skill events, since firing a Skill is what publishes events;
`events: []` selects every event.
`secret` enables HMAC-SHA256 signing. Delivery is live-process best effort, not
a durable queue.

## Attempt pricing

Compatibility Attempt pricing is keyed by the exact model string. Native provider
reservations use validated retained provider bounds, which this table cannot replace:

```yaml
pricing:
  gpt-5:
    input_per_mtok: 1.25
    output_per_mtok: 10.0
```

Values are dollars per million tokens. Provider-reported `reasoning_tokens` are charged at
the model's `output_per_mtok` rate. Missing remote model prices remain
unknown.

A loadout's Codex writer reports tokens but no cost: its cost is computed from them at the
`pricing` entry for exactly its model name when there is one, before the list price
Axocoatl pins for the model (see
[What a run costs](/configure/external-agents/#what-a-run-costs)). The entry's input rate
applies to every input token, cached or not. Ollama Ways have a known-zero model API charge only when
`providers.ollama.base_url` uses `localhost`, a `.localhost` host, or a loopback
IP address. A non-loopback Ollama endpoint uses its configured model price or
remains unknown.

## Run defaults

```yaml
run:
  models:
    writer: "ollama:qwen3-coder:30b"   # default of a loadout's writer_model
    reviewer: "ollama:gpt-oss:20b"     # default of a loadout's reviewer_model
```

`axocoatl onboard` writes the models it set up here, so `axocoatl run fix --task "…"`
needs no `--model`. Each value is `provider:model`. `run.models.writer` is the default of
a loadout's `writer_model` parameter and `run.models.reviewer` of its `reviewer_model`,
for `axocoatl run` and `POST /api/runs` alike; `--model` (or the request's `params`)
wins. Both keys are optional, and `run:` without them is the same as no `run:`.

Validation refuses:

- a value that is not `provider:model`;
- a reviewer on a provider other than `ollama` or `openrouter`: the reviewer is a native
  Agent, and Claude Code and Codex can write but not review;
- a writer on a provider other than `ollama`, `openrouter`, `anthropic` (Claude Code's
  models, for `fix-claude-code`) or `openai` (Codex's, for `fix-codex`);
- the same model as writer and reviewer;
- any other key under `run:` or `run.models:`.

A default applies to a run only where its provider fits what the parameter feeds: an
`ollama:` writer is not used for `fix-claude-code`, whose writer runs Claude Code and keeps
its own `anthropic:sonnet`, and an `anthropic:` writer is not used for `fix`'s native writer.
The run says which defaults it used and which it left out, and why, in its notes; see
[Models from your setup](/reference/run/#models-from-your-setup). The daemon reads `run:`
when it starts; restart it after a change. Until then, a run that misses a parameter the
file now sets is refused with a note that the file changed since the daemon started and
that it needs a restart.

## Validation boundary

`axocoatl validate` checks structural invariants such as duplicate IDs,
non-empty Agent provider/model strings, dependency and role constraints,
token-budget relationships, MCP transport shape, webhook URL shape, that
`sandbox.network` is exactly `bridge`, `none` or `egress`, and the bounds of the
`sandbox.egress` and `browser` blocks. It does not prove that:

- a provider ID has a registered adapter or credentials;
- a hosted model is reachable or entitled;
- sandbox backend/network strings are operational on this host;
- an MCP process/URL connects;
- the browser image exists (`axocoatl doctor` checks that);
- an Automation in the separate canonical store is valid.

<Aside type="caution" title="Settings has mixed persistence">
Agent patches and MCP catalog connections are live-process state. Automation
records and MCP decisions have durable JSON stores. YAML remains the durable
source for providers, Agents after restart, sandbox policy, configured Skills,
and MCP definitions.
</Aside>
