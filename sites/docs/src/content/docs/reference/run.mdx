`axocoatl run` runs one [loadout](/configure/loadouts/) against a repository through the
running daemon, prints progress and a summary, writes JUnit, a record bundle and the run's
[signed receipt](/workbench/receipts/) when asked, and exits with a code that says how the
run ended.

```text
axocoatl run <LOADOUT> (--task <TEXT> | --task-file <FILE|->)
             [--repo <DIR>] [--junit <FILE>] [--record <FILE>] [--receipt <FILE>]
             [--model <ROLE>=<PROVIDER:MODEL>]... [--param <NAME>=<VALUE>]...
             [--check <CMD>] [--setup <CMD>] [--keep none|branch|pr]
             [--json] [--dry-run] [--url <DAEMON URL>] [-c, --config <CONFIG>]
```

| Flag | Meaning |
| --- | --- |
| `<LOADOUT>` | A loadout id: `fix`, `fix-claude-code`, `fix-codex`, `qa`, `audit` or one of yours. Every run names its loadout, so the opt-in `audit` runs only when you ask for it here. A built-in id that a file of yours also declares is refused, naming the file, until you rename or remove it (see [Where loadouts live](/configure/loadouts/#where-loadouts-live)). |
| `--task <TEXT>` | The request, as you would type it in a Session. |
| `--task-file <FILE>` | Read the request from a file; `-` reads standard input. |
| `--repo <DIR>` | The repository; default the current directory. The daemon resolves it to a canonical path and uses the Workspace for it, creating one if needed. |
| `--junit <FILE>` | Write the [JUnit file](#junit) of checks and findings. |
| `--record <FILE>` | Write the [record bundle](#record-bundle). |
| `--receipt <FILE>` | Write the run's [signed receipt](/workbench/receipts/), a DSSE envelope. |
| `--model <ROLE>=<PROVIDER:MODEL>` | Sets the parameter `<ROLE>_model`, such as `--model writer=ollama:qwen3-coder:30b`. Repeatable. A parameter with a default needs none: `fix-claude-code` and `fix-codex` need only `--model reviewer=…`, and `writer_model` and `reviewer_model` default to the [models from your setup](#models-from-your-setup) when the configuration has them. `--model` wins over both. |
| `--param <NAME>=<VALUE>` | Sets a loadout parameter, such as `--param credential=codex-chatgpt` for `fix-codex`. Repeatable. An unknown name is a usage error. |
| `--check <CMD>` | The command a `detected: true` check runs, as `sh -c`, in place of the repository's detected check command. Needed when the repository has none. |
| `--setup <CMD>` | The exact setup command this run approves, in place of the loadout's `environment.setup`. |
| `--keep none\|branch\|pr` | What to do with a passing run's changes; default `none`. See [Keep as PR](/workbench/keep-as-pr/). |
| `--json` | Print the Outcome as JSON on standard output instead of the summary (with `--dry-run`, what admission found). |
| `--dry-run` | Only check the run as admission would and list every problem; no run, Workspace or Session is created, and a stopped Podman machine is not started. Each Ollama model is loaded once and probed, as a run's admission does. Also `--preflight`. `--task` is optional. See [The dry run](#the-dry-run). |
| `--url <URL>` | The daemon's address. |
| `-c, --config <CONFIG>` | The configuration file used to find the daemon's address and data root; default the user configuration. |

### Toolchain flags

```text
axocoatl run <LOADOUT> ... [--toolchain detected|node|python|rust|go|none]
             [--image <REF>] [--no-setup] [--no-build] [--no-probe]
```

A loadout that runs the repository's check (`fix`, `fix-claude-code`, `fix-codex`) runs
in Axocoatl's image of the repository's language. The run installs the repository's
dependencies with only that language's registries open, and checks that the check can
start before any model call. [Repository toolchains](/configure/toolchains/) describes
each step.

| Flag | Meaning |
| --- | --- |
| `--toolchain <NAME>` | `detected` (the default for such a loadout), `node`, `python`, `rust` or `go`, or `none` for the image as the loadout names it, with no detected install. Several toolchains whose check does not say which is a usage error that lists them. |
| `--image <REF>` | Run this curated or trusted image as it is, without a toolchain. Give its installs with `--setup`. You cannot combine it with `--toolchain <language>`. |
| `--no-setup` | Run no setup, not even the detected install. |
| `--no-build` | Refuse the run when its toolchain image is not built, naming the `axocoatl recipe build` command. Without this flag, `axocoatl run` builds the image first and prints what it builds, its size and Podman's progress on standard error. |
| `--no-probe` | Skip the probe that refuses a run whose check cannot work in its image, for a check the probe is wrong about. |

With a toolchain, `--setup` replaces the detected install and gets the same registries,
and `--check` also chooses among several toolchains by its program. A check whose
program cannot start in the image, or that runs none of the repository's tests, is
refused with exit code 3, and a setup that fails ends the run with exit code 5. Both
happen before any writer or reviewer turn.

## Models from your setup

`axocoatl onboard` writes the writer and reviewer it set up as
[`run.models`](/reference/config/#run-defaults) in the configuration. A run that does not name
them takes them from there: `run.models.writer` is the default of the loadout's
`writer_model` parameter and `run.models.reviewer` of its `reviewer_model`. With both
configured, `axocoatl run fix --task "…"` needs no `--model`, and `fix-claude-code` and
`fix-codex` take the reviewer.

- `--model` (or `--param`) on the command line wins.
- A default applies only where its provider fits: a writer on Ollama or OpenRouter is not
  Claude Code's model, so `fix-claude-code` keeps its own `anthropic:sonnet` writer and says
  why in a note.
- A run whose writer and reviewer would be the same model because of a default is refused
  (exit code 3): a default never reviews its own writer's change. Naming both yourself gives
  the same-model warning instead.
- The run says which defaults it used, as notes at the start (`· note: reviewer_model =
  ollama:gpt-oss:20b (from your setup: run.models.reviewer in the configuration)`) and in
  the summary's notes; the run's manifest records the values.

The daemon reads `run.models` when it starts, like the rest of the configuration, so
restart it after `axocoatl onboard` or an edit changes them. A daemon started before the
change says so: a run that misses a parameter the file now sets is refused with "the
configuration file … now sets run.models differently from when this daemon started …
restart it", and a run that starts anyway notes it.

## Before a run starts

The daemon checks a run in one pass before it creates anything (admission), and refuses it
with every problem it found, in one message:

1. The loadout, the task and the repository. The repository becomes the run's Workspace,
   which its Session mounts read-write, so it keeps to the rules of Open workspace…: one
   of Axocoatl's own directories (its data, configuration, lease or control-socket
   directory, or a folder inside one) is refused (`workspace_protected`), and so is a
   folder too broad to be a Workspace, such as the file system root, your home folder
   and the folders above it, or a folder that contains one of Axocoatl's own directories
   (`workspace_too_broad`), unless you opened it with Open workspace… in the workbench
   and confirmed it. A broad folder that Axocoatl 1.4 registered as a Workspace without
   asking is refused until you do.
2. The parameters, with the defaults above. Every missing parameter is named at once, with
   the `--model ROLE=provider:model` (or `--param`) that sets it and the `run.models` key
   that can.
3. The run's environment: its toolchain, image and setup, from the
   [toolchain flags](#toolchain-flags), the loadout and the repository's files
   (`--toolchain` with `--image` is refused). A `detected` check needs a
   check command: `--check`, a `Check command:` line of `AXOCOATL.md`, or one detected in
   the repository.
4. Each external writer's stored credential: the one it names, or for `credential: auto`
   the first of its runtime's that is stored. A credential that is not stored is refused
   with the `axocoatl connect` command that stores it.
5. Each native model (every native Agent and the reviewer) runs on Ollama or OpenRouter,
   and that provider is configured. Claude Code and Codex can write but cannot review, so
   `--model reviewer=anthropic:…`, `openai:…`, `claude-code:…` or `codex:…` is refused.
6. On Ollama: the server answers, runs a version native runs accept and has its cloud
   models off; then each model is pulled, is a GGUF model, loads and passes the contract
   probes, and is loaded with at least 16,384 tokens of context. Each refusal keeps
   Ollama's own reason and the fix, such as "Ollama does not have gpt-oss:20b: run
   `ollama pull gpt-oss:20b`". Unless `OLLAMA_CONTEXT_LENGTH` says otherwise, Ollama loads
   models with 4,096 tokens on a computer with less than about 23 GiB of GPU memory, and the
   fix writer's first call alone is about 9,700 tokens, so a smaller context is refused
   here, with the observed and the needed numbers and how to set `OLLAMA_CONTEXT_LENGTH`
   (or to use OpenRouter for that role), instead of failing on the run's first call. All the
   models under that floor are named in one problem, with the fix once: for the Homebrew
   service, `OLLAMA_CONTEXT_LENGTH=32768` in `~/.homebrew/services/ollama.env` and `brew
   services restart ollama`; for the Ollama app, its context length setting; for the
   systemd service, a drop-in (`sudo systemctl edit ollama`); otherwise
   `OLLAMA_CONTEXT_LENGTH=32768` in the environment that starts `ollama serve`. `axocoatl
   onboard` sets it for the Homebrew and systemd services after asking. A busy server
   (HTTP 503) is asked once more; one that is still busy, or fails to load a model (HTTP
   500), is an infrastructure problem (exit code 5), not a usage one.
7. The budgets, the network routes, the recipe image (with `--no-build`, one that is not
   built is refused, naming the `axocoatl recipe build` command), and for `qa` and e2e
   checks their own settings.
8. Podman, last: it must answer and run rootless. A stopped Podman machine (after a
   reboot, say) is started, as it is for a Session, but only when no other problem was
   found. A run installs nothing and creates no machine; that is left to you or to
   [`axocoatl onboard`](/start/onboard/). A machine switched from rootful to rootless is
   seen at the next run, without restarting the daemon.
9. A toolchain or recipe image that is not built is built now, once nothing else stops the
   run and Podman answered; a build that fails is an infrastructure problem (exit code 5).

Usage problems (exit code 3) come before infrastructure ones (5). A run with a usage
problem never asks Podman, and a run with any other problem only asks it, so a run that
cannot start never starts a Podman machine. A run refused by these checks leaves nothing
behind: no Workspace, Session, container, volume, run record or receipt. One problem is
printed as itself; several as a numbered list:

```text
axocoatl run: 2 problems stop this run, and nothing was started:
  1. Agent writer (claude-code) needs the credential claude-code-oauth (Claude Code's OAuth token, sent to api.anthropic.com), and it is not stored yet: run `axocoatl connect claude-code` (…), then run again
  2. the reviewer runs anthropic:opus, on the provider anthropic, and a native Agent or reviewer runs only on Ollama or OpenRouter (Claude Code and Codex can write, in fix-claude-code and fix-codex, but cannot review): pass --model reviewer=ollama:<model> or --model reviewer=openrouter:<vendor>/<model>
```

## The dry run

`axocoatl run <LOADOUT> --dry-run` (or `--preflight`) runs the same checks and starts
nothing: no Workspace, Session or run record is created, and Podman is asked
(`podman info`, `podman machine list`) but never started, so a stopped machine is reported
as "a run starts it first" rather than as a problem, and an image that is not built is
noted as one a run builds first. It is not free for Ollama: as a run's
admission does, it loads each Ollama model once, without a prompt, and runs the two
one-token contract probes, so the model then holds its memory until Ollama unloads it.
`--task` is optional (without one the task is not checked, and none is sent); `--junit`,
`--record` and `--receipt` are refused, since there is no run. When the check takes more
than a few seconds, a line says what it is doing. It prints the Ollama models with the
context each was loaded with, the parameters the run would use, the notes, what Podman said
and then either `Ready: yes, this run would start.` or every problem with its class:

```text
Dry run of loadout fix in /home/me/src/app: nothing was created or started.
Ollama models (each loaded once without a prompt and probed, as a run's admission does):
  ollama:qwen3-coder:30b: 32768-token context
  ollama:gpt-oss:20b: 32768-token context
Parameters:
  reviewer_model = ollama:gpt-oss:20b
  writer_model = ollama:qwen3-coder:30b
Notes:
  writer_model = ollama:qwen3-coder:30b (from your setup: run.models.writer in the configuration)
  reviewer_model = ollama:gpt-oss:20b (from your setup: run.models.reviewer in the configuration)
Sandbox: the Podman machine is stopped; a run starts it first
Ready: yes, this run would start.
```

It exits 0 when the run would start, else with the first problem's code (3 or 5), and 4
when the daemon cannot be reached or is older than this `axocoatl` and has no dry run (it
then says to restart the daemon, and nothing was started). With `--json` it prints the
daemon's answer to
[`POST /api/runs/preflight`](/reference/http-api/#loadouts-and-runs):
`{loadout, ready, exit_code, problems: [{code, exit_code, message}], params, defaults,
warnings, notes, sandbox?, ollama_models: [{model, loaded, context_tokens?}]}`. A dry run
that is ready can still meet a Workspace another run holds (exit code 7) or a setup that
changed in between.

The dry run is its own route, not a flag on `POST /api/runs`: a daemon too old to know it
answers 405, so an upgraded `axocoatl` talking to a daemon started before the upgrade can
never start a run when it asked for a dry run.

## How it finds the daemon

`axocoatl run` talks to a daemon that is already running (`axocoatl dev`, `axocoatl
serve` or the [service](/operate/service/)) over its HTTP API. It never starts one; when
none answers, it says to start one with `axocoatl dev`.

- **Address:** `--url`, else `AXOCOATL_URL`, else `http://<server.host>:<server.port>`
  from the configuration file.
- **Credential:** `AXOCOATL_TOKEN`, else the daemon's
  [local API token](/operate/security/#the-local-api-token), read from
  `local-api-token` in the data root, sent as `Authorization: Bearer`. Pass the same
  `--config` and `AXOCOATL_DATA_DIR` the daemon uses.

A daemon that cannot be reached, or that refuses the credential, is exit code 4.

## The data directory

Loadout runs need native Session history. A data directory the daemon creates is
native, and so is one that existed before the daemon first started but that no daemon
has used and that holds no Session, such as a directory you made with `mkdir` or in
which `axocoatl secret set` stored a credential. A data directory that a daemon already
used in the 1.0 Session format still uses it, and a run on it exits with code 5 and the
message to stop Axocoatl, make a cold backup, and run `axocoatl session upgrade
--confirm` with the same `--config` and `AXOCOATL_DATA_DIR`, then start Axocoatl again.
See [Upgrade](/operate/upgrade/).

## One run per Workspace

A run needs its repository's Workspace to itself. When another Session holds that
Workspace, because one of its turns is running or needs attention, the run is refused at
once, before a Session or a run is created, and the message names what holds it, such
as the Session, its run and its turn: the Workspace is busy; retry later. The command
exits with code 7 (busy), and `POST /api/runs` returns 409 with `code: workspace_busy`. Let that turn
finish, or stop it or close its Session, then run again. A run never waits for the
Workspace.

A run does not hold it once it ends. When a run has everything its Outcome needs, it
stops each of its own turns that did not complete, such as one that needs attention, as
a person's Stop would (a `closing_turn` phase line on standard error), so the next run
on the repository is admitted. The Outcome keeps each turn as it was observed.

Then the run stops its Session's runtime, before its network summary, receipt and
Outcome are written: the Session's container, egress sidecar and browser stop, as when
the daemon stops, so a run that ended leaves nothing running. A run that ends at its
environment (the setup or the toolchain failed, or its read-only Agents cannot read the
repository) stops it too. The Session stays open with its turns, History, team, network
record and changes, so Keep, the record bundle and the workbench work as before, and what
needs its container again, such as its Terminal in the workbench, starts it again. When
the runtime cannot be stopped, for example because another Session's turn holds the
Workspace, the run has the warning `session_runtime_not_stopped`, which names the Session
and `axocoatl session close`; the verdict and the exit code do not change.

A run can still be refused after its Session was made: by the check probe, which runs in
the Session's container, or when its run record cannot be written. That closes the
Session, so nothing of it runs on; the repository stays in the list of Workspaces with
that closed Session, and no run record or receipt is left. A run whose record could be
made before a later write failed ends in the record as failed, with the refusal.

## What it prints

1. Once the daemon has admitted the run: the run id, the Session id and any warnings, on
   standard error, then admission's notes, such as the models it took from your setup
   (`· note: reviewer_model = ollama:gpt-oss:20b (from your setup: …)`) and the stored
   credential an external writer's route sends (`· note: Agent writer (codex) sends the
   stored credential …`). Admission checks the run first (it loads each Ollama model once
   and probes it, then asks Podman and starts a stopped Podman machine when nothing else
   stops the run), then prepares the Session's environment; when that takes more than a
   few seconds, a line says what it is doing. A refused run prints every problem admission found
   ([Before a run starts](#before-a-run-starts)) and never says that it started.
2. One line per phase, turn start and end, warning, not-covered entry and provider retry,
   on standard error, while the run proceeds. Each warning is printed once.
3. When the run finishes, a summary on standard output: the verdict; each check with its
   state, exit code and report counts; the review verdict and rounds; each adjudication
   (finding, decision, reason); the findings, each with its area, severity and location
   when known, and "fails on clean build" shown as such; every not-covered entry with its
   reason; the notes (what was neither a gap nor a warning, such as the stored
   credential an external writer's route sent and, for `credential: auto`, why, what an
   audit worker said it did not reach, or the files an audit gave to its area `rest`); the
   warnings, including the same-model warning; usage (marked "known subtotal"
   when a call's usage is unknown, with the cost as "$X (includes cost computed from
   reported tokens at list prices)" when part of it is computed from a program's reported
   tokens, such as a Codex writer's, and as "cost unknown (reserved up to $X)" when a
   call's cost is not known, such as a Codex writer's on a model without a price);
   and the record id. With `--json`, standard output holds only the Outcome, one JSON
   document, and everything else goes to standard error, `Kept:` and `Pull request:`
   from Keep included. That Outcome is the one the run ended with; what Keep did is in
   the record's `keep` event and in `GET /api/runs/{run_id}`. After Keep, `Receipt:`
   names the receipt the commit's `Axocoatl-Receipt` trailer carries.

`--junit`, `--record` and `--receipt` are written even when the run fails, each to a
temporary file that is then renamed, so a reader never sees half a file; standard error
says where, and for the receipt which key signed it, how many files it covers and where
their digests come from. A run that never started (the
daemon refused it, as for a busy Workspace or a missing parameter, could not be reached,
or the flags were refused) has no run id: `--junit` still writes a file whose `run`
suite's `verdict` case is an `<error>` of type `busy` (exit code 7), `usage` (3) or
`error` (any other code), with the reason and `axocoatl.exit_code`, and `--record` and
`--receipt` write nothing, since there is no run to record or sign; standard error says
so. A finished run whose receipt could not be signed has the warning
`receipt_unavailable`; `--receipt` then writes nothing, says why, and the exit code is
the run's. A run whose receipt does not cover every path it changed has the warning
`receipt_incomplete`, and standard error says so after where the receipt was written. With `--keep`, Keep runs first,
so the `--record` file holds its `keep` event like `GET /api/runs/{run_id}/record`. When
the run passed but one of the files could not be written, `axocoatl run` exits with that
error's code instead of 0.

**Ctrl-C** asks the daemon to stop the run, waits up to 30 seconds for its Outcome,
writes `--junit`, `--record` and `--receipt`, and exits with code 6. Ctrl-C before the
daemon has admitted the run, while it checks the run or prepares the Session's
environment, ends `axocoatl run` at once with code 6 and writes only `--junit`, as for a
run that never started. The daemon finishes the admission on its own: a run it refuses
cleans up as above, and a run it admits stops before its first turn, as interrupted,
and stops its Session's runtime, so nothing of it runs on. `GET /api/runs` lists that run.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | Pass: every required check passed, the review (if any) approved, every review finding was answered, nothing is not covered, and no finding the loadout fails on. |
| 1 | A required check failed or timed out on the final result. |
| 2 | Needs attention: the review did not pass, a finding was not answered, something was not covered, an audit area's findings could not be read, a check never ran on the final result, a turn needs attention or was blocked, a budget or the wall clock ran out, findings the loadout fails on (`fail_on_findings`), or Keep failed. |
| 3 | Usage: a bad flag; an unknown loadout or one that cannot be used; a repository that is one of Axocoatl's own directories, or too broad to be a Workspace and not confirmed as one; a missing or unknown parameter; a writer and reviewer on the same model because of a [default from your setup](#models-from-your-setup); a built-in id that a file of yours also declares; a `detected` check with no detected command and no `--check`; an external writer's credential that is not stored (the one it names, or none of its runtime's for `credential: auto`), a route credential that is neither configured nor stored, or a route that differs from one your configuration has for the same host; a native model (an Agent's or the reviewer's) on a provider other than Ollama or OpenRouter, or on one that is not configured; an Ollama server that cannot be reached, runs a refused version or has its cloud models on, or a model it does not have, that is not GGUF, that fails the contract probes, or that it loads with less than 16,384 tokens of context; for `qa`, no `browser:` block or a URL the browser cannot reach; an e2e model that OpenRouter does not list with tool calls and image input; or budgets that cannot pay for one model call, or for the run's checks or review. Admission reports every one it finds at once. |
| 4 | The daemon could not be reached, or it refused the credential; with `--dry-run`, also a daemon too old to have a dry run. |
| 5 | Infrastructure: Podman is not installed, has no machine, cannot start its machine or does not answer; Ollama is still busy after one retry, fails to load a model (HTTP 500) or stops answering while admission checks a model; the Session could not run under egress with the `hardened` workload (rootful Podman, `backend: e2b`); a recipe image was not built; the Session environment failed; OpenRouter's catalog could not be read for an e2e check; a provider failed when the Session started; or another daemon error. |
| 6 | You interrupted the run. |
| 7 | Busy: another run, or a Session's turn, holds the repository's Workspace, so the run was not admitted or its next turn could not start. Nothing is wrong with the run; run it again once that turn ends. The message names the Session and turn that hold the Workspace when they are known. |

When several of 1, 2, 5 and 6 apply, the code is the first of 5, 6, 1, 2 in that order,
and 0 only when none does. Code 7 takes the place of 5 when the run could not go on only
because the Workspace was held. Code 3 usually comes before a run starts, and also ends a
started run whose loadout the daemon could not apply as written, such as budgets too small
for its checks. Code 4 can come at any point, when the daemon stops answering. Nothing is
a pass by default: a check that did not run, a review finding nobody answered and an area
nobody reached each make the run need attention.

The reasons are listed under `attention` in the Outcome, in words.

```sh
axocoatl run fix --task-file task.md \
  --model writer=ollama:qwen3-coder:30b --model reviewer=ollama:gpt-oss:20b \
  --junit axocoatl-junit.xml --record run.axorecord.jsonl
case $? in
  0) echo "passed" ;;
  1) echo "checks failed" ;;
  2) echo "needs a person" ;;
  7) echo "the Workspace is busy; run again later" ;;
  *) echo "could not run" ;;
esac
```

## JUnit

The JUnit file has one `testsuite` per kind of result, and a last one for the verdict:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<testsuites name="axocoatl" tests="7" failures="2" errors="0" skipped="1" time="512.3">
  <properties>
    <property name="axocoatl.run_id" value="run-…"/>
    <property name="axocoatl.session_id" value="…"/>
    <property name="axocoatl.loadout" value="fix@1 sha256:…"/>
    <property name="axocoatl.verdict" value="needs_attention"/>
    <property name="axocoatl.exit_code" value="2"/>
    <property name="axocoatl.usage" value="1200 input + 300 output tokens, $0.0123"/>
    <property name="axocoatl.warning.same_model_reviewer" value="…"/>
  </properties>
  <testsuite name="checks" tests="1" failures="0">
    <testcase classname="axocoatl.check" name="tests" time="41.2"/>
  </testsuite>
  <testsuite name="check:e2e" tests="2" failures="1">
    <testcase classname="e2e.checkout" name="pays with a saved card">
      <failure message="expected …">…</failure>
    </testcase>
  </testsuite>
  <testsuite name="review" tests="1" failures="0">
    <testcase classname="axocoatl.review" name="required-review"/>
  </testsuite>
  <testsuite name="adjudications" tests="2" failures="1">
    <testcase classname="axocoatl.adjudication" name="round 1 F1"><system-out>accept: …</system-out></testcase>
    <testcase classname="axocoatl.adjudication" name="round 1 F2"><failure type="missing" message="the writer did not answer F2"/></testcase>
  </testsuite>
  <testsuite name="findings" tests="2" failures="1" skipped="1">
    <testcase classname="axocoatl.finding.checkout" name="B1 total ignores coupon"><failure type="confirmed" message="…"/></testcase>
    <testcase classname="axocoatl.finding.search" name="B2 …"><skipped message="fails on clean build"/></testcase>
  </testsuite>
  <testsuite name="coverage" tests="1" failures="1">
    <testcase classname="axocoatl.coverage" name="gift cards"><failure type="not_covered" message="provider_refusal: classifier stop"/></testcase>
  </testsuite>
  <testsuite name="run" tests="1" failures="1">
    <testcase classname="axocoatl.run" name="verdict"><failure type="needs_attention" message="…the reasons…"/></testcase>
  </testsuite>
</testsuites>
```

| Result | In the JUnit file |
| --- | --- |
| A check that failed or timed out | `<failure>` |
| A check that did not run, or whose record cannot be read | `<error>` |
| A check that wrote a report ([e2e](/configure/e2e-check/), JUnit) | one more suite, `check:<name>`, with its test cases |
| A review that did not pass | `<failure>` |
| An adjudication the writer did not give | `<failure type="missing">` |
| A rejected finding | a passing case with the reason in `<system-out>` |
| A confirmed or reproduced QA finding, or an audit finding | `<failure>` when the loadout fails on findings, otherwise a passing case with the finding in `<system-out>` |
| A finding that fails on the clean build, or did not reproduce | `<skipped>` |
| A reproduction that could not run, or is missing | `<error>` |
| Anything not covered | `<failure type="not_covered">`, never skipped |
| An audit area whose findings could not be read | in `findings`, `<failure type="findings_unreadable">` named `<area> (findings unreadable)`, with the worker's last answer in `<system-out>` |
| A warning, such as the same-model reviewer | a property `axocoatl.warning.<code>` |
| The run's notes | the `verdict` case's `<system-out>`, one `note: ` line each, whatever the verdict |
| Usage | a property `axocoatl.usage`, worded as in the summary: a cost the run does not know is "cost unknown (reserved up to $X)", never a price, and a cost computed from reported tokens says "includes cost computed from reported tokens at list prices" |
| The run's verdict | suite `run`, case `verdict`: a `<failure>` with the reasons when checks failed or the run needs attention, an `<error>` when it was interrupted or could not run (`type="busy"` when another run or Session held the Workspace, exit code 7), so a CI job that reads only JUnit still sees a run that did not pass. A run that was never admitted has only this case, an `<error>` of type `busy`, `usage` or `error`, with `axocoatl.loadout`, `axocoatl.verdict` (`error`) and `axocoatl.exit_code` and no run or Session id |

Text is XML-escaped and control characters other than tab and newline are removed. Each
message is at most 4 KiB and the file at most 8 MiB; cases beyond that are summarized in
one `truncated` case.

## Record bundle

`--record` writes the run's whole record as one JSON Lines file, schema
`axocoatl.record-bundle/2`
(`application/vnd.axocoatl.record+jsonl`; a name such as
`run-….axorecord.jsonl`). The same file, byte for byte, is
[`GET /api/runs/{run_id}/record`](/reference/http-api/#loadouts-and-runs) and
**Download record** in the Run outcome panel: the header's `created_at_ms` is when the
run finished (the Outcome's `finished_at_ms`), not when the file was downloaded, so
every download of a finished run is the same file while nothing is added to its record
and its Session does not change. Keep adds a `keep` event, and closing the Session
changes its `session` section. The bundle of a run that has not finished is a snapshot
of a record still growing and carries the time it was read.

```text
{"schema":"axocoatl.record-bundle/2","run_id":"run-…","session_id":"ses-…","created_at_ms":…,"axocoatl_version":"1.4.0"}
{"section":"manifest","data":{…}}        the run's manifest: loadout, parameters, the stored credential each external writer sent, task, repository HEAD, dirty paths
{"section":"loadout","data":{"text":"…exact YAML…","digest":"…"}}
{"section":"outcome","data":{…}}         the Outcome
{"section":"session","data":{…}}         the Session record
{"section":"team","data":{…}}            the applied Team and budget
{"section":"turn","data":{…}}            one per turn: its control-plane record
{"section":"history","data":[…]}         the Session's History, versioned
{"section":"network","data":{…}}         one per network-record event, all of them
{"section":"run_event","data":{"seq":1,"event":{…}}}   one per run event
{"section":"receipt","data":{…}}         the run's signed receipt, its DSSE envelope (absent without one)
{"section":"end","lines":N,"sha256":"…"}
```

Sections appear in that order. `team` is the Team as the run applied it: each slot with
`reset_history` (whether Apply started its Agent from a fresh conversation, as a run
always does), `tools` (the tools its retained definition lists) and, for a loadout's
Agent, the inline `definition` it was given. `history` is the Session's History in its
versioned form, one `{"history_version": "execution_v2", "turn": {…}}` entry per turn
with its activations and their streams. The last line counts the section lines between
the header and itself and holds the SHA-256 of every byte before it. Check a bundle:

```sh
axocoatl record verify run.axorecord.jsonl
```

It prints the run id, the sections and their line counts, and exits 0, or 2 when the
order, the count or the digest does not match. It also accepts the bundles of Axocoatl
1.3 (schema `axocoatl.record-bundle/1`, the same sections without `receipt`). The digest
shows that the file was not changed after it was written; it is not a signature: anyone
who edits the file can compute it again. The `receipt` section is signed:
`axocoatl receipt verify <receipt> --record <bundle> --keys <trusted keys>` checks that the
bundle verifies and carries that receipt for its run. The bundle holds only recorded
evidence: routes never record a credential's value, so none is in the file.

## Where runs are kept

Each run is kept under `loadout-runs/<run id>/` in the data root: `manifest.json`,
written once when the run is admitted; `events.jsonl`, appended as the run proceeds;
`receipt.dsse.json` (`0600`), the signed receipt, written just before the Outcome; and
`outcome.json`, written once when it ends. Deleting the Session does not delete them.
If the daemon restarts during a run, the run ends as failed with the reason "the daemon
restarted during the run; it was not resumed". A repeated `request_id` returns the same
run only while the daemon process that admitted it is running.

<Aside>
A run is an ordinary Session. Open it in the workbench to read its turns, the Agent graph,
the network record and Git while it runs or after it ends. Once the run has ended, its
container is stopped until something in the Session needs it again.
</Aside>
