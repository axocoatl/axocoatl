The daemon listens on `http://127.0.0.1:8080` by default and, on loopback with
no configured credentials, requires its per-daemon local API token (see below).
JSON errors generally
use `{ "error": "message" }`. The router in `axocoatl-server/src/lib.rs` and
handler Serde types remain authoritative; there is not yet a generated OpenAPI
document.

The docs content check compares every literal router path with this page and
the [WebSocket reference](/reference/websocket/).

## Authentication, CORS, and rate limits

Every workbench and control-router route that reads or changes state requires a
credential. The dedicated Preview virtual Host is intercepted before that router
and is constrained separately by its exact Session/port Host and browser-origin
boundary.

**Local token (default).** On a loopback listener with no `server.auth`
credentials, the credential is the per-daemon token in the data root's
`local-api-token` file. Send it in one of three forms:

```http
Authorization: Bearer <token>
x-api-key: <token>
Cookie: axocoatl-token-<port>=<token>
```

Browsers get the cookie by opening the sign-in link that `axocoatl dev`,
`axocoatl serve`, or `axocoatl url` prints. `GET /?token=<token>` answers
`303 See Other` to the same path and query without `token`, sets the cookie
(HttpOnly, SameSite=Strict, `Path=/`, `Max-Age=2592000`), and sends
`Referrer-Policy: no-referrer` and `Cache-Control: no-store`. A wrong token,
or `/` without a credential, returns `401` with a short sign-in page. The cookie
is ignored on requests marked `Sec-Fetch-Site: cross-site` or `same-site`.
Public paths in this mode: `/health`, `/health/ready`, `/health/live`, `/ui/*`,
`/vendor/*`, `/lattice/*`, `/brand/*`, `/axo-tap.js`, and the sign-in page at
`/`. `server.auth.allow_unauthenticated: true` turns the token off but keeps
the Host check described below.

**Configured credentials.** With `server.auth.api_keys` or `bearer_tokens`,
send one of:

```http
x-api-key: <key>
Authorization: Bearer <token>
```

Only the health probes are public, there is no sign-in cookie, and an empty
configured value never matches. All comparisons are constant time.

Checks run in this order: an unexpected Host (`421`), a disallowed browser
origin (`403`), then the credential (`401`). An empty `server.cors_origins`
allows same-origin workbench requests only. Browser writes and WebSockets with
an opaque `Origin: null` are always rejected; other cross-origin browser writes
require an explicitly allowed origin. On a loopback listener without configured
credentials, including with `allow_unauthenticated`, a Host other than
`localhost` or a loopback IP literal is rejected to prevent DNS rebinding. Origin-less CLI clients remain supported. Cross-origin
preflight for the control router advertises HEAD, GET, POST, PUT, PATCH, and
DELETE. Control-router rate limiting is disabled by default and applies per
client IP when enabled; Preview traffic stays outside that middleware.

Preview applications use a separate virtual origin shaped like
`<session>-p<port>.localhost:<listener-port>`. That Host is intercepted
before the workbench router, so no `/api`, `/ws`, app-shell, or static-asset
path can fall through to the control origin. Each Session and logical port has
its own browser storage/cookie origin. Modern browsers can block ordinary app
cookies while that origin is embedded; the workbench's **Open full preview**
action opens the same virtual URL top-level with `noopener`, where host-only
cookies work without becoming shared sibling cookies. A browser GET or HEAD
for the exact `/` workbench document on a loopback IP literal redirects to
`localhost` on the same listener and preserves the query. API, health, and
asset URLs do not redirect.

## Native Session controls

These routes use the same authenticated Session owner as ordinary Send. A preview
is read-only; Apply binds the reviewed request and exact revisions. Retrying an
uncertain reply must reuse that request unchanged. Stale revisions are conflicts,
not permission to choose another activation or team.

| Method | Path | Request / behavior |
| --- | --- | --- |
| GET | `/api/sessions/{id}/team` | Current team revision, selected templates, explicit limits, and expiry. `required_checks` lists the applied team's checks; `suggested_check` is the Session's detected check command as an argument array, offered only and never run unless an Apply includes it. `required_review` is the applied team's review setting, when it has one, and `reviewers` lists the templates that may review: read-only Workers. `warnings` lists warnings about the applied team, such as `{"code": "same_model_reviewer", "message": …}` when the required reviewer runs a writer's provider and model |
| POST | `/api/sessions/{id}/team/preview` | Typed whole-team edit; resolves and reviews future-turn definitions and authority. A slot's `writes` is the whole list of paths that Agent may change: `null` allows any file and `[]` is read-only. Leaving it out keeps the scope of the template or current definition the slot starts from, so omitting it never widens what the Agent may change; the app always sends it. The edit's optional `required_checks` is an array of argument arrays, such as `[["sh", "-c", "npm test"]]`, that the host runs after every turn's required Agents finish; it is refused when no required Agent has `bash`. The optional `check_options` is aligned by index with `required_checks`, one `{name?, timeout_ms?, report?, egress?}` per check or none at all: `timeout_ms` is 1,000 to 1,800,000 (180,000 when omitted), `egress: true` gives the check's process its own egress credential under `network: egress` (an e2e check sets it; other checks have no network there), and `report` is `{format, path}`, with `format` `junit` or `e2e_report_json` and `path` under `/tmp/axocoatl-check-reports/`; a check that writes its report there and prints its digest has it parsed into the turn's check result (see [The e2e check](/configure/e2e-check/)). The optional `required_review` is `{"template_id", "max_rounds", "limits", "max_output_tokens"}`: a read-only Worker template the host runs after every turn's required Agents and checks, 1 to 3 rounds (2 when omitted), the reviewer's limits for all rounds of one turn, and its output bound per request (the template's when omitted). An edit whose limits cannot pay for what it names (a missing or zero limit, a missing or past expiry, a helper over its lead's limits, review rounds outside 1 to 3, or a check payer, reviewer or lead budget too small for its rounds) is refused with `422` and the reason alone; a stale configuration revision is `409` |
| POST | `/api/sessions/{id}/team/apply` | `{edit, review_digest}`; exact reviewed future-turn edit |
| POST | `/api/sessions/{id}/team/cancel` | Cancel the referenced team draft without changing current authority |
| POST | `/api/sessions/{id}/turns/{turn_id}/control-commands` | Typed human action with exact command/activation/revision identities; returns the canonical receipt |
| POST | `/api/sessions/{id}/turns/{turn_id}/graph-edits/preview` | Review AddAgent or ReplaceFutureAgent against the exact graph revision. The new work starts from one of the Session team's Agents (`agent.source_slot_id`) or a configured template (`agent.template_id`), exactly one of the two, and keeps what that Agent may change; `agent.writes` may only narrow it |
| POST | `/api/sessions/{id}/turns/{turn_id}/graph-edits/apply` | Apply the original reviewed graph edit and digest |
| GET | `/api/sessions/{id}/turns/{turn_id}/grants` | `{grants, proposals}`: each grant's `policy`, `authority_revision`, `revoked_at_revision` and cumulative `usage` (`activations`, `invocations`, `tokens`, `cost_microunits` charged so far: a running call's reservation, then what the settled call reported), and retained expansion proposals |
| POST | `/api/sessions/{id}/turns/{turn_id}/grants/preview` | Explicit total limits, expiry, delegated operations, graph bounds, and reason |
| POST | `/api/sessions/{id}/turns/{turn_id}/grants/decide` | `{request, review_digest, approve, reason}`; exact approval or decline |
| POST | `/api/sessions/{id}/turns/{turn_id}/grants/revoke` | `{grant_id, expected_grant_revision}`; closes new dispatch without undoing started effects |
| GET | `/api/sessions/{id}/ways-history` | Retention limits, retained decision records, and deletion tombstones |
| POST | `/api/sessions/{id}/ways-history/configuration` | `{limits: {version, field_bytes, record_bytes, aggregate_bytes, records, candidates, items_per_field}}`; every numerical limit is explicit |
| GET | `/api/sessions/{id}/ways-history/{decision}` | Export the retained record and protected patch bodies |
| DELETE | `/api/sessions/{id}/ways-history/{decision}` | Explicit deletion after runtime cleanup; retains a tombstone |

## Loadouts and runs

[Loadouts](/configure/loadouts/) and the runs [`axocoatl run`](/reference/run/) starts.
Errors are `{"error": "…"}`: `422` for a usage error (an unknown or invalid loadout, a
missing or unknown parameter, an opt-in loadout not named), `409` for a conflict, `501`
for a part this build does not implement, `400` otherwise.

| Method | Path | Request / behavior |
| --- | --- | --- |
| GET | `/api/loadouts` | Every built-in and user loadout: `[{id, version, name, description, kind, builtin, opt_in, digest, params, warnings, error?, path?}]`. `params` lists each parameter's `name`, `kind`, `required`, `default` and `description`. A user file that cannot be used has its `path` and `error` and empty `version`, `kind` and `digest` |
| GET | `/api/loadouts/{id}` | `{summary, file, text, graph}`: the summary row, the parsed file, its exact text and a display graph of `nodes` (`{id, kind, label, detail}`, `kind` one of `agent`, `check`, `review`, `area_workers`) and `edges` (`{from, to}`). The graph is for display only |
| POST | `/api/loadouts/validate` | `{text}`, at most 128 KiB. Returns `{valid, error?, warnings, summary?}` without saving anything |
| POST | `/api/runs` | Start a run: `{loadout, task, repo, params?, keep?, check_command?, setup_command?, request_id}`. `repo` is canonicalized and found or created as a Workspace; `keep` is `none` (the default), `branch` or `pr`; a repeat with the same `request_id` returns the same run. Answers `202` with `{run_id, session_id, workspace_id, warnings}` |
| GET | `/api/runs` | Every run, newest first: `[{run_id, session_id, loadout, state, phase, started_at_ms, outcome?}]`; `state` is `preparing`, `running`, `finished` or `failed` |
| GET | `/api/runs/{run_id}` | One run, with its Outcome once finished, and `keep` after Keep as PR |
| GET | `/api/runs/{run_id}/events?after=<seq>&limit=<1-1000>` | `{events, next_after, finished}`; each event is `[seq, {kind, at_ms, …}]` with `kind` `phase`, `turn_started`, `turn_ended`, `warning`, `adjudication`, `finding`, `not_covered`, `provider_retry` or `ended` |
| POST | `/api/runs/{run_id}/stop` | Stop the run's turn; answers `202`. The run ends `interrupted` |
| GET | `/api/runs/{run_id}/junit` | The run's [JUnit file](/reference/run/#junit), `application/xml` |
| GET | `/api/runs/{run_id}/record` | The run's [record bundle](/reference/run/#record-bundle), streamed as `application/vnd.axocoatl.record+jsonl` |
| POST | `/api/sessions/{id}/keep-pr` | [Keep as PR](/workbench/keep-as-pr/): `{run_id, branch?, open_pr?, remote?, title?}`. Returns `{branch, commit, paths, pushed_to?, pull_request_url?}`; `409` with the reason when the run did not pass, a run path was dirty before the run, the branch exists, the branch is the remote's default branch, or the remote branch exists |

The Outcome (`schema` `axocoatl.run-outcome/1`) holds `run_id`, `session_id`,
`workspace_id`, `loadout` (`{id, version, kind, digest, builtin}`), `task`,
`started_at_ms`, `finished_at_ms`, `verdict` (`pass`, `checks_failed`,
`needs_attention`, `interrupted` or `error`), `exit_code`, `attention` (the reasons, in
words), `turns`, `checks` (each with `name`, `argv`, `state`, `timeout_ms`, `exit_code`,
output tails, `candidate_sha256`, `report` and `reason`), `review` (the reviewer and every
round's verdict and numbered findings), `adjudications` (`round`, `finding_id`, `finding`,
`decision` `accept`, `reject` or `missing`, `reason`), `findings` (with `repro` and its
`classification`: `confirmed`, `fails_on_clean_build`, `reproduced`, `not_reproduced`,
`repro_error` or `missing`), `not_covered` (`area`, `class`, `detail`), `warnings`,
`usage` (with `complete` and `retries`), `network` (event, connection and route request
counts), `keep` and `error`.

A Session that a run created carries `loadout`:
`{run_id, loadout: {id, version, kind, digest, builtin}, network, workload}`. Every other
Session has `"loadout": null`, and its behavior is unchanged.

`GET /api/session-teams` returns config-owned records of this shape:

```json
[
  {
    "id": "feature-team",
    "name": "Feature team",
    "agents": ["planner", "coder", "reviewer"],
    "entry_point": "planner"
  }
]
```

The `workflow_id` stored by a Lattice Session must be an `id` from this response.
This inventory is deliberately independent of the mutable Automation records
returned by `/api/workflows`.

Workspace paths and Session `working_dir` values are canonical absolute paths.
Every Session response carries its durable `workspace_id`; `working_dir` remains
for execution and compatibility clients.

`environment.state` is `unprepared`, `awaiting_approval`, `preparing`, `ready`,
or `failed`. A setup command is executable only when the durable Session record
binds `setup_approved:true` to that exact text. A reviewed API request can grant
that approval; the operator's visible devcontainer default described below can
grant it only while the Session remains unreviewed. Clearing the command with
`setup_reviewed:true` is an explicit no-setup decision. Expected
runtime/setup failures return the updated Session in `failed` state so clients
can render retained evidence; malformed consent is `400`, and an active turn or
Attempt ownership conflict is `409`. File, task, Git, Preview, turn, and Ways
execution fail closed until the environment is Ready.

Live-checkout routes return `404` for a missing Session and `409` for every
existing non-Ready environment. This applies to Session file tree/read/write,
tasks and terminal attach, Git, Preview, HTTP execute, and Ways routes that
start work or inspect a live checkout. Durable History and attachments,
environment review/rebuild, completed Attempt results and cost, and the exact
Keep/Discard recovery actions remain available so a failed Session can still be
understood or resolved.

`GET /api/fs/project?path=…` includes runtime capability metadata. Under E2B,
`supports_session_image` is false and `template` names the daemon-configured
runtime; create or reconfigure rejects an explicit/devcontainer OCI image
before provisioning. `auto_approve_devcontainer_setup` exposes the operator
default for the exact devcontainer command. A browser/API request with
`setup_reviewed:true` remains authoritative, including an unchecked veto;
lockfile-detected commands are never covered by that policy.

Session `mode` is tagged JSON such as
`{"kind":"single_agent","agent_id":"coder"}` or
`{"kind":"lattice","workflow_id":"feature-team"}` or
`{"kind":"custom","agents":["planner","coder","reviewer"]}`. In compatibility
(`legacy_v1`) execution, Lattice mode resolves its stored team ID and Custom mode
resolves its stored Agent IDs against the current daemon configuration when each turn
starts. A single-Agent Session, a one-Agent team, a team whose entry point is a
Coordinator, or a request targeted to one Agent runs directly. A turn that would run
two or more Agents is refused before it starts; the error tells the operator to stop
Axocoatl, make a cold backup, and run `axocoatl session upgrade --confirm`.

### Session History versions

`/turns`, `/turns/{turn_id}`, and `/messages` take an optional `history_version`
query parameter:

- `history_version=1` returns the legacy 1.0 shape: turn records with `id`,
  `user_input`, `final_output`, `status`, and their execution events from `/turns`,
  and `role`/`content` messages from `/messages`. A Session whose History holds
  native execution refuses it with `400`, because legacy rows cannot represent that
  work.
- `history_version=2` returns versioned entries. Each names its source:
  `{"history_version": "legacy_v1", "turn": {…}}` for a turn recorded by the
  compatibility path, and `{"history_version": "execution_v2", "turn": {…}}` for a
  native turn. `/messages` entries carry `content` in place of `turn`.
- Without the parameter, a Session whose History holds native execution answers as
  `history_version=2`, and every other Session answers exactly as `history_version=1`.
  Read each entry's `history_version` rather than assuming one shape.

```bash
# curl reads the header from stdin, so the token stays out of the process list.
# DATA_ROOT is the daemon's data root, which holds local-api-token.
printf 'Authorization: Bearer %s\n' "$(cat "$DATA_ROOT/local-api-token")" |
  curl -s -H @- "http://127.0.0.1:8080/api/sessions/$SESSION/turns?history_version=2"
```

```json
[
  {
    "history_version": "execution_v2",
    "turn": {
      "owner": { "workspace_id": "…", "session_id": "…" },
      "turn_id": "turn-3f0c…",
      "revision": 14,
      "state": "needs_attention",
      "superseded": false,
      "epochs": [],
      "legacy_predecessor": null,
      "request": {
        "status": "available",
        "reference": "…",
        "content": { "display_input": "Fix the failing test", "…": "…" }
      },
      "activations": []
    }
  }

```

A native turn's `state` is `running`, `needs_attention`, `completed`, `cancelled`, or
`finished`. Evidence such as `request` and each activation's output carries a
`status` of `available`, `missing`, or `not_recorded`; only `available` has
`content`. The `control-plane` endpoint below is the per-turn detail view.

### A new request while a turn needs attention

A native Session runs one turn at a time. While its current turn needs attention,
a new request (`POST /api/sessions/{id}/execute` or the WebSocket `session`
command) is refused with `409` or `session-request-rejected`, and nothing starts or
closes. The error names the turn and the two ways out, both through
`POST /api/sessions/{id}/turns/{turn_id}/control-commands`:

- Continue that turn with the message: action `revise`, the exact activation of an
  Agent with an accepted answer, and the message as `instruction`. `continue`
  restarts stopped work without a message.
- Finish it as it is, then send the request again as a new turn: action `finish`
  with a confirmed `partial_finish` built from `turn_controls.partial_finish` in the
  turn's `control-plane`. Only the accepted final answers it selects carry into the
  next turn's conversation; an activation that failed or was interrupted has no
  accepted answer, so its work does not carry forward.

The app offers the same two choices when a message is sent while the turn needs
attention.

### Session network record

`GET /api/sessions/{id}/network` returns the Session's network mode and the events
in its network record. Reading never creates a record: a Session with no network
activity returns an empty list.

```json
{
  "session_id": "ses-…",
  "mode": "bridge",
  "sidecar": null,
  "policies": [],
  "private_destinations": [],
  "record": {"events": 3, "bytes": 412, "gaps": 0},
  "events": [
    {"v": 1, "seq": 1, "ts_ms": 1790000000000, "event": {"kind": "sidecar", "state": "ready", "generation": 1}}
  ],
  "next_after": 1,
  "warnings": ["Axocoatl's config file is inside this Workspace; Agents can read it. Keep secrets in environment variables."],
  "proposals": []
}
```

`mode` is `sandbox.network`. Pass `next_after` back as `after` to read on. Each
event has a `kind`: `policy`, `sidecar`, `bind`, `unbind`, `open`, `close`,
`request`, `response`, `web_request`, `web`, `browser`, `proposal` or `limit`. An `open` event names the destination `host` and `port`, its
`conn_kind` (`connect` for a tunnel or `http`), the `decision` (`allow` or `deny`)
with its `reason` and `status`, the `rule` that decided (`route#0` for an
[egress route](/configure/credentials/)), the addresses used, and the tool call (`binding`)
whose credential it presented. Credentials appear only as 16-hex tags. In a Session
container with [workload users](/configure/sandboxes/#workload-users) under
`network: egress`, an `open` event also has `peer`: the program that opened the
connection as the container's first process found it, with `pid`, `uid`, `gid`, `exe`
(its path), `exe_sha256` (of the file's contents), `ancestors` (the paths of up to 8
parent programs, nearest first) and, for what it could not find, `error`
(`no_access`, `not_found`, `timeout`, `foreign_namespace` for a program run from a
mount namespace of its own, whose path is left out, or `unsupported`). A `close`
event adds the bytes sent and received and the duration, and for a route's
connection the reason the daemon ended it, if it was not an ordinary close. On a
route, each HTTP request is a `request` event written before the request is sent
(`conn`, `seq_in_conn`, `method`, `path` without its query, `host`, the `rule` that
allowed it, `decision`, `reason`, and the `credential`'s name, never its value), and
a `response` event says how an allowed one ended (`status`, `up`, `down`, `ms`,
`outcome`, and `cookies_dropped` when a credentialed route removed `Set-Cookie` or
`Set-Cookie2` fields). `record` counts the events kept and the bytes of their lines;
`gaps` counts places where a sequence number was skipped. The record keeps every
event for the Session's life, so the `max_events` and `full` fields of 1.2.0 are
gone.
An `open` or `close` event's `conn` is `g<generation>:<id>`; generations continue
across proxy restarts and runtime starts, so `conn` is unique in one record. A
`limit` event with `what: "unrecorded_refusals"` counts refusals of connections
without a valid credential that were not recorded one by one. `warnings` is present
when the person should know something about the Session, such as Axocoatl's config
file being inside its Workspace.
Under `network: egress`, `sidecar` reports the egress proxy of the Session's running
runtime (`state` is `starting`, `ready`, `restarting`, `failed` or `stopped`, with its
`generation` and the number of `restarts`), and `policies` lists each scope's compiled
policy: `session` (your `sandbox.egress` list plus this Session's allows),
`provisioning` (the Alpine, Debian and Ubuntu mirrors) and, when `browser:` is
configured, `browser` (`browser.allow` plus this Session's browser allows), which only
the browser's credentials are checked against. Each rule has an `id`, its
`text` and its `source` (`preset`, `config`, `session`, or `route` for an entry of
`sandbox.egress.routes` in the `session` policy). A `policy` event's `source` is `config` (the configuration
the decision point opened with), `config_reload` (a
[reload](#reload-the-network-allowlists)), `session_allow` or `session_revoke`.
`proposals` lists the hosts Agents [asked for](#hosts-agents-ask-for), pending ones
first. Under `bridge` and `none`, `sidecar` and `policies` describe
only the browser's own egress sidecar and its `browser` policy, once a browser call
with declared hosts (`browser.allow`) has started them. Otherwise, and while an
`egress` Session has no running runtime, they are empty.

A `web_request` event is written before a `web_search` or `web_fetch` call with
valid arguments sends anything: the `tool`, its `invocation_id`, `activation_id`
and `agent`, and either the `url` a fetch requests or a search's `query_sha256` and
`query_bytes`. If it cannot be written, nothing is sent. A `web` event with the same
`invocation_id` follows when the call finishes; a call with invalid arguments has
only the `web` event.

A `web` event records how one call ended: the `tool`, its `invocation_id`,
`activation_id` and `agent`, the `decision` and `reason`, the `source_ids` it
returned, `retrieved_at_ms` and `ms`. A search adds `query_sha256` and
`query_bytes` (not the query text), `results`, `unresponsive_engines` and `sources`
(each `{id, url}`, URLs cut to 512 bytes and then marked `url_truncated`). A fetch
adds `url`, `final_url`, `redirects`, `status`, `bytes`, `content_sha256` and
`text_sha256`. Each fetch URL, in `web_request` too, is cut to 1,024 bytes;
`url_truncated`, `final_url_truncated` and `redirects_truncated` are present and
`true` only when one was cut. The full URL is in the tool call's recorded
arguments.

```json
{"v": 1, "seq": 6, "ts_ms": 1790000000000, "event": {"kind": "web_request",
  "tool": "web_fetch", "invocation_id": "tool-…", "activation_id": "…", "agent": "…",
  "url": "https://www.rust-lang.org/"}}
{"v": 1, "seq": 7, "ts_ms": 1790000000412, "event": {"kind": "web", "tool": "web_fetch",
  "invocation_id": "tool-…", "activation_id": "…", "agent": "…", "decision": "allow",
  "url": "https://www.rust-lang.org/", "final_url": "https://www.rust-lang.org/",
  "status": 200, "redirects": [], "unresponsive_engines": [], "bytes": 18234,
  "content_sha256": "…", "text_sha256": "…", "source_ids": ["S1a2b3c4d"],
  "retrieved_at_ms": 1790000000412, "ms": 412}}
```

A `browser` event is one `browser` or `browser_check` call: `tool`, the
`invocation_id`, `activation_id` and `agent`, `ok`, the `url`, `final_url` and
`status` (or the `test_path` and `check_status`), the number of `blocked` requests,
the egress credential's `token` tag when the call used declared hosts, `ms`, and a
`screenshot` `{sha256, media_type, bytes}` when one was kept (or `screenshot_dropped`
with the reason). A call that failed before it produced a result has `ok: false` and
the reason in `error`. `GET /api/sessions/{id}/network/screenshots/{sha256}` returns
the image. Screenshots are for people; no model sees them.

#### Allow or revoke a host for one Session

Under `network: egress`, a person can allow a host that the Session's list refuses,
for this Session only, and take that back:

```json
POST /api/sessions/{id}/network/allow
{"command_id": "c-41f2", "scope": "session", "host": "api.example.com", "ports": [443]}

{"revision": 4, "digest": "9f47a9dc…"}
```

- `scope` is `session`, or `browser` for the browser's declared hosts when
  `browser:` is configured. The panel sends the scope of the refused connection.
- `host` is one exact host name. A wildcard, an IP address or a private range is
  refused; put those under `sandbox.egress` instead. `ports` defaults to `[443]`.
- The change is written to the Session's network record as a `policy` event with
  `source` `session_allow` or `session_revoke`, the `change` (including the
  `command_id`) and `actor` `human`, then applies to new connections at once, also
  while the Session's runtime is stopped. The answer is the scope's new policy
  `revision` and `digest`.
- Revoke removes every allow this Session added for the host and closes the open
  connections they admitted. A host from your configuration cannot be revoked here.
- Each `command_id` (1 to 128 characters) is used once. A resend, also after a
  daemon restart, gets `409`. A validation failure gets `400` with the reason, a
  closed Session `409`, and an unknown Session `404`.

Agents have no tool or route that reaches these changes. An Agent can only ask, as
below.

#### Hosts Agents ask for

Under `network: egress`, a writer Agent whose `tools` list `request_network_access`
can ask for one exact host, with its ports (default `[443]`) and a reason. The request
is written to the record as a `proposal` event with `state: pending`, its `id`
(`prop_` and 16 hex digits), `host`, `ports`, `reason`, and the `agent`,
`invocation_id` and `activation_id` of the call, and the tool call waits for a person
(up to `wait_secs`, default 120, at most 600). An identical pending request joins the
first one. A Session keeps at most 16 pending requests. `GET /api/sessions/{id}/network`
lists them under `proposals`:

```json
{"id": "prop_6f1c0b3e9a2d4c71", "state": "pending", "host": "api.example.com",
 "ports": [443], "reason": "The build downloads its schema from here.",
 "agent": "writer", "invocation_id": "tool-…", "activation_id": "…"}
```

```json
POST /api/sessions/{id}/network/proposals/prop_6f1c0b3e9a2d4c71/approve
{"command_id": "c-7a10"}

{"proposal_id": "prop_6f1c0b3e9a2d4c71", "state": "approved", "revision": 5, "digest": "…"}
```

- Approve is the per-Session allow above, in the `session` scope: a `policy` event
  with `source` `session_allow`, `actor` `human` and `change.proposal_id`, then a
  `proposal` event with `state: approved` and the `revision`. The waiting tool call
  returns `approved`, and new connections to the host are allowed at once. Revoke it
  like any other Session allow.
- Reject records a `proposal` event with `state: rejected`; nothing is allowed, and
  the tool call returns `rejected`.
- A call that nobody answers in time returns `pending`; the request stays in the list
  and a later call for the same host and ports waits on it again. A request still
  pending when the daemon stops is listed again, and can be decided, once the
  Session's runtime runs after the restart.
- A decided proposal gets `409`, as does a reused `command_id`. An unknown Session or
  proposal gets `404`, a malformed proposal id or a daemon that does not run
  `network: egress` `400`.

Nothing approves a request by itself, and no Agent can reach these routes.

### Reload the network allowlists

`POST /api/network/reload` (and [`axocoatl network reload`](/reference/cli/#network-policy))
reads the configuration file the daemon was started with again and validates all of
it. Only six settings apply while the daemon runs: `sandbox.egress.allow`,
`sandbox.egress.private_destinations`, `sandbox.egress.routes`, `credentials`,
`browser.allow` and `browser.private_destinations`.

```json
POST /api/network/reload

{"applied": ["sandbox.egress.allow"],
 "unchanged": ["sandbox.egress.private_destinations", "sandbox.egress.routes", "credentials",
               "browser.allow", "browser.private_destinations"],
 "restart_required": ["sandbox.egress.max_connections"],
 "revisions": [{"session_id": "ses-…", "scope": "session", "revision": 6, "digest": "…", "closed": 1}],
 "changes": [{"key": "sandbox.egress.allow",
              "added": ["registry.npmjs.org:443 (preset npm)"],
              "removed": ["old.example.com:443 (config)"]}]}
```

- `changes` names, for each list that changed, every entry it gained and lost
  compared with the lists in force before: allow entries as the rules they compile
  to (a preset as each of its hosts, with its ports), private ranges as ranges, routes
  as their configuration in JSON and credentials as their name and where they are
  read (`github: env GITHUB_TOKEN`; there is no value to show). Read it to see
  exactly what a reload widens.

- New Sessions use the new lists. Each running Session whose policy changed records
  it as a `policy` event with `source` `config_reload` and `actor` `human`, and uses
  it for new connections at once. Its own per-Session allows stay.
- Open connections admitted by a rule the new list no longer has, unchanged, are
  closed (`closed` counts them per Session and scope). A rule whose position in the
  list moved gets a new id, so its connections are closed too and reconnect.
  Removing a private range closes that scope's open connections. A route that
  changed in any way (its rules, credential, `for` or other settings) closes the
  connections it was serving, and a new route closes the plain tunnels already open
  to its host on its ports.
- A Session whose runtime started without routes has no trust files for the
  Session's authority, so its clients refuse the certificates of routes a reload
  adds until the runtime starts again; see
  [What the client sees](/configure/credentials/#what-the-client-sees).
- `restart_required` names every other setting that differs from the configuration
  the daemon started with, such as `sandbox.network`,
  `sandbox.egress.sidecar_network`, `sandbox.egress.max_connections`, adding or
  removing the `browser` block, Agents or providers. Only key names are reported,
  never values. These are not applied.
- `failed` lists running Sessions whose new policy could not be recorded, with the
  `scope` that failed (none when the Session's lists did not compile at all). That
  scope keeps its old policy, its old lists and the connections they admitted. The
  answer is then `503` with the same report and an `error`; every other Session uses
  the new lists. The next reload, even of an unchanged file, applies the lists to
  each Session that has not taken them yet, so send it again.
- An invalid file, or a daemon not started from a file, gets `400` with the reason,
  and nothing changes.
- So does a configuration file inside the Workspace of any of the daemon's Sessions:
  that Session's Agents can edit it, so it is not applied to every running Session
  while the daemon runs. Check the file and restart the daemon, or start the daemon
  from a file outside every Workspace.

### Turn control plane

The `control-plane` endpoint returns `schema_version: 1`, the source
`history_version`, exact Session and turn identities, nodes, activation histories,
and causal evidence. Evidence values carry an explicit `status`: `available`,
`not_recorded`, `unknown`, `missing`, `unavailable`, or `truncated`. A truncated
preview includes its original byte length. Clients must not turn unavailable usage
into zero or missing output into a successful empty answer.

An activation whose tool calls opened or were refused connections through an egress
proxy (under `network: egress`, or through the browser's declared hosts), or called
`web_search` or `web_fetch`, has one evidence item of kind `network`. Its `summary`
names each destination, such as `registry.npmjs.org:443 allowed ×3 (1.2 MB in);
evil.test:443 refused (not_allowed)`, with ` by node, curl` after a destination when
the record names the programs behind its connections, and counts web calls, followed by the
requests made on routes; its `details` holds up to 200 of the matching `open`, `close`, `request`, `response` and `web` lines from
the [network record](#session-network-record), with
`truncated` set when there were more. Events are joined to the activation through the
tool call whose credential they presented. Setup, terminal and unattributed events
appear only in the network record.

An activation that used `web_search` or `web_fetch` has one evidence item of kind
`sources`. Its `details.sources` lists each source id the activation received with
`url`, `final_url`, `searched`, `fetched`, `status`, `retrieved_at_ms`,
`content_sha256`, `text_sha256`, the `invocations` that returned it and `cited`,
which is true when the activation's final output cites the id in square brackets
(`[S1a2b3c4d]` or `[S1a2b3c4d ¶3]`). `details.unknown_citations` lists ids the
output cites that no web tool returned to that activation.

In a native turn, an edge of kind `delegated_by` runs from a lead's node to a helper
node the lead admitted through `delegate`; its `summary` names the helper template and
its `evidence` is the helper's admission grant. It is not a dependency: the lead
waits for the helper inside its own activation, and the helper does not gate it.

Compatibility Session history is identified as `legacy_v1`. Its activation references
retain their recorded generation when available; they do not invent execution
epochs or current Agent definitions. Per-activation Stop, Retry, Guide, and Revise
capabilities are disabled for these historical identities. Reading this endpoint
does not mutate the turn or start execution.

Native `execution_v2` capability entries distinguish an enabled live action from
an optional `requires_revalidation: true` request after restart. A recovery request
keeps `enabled: false`: the read did not attach a runtime or establish authority.
The existing control-command POST reconnects the Session and validates its exact
revision, epoch, repository, grant, and remaining budget before applying it.
Recovered Revise, Continue, and Finish retain their original identities and may
be refused. Failed or interrupted work in a paused epoch is selected through
Continue. Closed turns, superseded conversation history, and isolated Ways do
not offer these cooperative recovery requests.

Native turn history retains `repository_reattachments` with the exact original
and reacquired repository descriptors; these records document host reattachment
without changing original activation inputs or grants, authorizing work, or replaying it.

Captured inline context has its own `reference_id` in the receiving turn. For a
`coordination_reference`, `metadata.reference_id` identifies the original evidence
alongside its exact source Session, turn, epoch, activation, and generation; for a
`ways_decision`, `metadata.decision_id` identifies the retained decision.

A native lead's `delegate` call whose raw return was lost retains a labeled
reconciliation result read from the command that admitted the helper and the
helper's canonical outcome: its accepted answer, or the error for a refused, failed,
or stopped helper. Recovery does not run the helper again or repeat a provider
request. An admitting command left requested or accepted by a crash admitted no
helper; the same reopen records that, and the lead may call `delegate` again.
Ordinary shell/tool effects are not automatically replayed.

For native cooperative turns, `turn_controls.partial_finish` supplies the exact
review for a human partial finish. The existing control-command POST uses
`action: "finish"` and an optional `partial_finish` object containing
`selected_activations`, `stop_activations`, `missing_conditions`, `unrun_nodes`, and
`confirmed: true`. Selected results must be current accepted sinks; the other lists
must match the reviewed state. Stale reviews are refused. Omitting `partial_finish`
retains normal Finish semantics. Partial finish records missing work explicitly and
waits for safe settlement; it does not grant an Agent permission to bypass checks.

A native turn whose team has required checks also carries `required_checks` in its
control plane: for each check, in order, its `argv` and the `state` of its latest run
(`pending`, `passed`, `failed`, `timed_out`, `outcome_unknown`, `unavailable` and so on),
with `exit_code`, `run_id`, `process_status` and bounded `stdout` and `stderr` previews
when recorded. Timeout, interruption, launch failure, no dispatch and a missing outcome
stay distinct, and a successful exit alone is not a readiness verdict. A check whose
record cannot be read is `unavailable` with a `reason`; it does not hide the rest of the
turn. `required_check_readiness` carries that verdict: `state` (`passed`, `failed`,
`not_run`, `skipped` or `unavailable`), a `reason` in words, and the `candidate_sha256`
tree it judged. Its conditions are named `required-check:0` (the capture before),
`required-check:1` to `required-check:n` (the checks), `required-check:n+1` (the capture
after) and `required-check:ready`. Selecting any of them in a Continue request, or
restarting any Agent, reruns both captures, every check and readiness. A check-only
Continue that the paying Agent's budget cannot cover is refused with the reason.

A native turn whose team has a required review carries `required_review` in its control
plane: the `reviewer` template, `state` (`not_run`, `running`, `approved`, `changes`,
`failed`, `skipped` or `unavailable`), a `reason` in words, the `verdict` (`approve`,
`changes` or `unreadable`), bounded `findings`, the `round` and `max_rounds`, `current`
(whether the verdict is about the current result) and the `candidate_sha256` tree the
reviewer was shown. The reviewer is the graph node `required-review` and its verdict the
condition `required-review:verdict`; selecting that condition in a Continue request runs
the reviewer again, and rerun checks or restarted work run it again too.

The directory must already exist when registering a new Workspace. The server has
no configured folder allowlist.

Rewind is blocked during an active turn or unresolved Attempt set and currently
requires an autonomous single-Agent Session. It changes the logical conversation head; it
does not restore files or reverse effects.

## Session files, tasks, Terminal, and Preview

| Method | Path | Request / behavior |
| --- | --- | --- |
| GET | `/api/sessions/{id}/tree?path=…` | Lazy one-level directory listing within Session root |
| GET | `/api/sessions/{id}/file?path=…` | Read one file, capped at 512 KiB |
| POST | `/api/sessions/{id}/file?path=…` | Atomically overwrite existing resolved path with `{content}` |
| GET | `/api/sessions/{id}/tasks` | Background task and terminal state |
| POST | `/api/sessions/{id}/tasks` | `{command, interactive?, rows?, cols?}`; uses or reconstructs the already-Ready sandbox and never prepares an unreviewed environment implicitly |
| GET (WS) | `/api/sessions/{id}/terminals/{tid}/ws` | Raw PTY output as binary; input binary/text; resize JSON |
| Any HTTP method | `/api/sessions/{id}/proxy/{port}` | Legacy response-sandboxed Preview proxy root |
| Any HTTP method | `/api/sessions/{id}/proxy/{port}/{*tail}` | Legacy response-sandboxed Preview proxy path |

File resolution rejects paths outside the canonical Session root. Tree, read,
and write execute through the Ready sandbox: local Podman operates on the
read-write Workspace bind, while E2B operates on its remote clone. There is no
host-filesystem fallback for a failed remote runtime or a container-local
dependency volume. The write endpoint does not create missing parent
directories. Terminal resize is `{"kind":"resize","rows":30,"cols":100}`.

The workbench opens the virtual Preview Host, not the legacy path. The Host
boundary validates the exact Session and logical port, resolves that pair to
the sandbox's dynamically assigned loopback transport, and forwards normal app
HTTP methods, query strings, request bodies, cookies, module/root assets, and
WebSocket upgrades. HTML receives the source-and-origin-pinned picker bridge;
non-HTML bodies stream without whole-response buffering. The upstream app sees
the validated virtual authority while the TCP connection remains loopback.
Sibling Sessions can therefore use the same logical port without sharing a
host port, browser origin, host-only cookies, or control-plane access. Rejection
of a parent-domain cookie such as `Domain=localhost` is browser policy; the
current Chromium journey verifies it, while the proxy forwards application
`Set-Cookie` headers unchanged. Both proxies remove `axocoatl-token-*` cookies
from forwarded requests and drop upstream `Set-Cookie` headers that would set
one. The legacy `/api/sessions/{id}/proxy/{port}` path sits behind API
authentication and never forwards Axocoatl credential headers. Its sandboxed
page has an opaque origin, so its subresource requests carry no SameSite=Strict
cookie; use it with a header credential.

## Attempts: Explore several ways

One Session can own one unresolved set. Except for `results`, set-scoped calls
use `attempt_set_id`; a stale ID returns `409` rather than touching a newer set.

| Method | Path | Request / behavior |
| --- | --- | --- |
| POST | `/api/sessions/{id}/variants` | `{input, task?, n?, lanes?}`; starts isolated local-Podman Attempts |
| GET | `/api/sessions/{id}/variants/status?attempt_set_id=…` | Changed-file status per Attempt |
| GET | `/api/sessions/{id}/variants/results` | Durable current set, outputs, verdicts, usage, and Judgment |
| GET | `/api/sessions/{id}/variants/trajectories?attempt_set_id=…&baseline=0` | Aligned Route comparison |
| GET | `/api/sessions/{id}/variants/diff?attempt_set_id=…&index=0&path=…` | One file before/after for one Attempt |
| POST | `/api/sessions/{id}/variants/verify` | `{attempt_set_id, check}`; run Checks after all Ways are terminal |
| POST | `/api/sessions/{id}/variants/judge` | `{attempt_set_id, agent_id}`; rank passing non-empty survivors with that configured Agent |
| GET | `/api/variants/probe?provider=…&models=a,b` | Preflight comma-separated models for structured tool calls; each result includes `control_usage` |
| POST | `/api/sessions/{id}/variants/plan` | `{task, agent_id}`; return plan, rendered instruction, and `control_usage` |
| GET | `/api/sessions/{id}/variants/cost?attempt_set_id=…&baseline=…&baseline_provider=…` | Actual and counterfactual price report with known flags |
| POST | `/api/sessions/{id}/variants/adopt` | `{attempt_set_id, index}`; resumable Keep without commit |
| POST | `/api/sessions/{id}/variants/discard` | `{attempt_set_id}`; cancel/join and remove without keeping |

Attempts require an autonomous single-Agent Session, Git, and local Podman. A keepable
candidate must be completed, non-empty, and passing. Keep phases are durable
and retrying the same index resumes; discard is rejected after apply begins.

Remote missing prices remain unknown. `total_usd` is complete only when its
known flag says so. Plan, model-check, and Judge calls are outside Attempt execution totals and
use `control_usage`. Plan/Judge error responses also include that field so a failed or invalid
Agent response does not hide a paid call; `token_usage_known: false` marks a known subtotal.
