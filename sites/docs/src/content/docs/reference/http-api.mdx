The daemon listens on `http://127.0.0.1:8080` by default. JSON errors generally
use `{ "error": "message" }`. The router in `axocoatl-server/src/lib.rs` and
handler Serde types remain authoritative; there is not yet a generated OpenAPI
document.

The docs content check compares every literal router path with this page and
the [WebSocket reference](/reference/websocket/).

## Authentication, CORS, and rate limits

Workbench and control-router routes other than `/health`, `/health/ready`, and
`/health/live` pass through configured authentication. The dedicated Preview
virtual Host is intercepted before that router and is constrained separately by
its exact Session/port Host and browser-origin boundary. Send one of:

```http
x-api-key: <key>
Authorization: Bearer <token>
```

An empty `server.cors_origins` allows same-origin workbench requests only.
Browser writes and WebSockets with an opaque `Origin: null` are always rejected;
other cross-origin browser writes require an explicitly allowed origin. In the
default unauthenticated loopback mode, an unknown Host is rejected independently
to prevent DNS rebinding. Origin-less CLI clients remain supported. Cross-origin
preflight for the control router advertises HEAD, GET, POST, PUT, PATCH, and
DELETE. Control-router rate limiting is disabled by default and applies per
client IP when enabled; Preview traffic stays outside that middleware.

Preview applications use a separate virtual origin shaped like
`<session>-p<port>.localhost:<listener-port>`. That Host is intercepted
before the workbench router, so no `/api`, `/ws`, app-shell, or static-asset
path can fall through to the control origin. Each Session and logical port has
its own browser storage/cookie origin. Modern browsers can block ordinary app
cookies while that origin is embedded; the workbench's **Open full preview**
action opens the same virtual URL top-level with `noopener`, where host-only
cookies work without becoming shared sibling cookies. A browser GET or HEAD
for the exact `/` workbench document on a loopback IP literal redirects to
`localhost` on the same listener and preserves the query. API, health, and
asset URLs do not redirect.

## Native Session controls and standing work

These routes use the same authenticated Session owner as ordinary Send. A preview
is read-only; Apply binds the reviewed request and exact revisions. Retrying an
uncertain reply must reuse that request unchanged. Stale revisions are conflicts,
not permission to choose another activation or team.

| Method | Path | Request / behavior |
| --- | --- | --- |
| GET | `/api/sessions/{id}/team` | Current team revision, selected templates, explicit limits, and expiry. `required_checks` lists the applied team's checks; `suggested_check` is the Session's detected check command as an argument array, offered only and never run unless an Apply includes it |
| POST | `/api/sessions/{id}/team/preview` | Typed whole-team edit; resolves and reviews future-turn definitions and authority. Leaving it out keeps the scope of the template or current definition the slot starts from, so omitting it never widens what the Agent may change; the app always sends it. | POST | `/api/sessions/{id}/turns/{turn_id}/graph-edits/preview` | Review AddAgent or ReplaceFutureAgent against the exact graph revision. | POST | `/api/sessions/{id}/turns/{turn_id}/graph-edits/apply` | Apply the original reviewed graph edit and digest |

| POST | `/api/sessions/{id}/work/receipts/{receipt}/dismiss` | `{reason}`; retain the dismissal against the exact receipt |
| POST | `/api/sessions/{id}/work/receipts/{receipt}/settle-at-ceiling` | A person accepts charging closed work's provider calls with unknown usage at their full admitted reservation, releasing the rest of the shared budget. Refused while the turn is open, a tool effect or check outcome is unknown, usage is already measured, or the total would exceed the grant's reviewed limits; repeating it after it succeeded returns the settled view |
| GET | `/api/sessions/{id}/work/signals` | Each signal field: per-route intensity, threshold and state; every deposit with per-route exclusion reasons; dispatches with receipt and turn. Uses the last observation; never starts a runtime |
| POST | `/api/sessions/{id}/work/signals/{binding}/sense` | Observe the running runtime's watched sources, record new deposits, and dispatch crossed routes |
| POST | `/api/sessions/{id}/work/signals/{binding}/flags` | `{paths, summary}`; a person's deposit of 1.0 on up to 32 repository paths |
| POST | `/api/sessions/{id}/work/signals/{binding}/deposits/{deposit}/withdraw` | `{reason}`; the deposit stays retained and stops counting |
| POST | `/api/sessions/{id}/work/signals/{binding}/routes/{slot}/dispatch` | Send one route its current deposits below threshold, recorded as a manual dispatch |
| GET | `/api/sessions/{id}/ways-history` | Retention limits, retained decision records, and deletion tombstones |
| POST | `/api/sessions/{id}/ways-history/configuration` | `{limits: {version, field_bytes, record_bytes, aggregate_bytes, records, candidates, items_per_field}}`; every numerical limit is explicit |
| GET | `/api/sessions/{id}/ways-history/{decision}` | Export the retained record and protected patch bodies |
| DELETE | `/api/sessions/{id}/ways-history/{decision}` | Explicit deletion after runtime cleanup; retains a tombstone |

A work source is `{kind: "manual"}`, `{kind: "signed_webhook", configuration_name}`,
`{kind: "session_completion", session_id}`, or `{kind: "signal_field", routes:
[{slot_id, watches, threshold_milli, owns?}], half_life_ms, max_dispatches,
max_episode_tokens?}`. `max_dispatches` and the optional `max_episode_tokens` apply per
episode: the work since the field was last quiet. A signal
route names one applied team slot, repository path patterns it watches (`lib/`,
`*.test.js`, `src/**/*.rs`), and a threshold in thousandths of one finding's deposit.
`owns` lists the patterns it may change during signal work; omitted means its watched
patterns and `[]` makes it read-only;
`half_life_ms` may be `null` to disable evaporation. Session completion sources must share
the Workspace; the host resolves causation from canonical source history. Manual and
webhook events carry `{event_id, correlation_id, subject: {kind, reference_id, version},
evidence_refs, caused_by_turn_id, expected_binding_revision?}`. A payload cannot
establish verified internal causation. `required_checks` is an array of explicit
argument arrays, such as `[["npm", "test"]]`. Events and checks share the approved
team's grant allowance; an event does not refill it.

Each readiness check retains its exact `run_id`, typed `process_status`, effect
disposition, and bounded output when recorded. Timeout, interruption, launch failure,
no dispatch, and missing outcomes remain distinct. A stale candidate assessment does
not change the recorded process result; an explicitly skipped check has no invented
process result. A successful process exit alone is not a readiness verdict.

Signed bodies are limited to 32 KiB. Supply `x-axocoatl-signature: sha256=<hex>`
containing the HMAC-SHA256 of the exact body bytes using the named configured webhook
secret. Do not reserialize a body after signing it.

`GET /api/session-teams` returns config-owned records of this shape:

```json
[
  {
    "id": "feature-team",
    "name": "Feature team",
    "agents": ["planner", "coder", "reviewer"],
    "entry_point": "planner"
  }
]
```

The `workflow_id` stored by a Lattice Session must be an `id` from this response.
This inventory is deliberately independent of the mutable Automation records
returned by `/api/workflows`.

Workspace paths and Session `working_dir` values are canonical absolute paths.
Every Session response carries its durable `workspace_id`; `working_dir` remains
for execution and compatibility clients.

`environment.state` is `unprepared`, `awaiting_approval`, `preparing`, `ready`,
or `failed`. A setup command is executable only when the durable Session record
binds `setup_approved:true` to that exact text. A reviewed API request can grant
that approval; the operator's visible devcontainer default described below can
grant it only while the Session remains unreviewed. Clearing the command with
`setup_reviewed:true` is an explicit no-setup decision. Expected
runtime/setup failures return the updated Session in `failed` state so clients
can render retained evidence; malformed consent is `400`, and an active turn or
Attempt ownership conflict is `409`. File, task, Git, Preview, turn, and Ways
execution fail closed until the environment is Ready.

Live-checkout routes return `404` for a missing Session and `409` for every
existing non-Ready environment. This applies to Session file tree/read/write,
tasks and terminal attach, Git, Preview, HTTP execute, and Ways routes that
start work or inspect a live checkout. Durable History and attachments,
environment review/rebuild, completed Attempt results and cost, and the exact
Keep/Discard recovery actions remain available so a failed Session can still be
understood or resolved.

`GET /api/fs/project?path=…` includes runtime capability metadata. Under E2B,
`supports_session_image` is false and `template` names the daemon-configured
runtime; create or reconfigure rejects an explicit/devcontainer OCI image
before provisioning. `auto_approve_devcontainer_setup` exposes the operator
default for the exact devcontainer command. A browser/API request with
`setup_reviewed:true` remains authoritative, including an unchecked veto;
lockfile-detected commands are never covered by that policy.

Session `mode` is tagged JSON such as
`{"kind":"single_agent","agent_id":"coder"}` or
`{"kind":"lattice","workflow_id":"feature-team"}` or
`{"kind":"custom","agents":["planner","coder","reviewer"]}`. In compatibility
(`legacy_v1`) execution, an all-team autonomous multi-Agent Lattice or Custom turn appends its immutable graph and causal
coordination transitions to the returned turn's `execution_events`. A one-Agent
team, a coordinator-led team, or a request targeted to one Agent runs directly
and does not fabricate a Coordination map.

For compatibility all-team turns, Lattice mode resolves its stored team ID and Custom mode
resolves its stored Agent IDs against the current daemon configuration. Agent
dependencies are validated before work starts. When the resolved path is a
multi-Agent coordination graph, its first `coordination_planned` event
snapshots the exact Agent names, dependencies, roots, sinks, and activation
bound used for that turn. Changing configuration afterward affects a later
turn, not this retained record.

### Durable coordination records

The `control-plane` endpoint returns `schema_version: 1`, the source
`history_version`, exact Session and turn identities, nodes, activation histories,
and causal evidence. Evidence values carry an explicit `status`: `available`,
`not_recorded`, `unknown`, `missing`, `unavailable`, or `truncated`. A truncated
preview includes its original byte length. Clients must not turn unavailable usage
into zero or missing output into a successful empty answer.

Compatibility Session history is identified as `legacy_v1`. Its activation references
retain their recorded generation when available; they do not invent execution
epochs or current Agent definitions. Per-activation Stop, Retry, Guide, and Revise
capabilities are disabled for these historical identities. Reading this endpoint
does not mutate the turn or start execution.

Native `execution_v2` capability entries distinguish an enabled live action from
an optional `requires_revalidation: true` request after restart. A recovery request
keeps `enabled: false`: the read did not attach a runtime or establish authority.
The existing control-command POST reconnects the Session and validates its exact
revision, epoch, repository, grant, and remaining budget before applying it.
Recovered Revise, Continue, and Finish retain their original identities and may
be refused. Failed or interrupted work in a paused epoch is selected through
Continue. Closed turns, superseded conversation history, and isolated Ways do
not offer these cooperative recovery requests.

Native turn history retains `repository_reattachments` with the exact original
and reacquired repository descriptors; these records document host reattachment
without changing original activation inputs or grants, authorizing work, or replaying it.

Captured inline context has its own `reference_id` in the receiving turn. For a
`coordination_reference`, `metadata.reference_id` identifies the original evidence
alongside its exact source Session, turn, epoch, activation, and generation; for a
`ways_decision`, `metadata.decision_id` identifies the retained decision.

A native `coordination_control` `submit` or `canonical` call whose raw return was
lost can retain a labeled reconciliation result from its exact accepted invocation
binding and command receipt. The receipt's actual state stays explicit: a successful
lookup does not mean the command was Applied or Settled. Recovery does not repeat
the command or provider request. Rejected or mismatched bindings remain unknown;
ordinary shell/tool effects are not automatically replayed.

For native cooperative turns, `turn_controls.partial_finish` supplies the exact
review for a human partial finish. The existing control-command POST uses
`action: "finish"` and an optional `partial_finish` object containing
`selected_activations`, `stop_activations`, `missing_conditions`, `unrun_nodes`, and
`confirmed: true`. Selected results must be current accepted sinks; the other lists
must match the reviewed state. Stale reviews are refused. Omitting `partial_finish`
retains normal Finish semantics. Partial finish records missing work explicitly and
waits for safe settlement; it does not grant an Agent permission to bypass checks.

A native turn whose team has required checks also carries `required_checks` in its
control plane: for each check, in order, its `argv` and the `state` of its latest run
(`pending`, `passed`, `failed`, `timed_out`, `outcome_unknown` and so on), with
`exit_code`, `run_id`, `process_status` and bounded `stdout` and `stderr` previews when
recorded. Its conditions are named `required-check:0` (the capture before),
`required-check:1` to `required-check:n` (the checks), `required-check:n+1` (the capture
after) and `required-check:ready`; selecting one check in a Continue request also reruns
both captures and readiness.

The `execution_events` array is the canonical ordered record. A live
`coordination` WebSocket frame nests the `RecordTurnExecution` body under
`event`; the HTTP turn representation flattens that body beside its durable
identity:

```json
{
  "operation_id": "coordination:turn-id:1:agent-activated",
  "recorded_at": 1788800000000,
  "kind": "coordination_agent_activated",
  "execution_id": "turn-id",
  "metadata": {
    "session_id": "session-id",
    "turn_id": "turn-id",
    "agent_id": "builder",
    "generation": 1,
    "cause_signal_ids": ["coordination-signal:turn-id:planner:g1:completed"],
    "parents": ["planner"]
  }
}
```

The coordination kinds are `coordination_planned`,
`coordination_agent_activated`, `coordination_signal`,
`agent_output_superseded`, `coordination_agent_reactivated`,
`coordination_agent_completed`, `coordination_agent_failed`,
`coordination_agent_blocked`, `coordination_agent_cancelled`,
`coordination_recovery_partial`, and
`coordination_completed`. See the
[WebSocket coordination metadata table](/reference/websocket/#coordination-event-metadata)
for every per-kind field and the live envelope.

Each coordinated entry in `agent_outputs` also carries its generation-aware
identity:

| Field | Meaning |
| --- | --- |
| `operation_id` | Ledger operation that recorded this exact output |
| `activation_generation` | One-based Agent activation represented by this output |
| `disposition` | `completed`, `changes_requested`, `failed`, or `cancelled` |
| `causal_signal_id` | Completion, failure, or feedback signal associated with the output, when one exists |
| `superseded` | Whether a later accepted generation made this output stale |
| `superseded_by_generation` | Replacement generation, when stale |
| `superseded_by_signal_id` | Revision signal that caused the replacement, when stale |

Canonical JSON retains superseded outputs as evidence. Normal conversation,
checkpoint projection, search output matching, and Markdown export omit those
stale Agent outputs so they cannot be mistaken for the current result.

The directory must already exist when registering a new Workspace. The server has
no configured folder allowlist.

Rewind is blocked during an active turn or unresolved Attempt set and currently
requires an autonomous single-Agent Session. It changes the logical conversation head; it
does not restore files or reverse effects.

| GET | `/api/sessions/{id}/tree?path=…` | Lazy one-level directory listing within Session root |
| GET | `/api/sessions/{id}/file?path=…` | Read one file, capped at 512 KiB |
| POST | `/api/sessions/{id}/file?path=…` | Atomically overwrite existing resolved path with `{content}` |
| GET | `/api/sessions/{id}/tasks` | Background task and terminal state |
| POST | `/api/sessions/{id}/tasks` | `{command, interactive?, rows?, cols?}`; uses or reconstructs the already-Ready sandbox and never prepares an unreviewed environment implicitly |
| GET (WS) | `/api/sessions/{id}/terminals/{tid}/ws` | Raw PTY output as binary; input binary/text; resize JSON |
| Any HTTP method | `/api/sessions/{id}/proxy/{port}` | Legacy response-sandboxed Preview proxy root |
| Any HTTP method | `/api/sessions/{id}/proxy/{port}/{*tail}` | Legacy response-sandboxed Preview proxy path |

File resolution rejects paths outside the canonical Session root. Tree, read,
and write execute through the Ready sandbox: local Podman operates on the
read-write Workspace bind, while E2B operates on its remote clone. There is no
host-filesystem fallback for a failed remote runtime or a container-local
dependency volume. The write endpoint does not create missing parent
directories. Terminal resize is `{"kind":"resize","rows":30,"cols":100}`.

The workbench opens the virtual Preview Host, not the legacy path. The Host
boundary validates the exact Session and logical port, resolves that pair to
the sandbox's dynamically assigned loopback transport, and forwards normal app
HTTP methods, query strings, request bodies, cookies, module/root assets, and
WebSocket upgrades. HTML receives the source-and-origin-pinned picker bridge;
non-HTML bodies stream without whole-response buffering. The upstream app sees
the validated virtual authority while the TCP connection remains loopback.
Sibling Sessions can therefore use the same logical port without sharing a
host port, browser origin, host-only cookies, or control-plane access. Rejection
of a parent-domain cookie such as `Domain=localhost` is browser policy; the
current Chromium journey verifies it, while the proxy forwards application
`Set-Cookie` headers unchanged.

## Attempts: Explore several ways

One Session can own one unresolved set. Except for `results`, set-scoped calls
use `attempt_set_id`; a stale ID returns `409` rather than touching a newer set.

| Method | Path | Request / behavior |
| --- | --- | --- |
| POST | `/api/sessions/{id}/variants` | `{input, task?, n?, lanes?}`; starts isolated local-Podman Attempts |
| GET | `/api/sessions/{id}/variants/status?attempt_set_id=…` | Changed-file status per Attempt |
| GET | `/api/sessions/{id}/variants/results` | Durable current set, outputs, verdicts, usage, and Judgment |
| GET | `/api/sessions/{id}/variants/trajectories?attempt_set_id=…&baseline=0` | Aligned Route comparison |
| GET | `/api/sessions/{id}/variants/diff?attempt_set_id=…&index=0&path=…` | One file before/after for one Attempt |
| POST | `/api/sessions/{id}/variants/verify` | `{attempt_set_id, check}`; run Checks after all Ways are terminal |
| POST | `/api/sessions/{id}/variants/judge` | `{attempt_set_id, agent_id}`; rank passing non-empty survivors with that configured Agent |
| GET | `/api/variants/probe?provider=…&models=a,b` | Preflight comma-separated models for structured tool calls; each result includes `control_usage` |
| POST | `/api/sessions/{id}/variants/plan` | `{task, agent_id}`; return plan, rendered instruction, and `control_usage` |
| GET | `/api/sessions/{id}/variants/cost?attempt_set_id=…&baseline=…&baseline_provider=…` | Actual and counterfactual price report with known flags |
| POST | `/api/sessions/{id}/variants/adopt` | `{attempt_set_id, index}`; resumable Keep without commit |
| POST | `/api/sessions/{id}/variants/discard` | `{attempt_set_id}`; cancel/join and remove without keeping |

Attempts require an autonomous single-Agent Session, Git, and local Podman. A keepable
candidate must be completed, non-empty, and passing. Keep phases are durable
and retrying the same index resumes; discard is rejected after apply begins.

Remote missing prices remain unknown. `total_usd` is complete only when its
known flag says so. Plan, model-check, and Judge calls are outside Attempt execution totals and
use `control_usage`. Plan/Judge error responses also include that field so a failed or invalid
Agent response does not hide a paid call; `token_usage_known: false` marks a known subtotal.
