This is the 5-minute path from "nothing installed" to "an agent worked in my
repository." If anything breaks, see [Troubleshooting](/guides/troubleshooting/).

## Prerequisites

- macOS or Linux (x86_64 or aarch64). On Windows, run Axocoatl inside WSL2 —
  see [Windows (WSL2)](#windows-wsl2) below.
- [Ollama](https://ollama.com) for local LLM use (recommended for first
  contact). Five other providers work too — OpenAI, Anthropic, Mistral,
  Gemini, and OpenRouter; set the right key in `.env`. (The `openai` provider
  also takes a `base_url`, so it can target compatible implementations such as
  LM Studio, vLLM, and MLX.)
- `podman` for the default local session sandbox, or credentials for an explicitly
  configured E2B-compatible remote backend.

<Steps>

1. **Install Axocoatl.**

   <Tabs syncKey="install">
     <TabItem label="Curl (recommended)">
       ```sh
       curl -fsSL https://axocoatl.ai/install.sh | sh
       ```
     </TabItem>
     <TabItem label="Cargo">
       ```sh
       cargo install axocoatl-cli
       ```
     </TabItem>
     <TabItem label="From source">
       ```sh
       git clone https://github.com/axocoatl/axocoatl && cd axocoatl
       cargo build -p axocoatl-cli --release
       ```
     </TabItem>
   </Tabs>

   If you use the from-source path, substitute `./target/release/axocoatl`
   for `axocoatl` in the commands below.

2. **Pull a model.**

   ```sh
   ollama serve &
   ollama pull llama3.2
   ```

3. **Run `axocoatl doctor` to confirm everything is reachable.**

   ```sh
   axocoatl doctor
   ```

   You should see ✓ on Rust toolchain, config, Ollama, model, data dir, and
   (if installed) podman.

4. **Start the daemon.**

   ```sh
   axocoatl dev
   ```

   This brings up the daemon, IPC, and the app on `http://localhost:8080`.

5. **Open the app and start a session.**

   In your browser, open `http://localhost:8080`. Authorize a project
   directory from the workspace rail, create a session, and ask the agent to
   inspect the repository. Chat remains the main work surface; Files, Activity,
   Terminal, Browser, Attempts, and Agent graph open around it.

   In a single-agent session on the default local Podman backend, enable
   **Explore several ways** for a task where you want alternatives, choose the
   agent and model for each attempt, and send the task. Open
   **Attempts** to compare **Outcome** and **Route**, run the detected repository
   checks, then keep one result.

</Steps>

## Windows (WSL2)

Axocoatl is a Unix-first runtime — the session sandbox is rootless Podman and
the always-on service is systemd/launchd — so on Windows it runs **inside
WSL2**, not natively. There is no native Windows binary; the install script
above will point you here if you run it from PowerShell or Git Bash.

<Steps>

1. **Install WSL2.** In an administrator PowerShell, then reboot when prompted
   (this installs Ubuntu by default):

   ```powershell
   wsl --install
   ```

2. **Open your WSL distro and install Podman** (needed for sandboxed directory
   sessions):

   ```sh
   sudo apt-get update && sudo apt-get install -y podman
   ```

3. **Install Axocoatl inside WSL** — the same one-liner, now detected as Linux:

   ```sh
   curl -fsSL https://axocoatl.ai/install.sh | sh
   ```

4. **Run it.** `axocoatl dev` inside WSL, then open `http://localhost:8080` in
   your Windows browser — WSL2 forwards `localhost` to the host automatically.

</Steps>

For the always-on service (`axocoatl service install`), enable systemd in WSL2:
add a `[boot]` section with `systemd=true` to `/etc/wsl.conf`, then run
`wsl --shutdown` once from PowerShell. Plain `axocoatl dev` does not need it.

## What just happened?

The daemon started the runtime and restored its durable state. Your session is
anchored to the directory you authorized; its file, shell, and terminal tools run
through the session sandbox. The app streams each action and keeps the conversation
and git state together. If you chose several ways, each attempt used an isolated
working copy until you kept one.
