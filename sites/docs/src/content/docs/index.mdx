Axocoatl's dashboard keeps your repository, conversation and Agent's work together.
Ask for a change in a **Session**, follow the tool calls, then inspect the actual
files and Git diff. Files, Preview, Terminal and History open around the conversation.
You decide what to commit.

## From setup to your first Session

<Steps>

1. [Install Axocoatl](/start/install/) for your platform.
2. [Set up this computer](/start/onboard/#recommended-setup): run
   `axocoatl onboard --start none`, then `axocoatl doctor`. Resolve any setup
   failures and start `axocoatl dev`. Leave that terminal open, or use an
   already-running daemon or Always-On Service.
3. Open the **Sign in:** link it prints. In the dashboard, choose
   **Open workspace…** and select your existing repository. Onboarding has not
   created or chosen a project for you.
4. Create a **New session**, review its environment setup, then apply
   **Team & budget**. Ask for one concrete result in Conversation.
5. Follow the work, inspect **Files → Source Control → Last turn**, check the
   result, and commit deliberately.

</Steps>

## Choose a model for the Session

Ordinary dashboard Sessions use native models through **Ollama** or **OpenRouter**.
The default is one Agent; helpers and required checks or review are choices you apply
in Team & budget. [Provider requirements](/configure/providers/) explain the models,
memory, accounts and network access each route needs.

Claude Code and Codex are also available as writers for headless loadout runs.
Those runs have their own outcome and signed-receipt workflow; a normal workbench
turn does not issue a run receipt. See
[Run a fix from the terminal](/start/first-fix/) when you want that workflow.
