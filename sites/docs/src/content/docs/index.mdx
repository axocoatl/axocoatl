Claude Code, Codex or a local model works in a sandbox its credential never enters.
When it says it is done, the host runs your tests on the final files and a different
model reviews the change. Every run ends with an exit code for CI and a receipt signed
on your computer.

## What the receipt rests on

When a run finishes, passing or not, the daemon signs a receipt with a key kept on
your computer: the files the run changed, each with its SHA-256 as the required checks
judged it, the sandbox and network policy, the checks, the review, the models and the
verdict. It proves which key signed which facts, not that the change is correct
([What it proves, and what it does not](/workbench/receipts/#what-it-proves-and-what-it-does-not)).
The facts come from what the host enforces whatever the model says.

Axocoatl is open source: a Rust daemon that runs Agents against your repository and
records their work, and a browser workbench around one durable Session. A new Session
starts with one Agent, the lead, which writes. Read-only helpers it can delegate to,
and [required checks](/configure/agents/#required-checks) and a
[required review](/configure/agents/#required-review) that the host runs before a turn
completes, are opt-in.

<CardGrid>
  <Card title="Isolation built in" icon="padlock">
    Every Session's repository tools run in a rootless Podman container; the web and
    MCP tools run on the host. Read-only helpers get no file-writing tools, and the
    kernel blocks their shell from writing, creating, renaming or deleting repository
    files or opening TCP connections (Landlock, Linux 6.7 or later); otherwise they get
    no shell. Per-Agent write scopes
    share one checkout, and every change is checked against complete, digest-verified
    snapshots. [Where the boundary stops →](/operate/security/#what-axocoatl-controls-and-what-it-does-not)
  </Card>
  <Card title="A complete record" icon="list-format">
    The host runs required checks on the exact final files. Budgets you approve are
    charged with what each call actually used and carry across restarts. The Session
    durably records every model call, tool call, budget decision and check, and every
    `axocoatl run` that finishes gets a signed receipt.
    [Native authority and budgets →](/configure/agents/#native-authority-and-budgets)
  </Card>
  <Card title="Any model, per Agent" icon="random">
    Each Agent has its own provider and model: local models through Ollama, hosted models
    through OpenRouter, with Anthropic, OpenAI, Gemini and Mistral adapters on the
    compatibility path. A local writer can be reviewed by a different model. The
    reviewer we measured ran locally; reviewers through OpenRouter have not been measured.
    [Cross-model review →](/configure/cross-model-review/)
  </Card>
</CardGrid>

Claims about results come only from measurements, stated once with their setup and
limits in [What we measured](/understand/what-we-measured/). One Agent remains the
cheaper choice for small tasks.

A [loadout](/configure/loadouts/) is a YAML recipe for one run: the built-in `fix`,
`fix-claude-code`, `fix-codex`, `qa` and `audit`, or your own. [`axocoatl run`](/reference/run/)
runs one headless in a Session under network egress (or none), ending with an exit
code, and on request a JUnit file, a record of the whole run and the signed receipt.

The Session keeps conversation, context, files, terminal, Preview, history, and Git
review together. Explore several Ways only when the task warrants comparison.
[Workspace knowledge](/workbench/knowledge/) retains source-linked decisions and
findings across Sessions.

## The shortest path

<Steps>

1. [Install the binary](/start/install/) on macOS, on Linux, or inside WSL2 on Windows (WSL2 not yet verified).
2. Run [`axocoatl onboard`](/start/onboard/) to configure Axocoatl for this user: it sets up a writer and a reviewer, and asks before each download or change. It installs Podman with Homebrew on an Apple-silicon Mac (then creates and starts its machine) or with apt, dnf, pacman or zypper on Linux; on an Apple-silicon Mac without Homebrew it points to the podman.io installer, on an Intel Mac to the Podman 5.8 package, on another Linux distribution it names what to install, and it refuses Ubuntu 22.04 and older. Then run [`axocoatl doctor`](/start/onboard/#run-doctor). Onboarding does not create a project or Workspace.
3. Start `axocoatl dev` and leave it running. From another shell, in a repository, run `axocoatl run fix --task "Paging skips the last item" --receipt receipt.json` with the local or OpenRouter writer onboarding set up, or `axocoatl run fix-claude-code` or `axocoatl run fix-codex` with the same flags when you chose Claude Code or Codex ([`axocoatl run`](/reference/run/)). Each uses the reviewer onboarding set up. Before the writer starts, the run detects the repository's language and installs its dependencies; after the writer, the host runs the repository's check, such as `npm test` or `pytest` ([which repositories work](/workbench/fix-qa-audit/#fix)).
4. Or open the sign-in link `axocoatl dev` prints, choose **Open workspace…**, and [create a Session](/start/first-session/). Apply **Team & budget**: Lead's limits, its helpers' limits, and any required checks or review. Then ask for a bounded change and inspect Git.

</Steps>

## What stays local—and what may not

The daemon and default Podman sandbox run on your machine, and Axocoatl adds no
product telemetry. That does not mean every configured path is offline: the
container's network is on by default, so set `network: none` for repositories
you don't trust. Hosted
model providers, remote MCP servers, web search, webhooks, bridged sandbox
networking, embedding-model downloads (the first daemon start downloads an 87 MB
model from huggingface.co), and an E2B Cloud remote sandbox can send data over the
network. [Review the security boundary before using untrusted
input →](/operate/security/)
