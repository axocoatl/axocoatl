Axocoatl runs coding agents against your repository. For a fix, choose Claude Code,
Codex, a local Ollama model or a hosted model through OpenRouter. The host runs the
repository's checks and a required review before deciding whether the fix passes.
You inspect the changed files, the outcome and its signed receipt.

## Start here

<Steps>

1. [Install Axocoatl](/start/install/). The release binaries support Linux and macOS;
   check the platform requirements before downloading.
2. [Set up this computer](/start/onboard/) with `axocoatl onboard --start none`.
   Choose a writer and reviewer, complete their sign-ins, and approve the setup
   changes you want. This configures the current user, without making a project.
3. Run `axocoatl doctor`. Resolve any failures, then start `axocoatl dev` and leave
   that terminal open. If onboarding already started the daemon, keep it running
   instead of starting another.
4. Open a **second terminal** and follow [Your first fix](/start/first-fix/) to run
   the selected writer in your repository, save its evidence and verify the receipt.
   For interactive work, open the daemon's sign-in link and
   [create a Session](/start/first-session/).

</Steps>

## Choose how to work

<CardGrid>
  <Card title="Run a task from your shell" icon="seti:shell">
    A **loadout** is a YAML recipe for one run. The built-in `fix`,
    `fix-claude-code` and `fix-codex` recipes include checks and a required review.
    `qa` explores a running app; `audit` reads a repository and reports findings.

    [Run your first fix →](/start/first-fix/)

    Then [keep a passing run as a PR](/workbench/keep-as-pr/), check its receipt with
    the [GitHub Action](/workbench/receipts/#checking-pull-requests-in-github-actions),
    or look up [flags and exit codes](/reference/run/).
  </Card>
  <Card title="Work in a repository Session" icon="laptop">
    A **Session** keeps your conversation and work anchored to a repository.
    Open Files, Terminal, Preview, History and Git around it. A new Session starts
    with one Agent; helpers, required checks and a required review are opt-in.
    Claude Code and Codex write headless runs; an ordinary workbench Session uses
    a native Ollama or OpenRouter model.

    [Create your first Session →](/start/first-session/)
  </Card>
</CardGrid>

## Read the evidence with its limits

A [signed receipt](/workbench/receipts/) identifies the key that signed the recorded
files, checks, review and verdict. It does not prove that the change is correct.
Failed runs can have receipts too; a run refused before it starts has none, and a
signing failure is reported. Workbench turns do not issue run receipts. The
[record bundle](/reference/run/#record-bundle) and [History](/workbench/history/)
retain execution evidence with their documented bounds; they do not promise that
every historical message or attachment is sent to every future model call.

Hosted providers receive the context sent to them. Local execution still downloads
software and models, and configured tools may use the network. Read the
[security boundary](/operate/security/) and [provider requirements](/configure/providers/).
Functional release checks and model-quality comparisons answer different questions:
see [release verification](/operate/verification/#release-evidence) and
[What we measured](/understand/what-we-measured/). The comparative review measurements
used a local reviewer; OpenRouter reviewers have not been measured in that comparison.
