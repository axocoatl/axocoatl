An Axocoatl agent is a [`ractor`](https://github.com/slawlor/ractor) actor:
an isolated unit of computation with its own mailbox, lifecycle, memory,
and token budget. Each agent runs in its own task. Crashes are caught by a
supervision loop that restarts the agent from its last checkpoint. State
survives the process through periodic checkpoints.

## Anatomy of an agent

A typical agent configuration combines identity, provider/model selection,
instructions, dependencies, budgets, and optional generation controls:

```yaml
- id: coder
  name: "Coder"
  provider: ollama
  model: qwen2.5-coder:14b
  system_prompt: |
    You are a senior software engineer working in a directory session.
    Write to disk with the write_file tool; never paste code as chat.
  depends_on: [planner]
  token_budget:
    per_execution: 8000
    per_call:      4000
    overflow_policy: warn
  sampling:
    temperature: 0          # asks supported adapters for lower-variance output
    response_format: json   # support and implementation vary by adapter
```

- **`id`** — the stable config id used by sessions, Automations, APIs, and
  coordination metadata.
- **`provider`** + **`model`** — which LLM backs this agent. Each agent
  can use a different one. Local for cheap tasks, frontier for hard ones,
  same workflow.
- **`system_prompt`** — the agent's role and operating instructions.
- **`depends_on`** — dependency metadata used when legacy workflow YAML is
  projected into an Automation DAG and when a multi-agent directory session
  determines execution order.
- **`token_budget`** — a pre-flight check, enforced *before* every LLM
  call. The agent can't spend more than `per_call` in any single call or
  more than `per_execution` across one full activation. `overflow_policy`
  is `abort` (the default — return a budget error and stop) or `warn` (log
  a warning and continue past the budget). The old `summarize` value is a
  **deprecated alias that now maps to `warn`** — context compaction toward
  the model window is automatic (see [Memory](/concepts/memory/)) and no
  longer a spend policy.
- **`sampling`** — generation controls for the default-agent execution path,
  all optional:
  `temperature`, `top_p`, `max_tokens`, and `response_format` (`text` or
  `json`). The current coordinator path does not carry these settings, and
  adapter support is not uniform: some fields are native request parameters,
  while JSON output may be prompt-assisted or unavailable. Temperature zero
  can reduce variability but does not make a generative model mathematically
  deterministic. Omit any field to keep the provider's default.

## Lifecycle

1. **Spawn** — on daemon boot, every agent in the config gets a
   `ractor::Actor` spawned. Agents are spawned *parentless* (no ractor
   supervisor tree); liveness is handled by the supervision loop below.
2. **Idle** — the actor sits in its mailbox loop, waiting for messages.
3. **Execute** — a session, Automation node, coordinator, or direct API/CLI
   caller sends it work.
4. **Stream** — the LLM call streams tokens internally (always). The session's
   Activity and Agent graph modules reflect execution live.
5. **Checkpoint** — periodically the actor writes its session transcript
   to disk so a crash + restart can resume the conversation.
6. **Complete** — returns the output and emits the relevant lifecycle/event
   records for observers and trigger subscribers.

## Supervision

Agents are spawned parentless, so supervision is a **liveness loop**, not a
ractor supervisor tree. A background runner polls every agent's status on a
**5-second interval**; if an agent has stopped unexpectedly, it respawns a
fresh actor whose `on_start` restores state from the latest checkpoint. A
per-agent restart cap (5 consecutive attempts) stops a crash-looping agent
from restarting forever.

The restart restores the **conversation transcript only** — the messages from
the last checkpoint. It does *not* restore token-usage accounting or
tool/plan state; the agent resumes the conversation and rebuilds the rest.
The app shows the restart in the agent's status line.

## Providers

A provider trait lets every agent pick its backend independently. Six
provider ids are wired:

- `ollama` — local Ollama daemon (default).
- `openai` — OpenAI chat completions. Honors a configurable `base_url`, so
  it can also target compatible implementations such as LM Studio, MLX, and
  vLLM.
- `openrouter` — the OpenAI client re-pointed at openrouter.ai, with the
  Axocoatl attribution headers attached.
- `anthropic` — Anthropic messages API.
- `gemini` — Google Gemini.
- `mistral` — Mistral chat.

Each agent's configured `model` is sent as a per-request override, so a
shared provider still serves every agent its own model. Keys live in `.env`.
The app's onboarding wizard fills the right keys for you.

## Restart, manually

If you change an agent's config (system prompt, model, budget) and want
the running actor to pick it up without restarting the whole daemon:

```sh
axocoatl agents restart coder
```

The supervisor stops the actor, re-reads its config, and respawns it.
Memory survives.
