---
title: Skills
description: Callable session capabilities that publish typed lattice events.
---

A **Skill** is a named capability that can be enabled for a session agent as a
callable tool. When called—or fired manually—it publishes the custom lattice
events in its `emits` list. Event-triggered Automations and webhooks can react
to those publications.

:::tip[Runnable example]
[`examples/skills-lattice`](https://github.com/axocoatl/axocoatl/tree/main/examples/skills-lattice)
demonstrates `emits` / `reacts_to` fan-out using the reusable coordination
primitives in a standalone harness—`cargo run`, no API keys. It is not the
daemon's Skill execution path.
:::

## Anatomy

```yaml
- id: code-review-checklist
  name: "Code Review Checklist"
  description: "Structured 12-point review."
  emits: ["ReviewComplete", "BlockingIssueFound"]
  reacts_to: ["CodeReady", "PullRequestOpened"]
  agents: [reviewer, coder]
  prompt: |
    Review the code against: correctness, edge cases, error handling,
    performance, security, style, naming, tests. Return JSON with
    `issues` and `severity`.
```

Five knobs:

- **`emits`** — events this Skill publishes when fired.
- **`reacts_to`** — capability metadata used by coordination-library examples;
  the product daemon does not currently execute holders from this field.
- **`agents`** — holder metadata shown in Settings and API responses. Session
  `enabled_skills` controls which Skill tools are actually exposed.
- **`prompt`** — task metadata used by the standalone coordination example; the
  current daemon publisher does not execute it as an agent prompt.
- **`description`** — surfaces in the app.

## Event-driven execution

Publishing a Skill does not itself select or run one of the configured holders.
For reachable event-driven work, use **Settings → Automations → + Automation**
and choose an On Skill or On event trigger. The same record can be created with
`POST /api/automations` (or by the one-time first-boot config seed), then edited
and run from Settings with either:

- **OnSkill** to match `produced_by: skill:<skill-id>` exactly.
- **OnEvent** to match one of the Skill's emitted event types exactly.

The Automation then runs through the canonical explicit DAG executor. The
coordinator role is the separate path for auctioning subtasks to workers.

## Manual fire

Use **Settings → Skills** or the HTTP API to publish a Skill's events manually:

```sh
curl -X POST http://localhost:8080/api/skills/code-review-checklist/fire
```

## Why this matters

Skill publication decouples the session agent that raises an event from the
Automations, webhooks, and retained API/WebSocket observers that consume it. Keep graph execution
explicit in Automations and use Skills as named, observable event-producing
capabilities.
