Workflow patterns to adapt.

These are representative workflow shapes built from Axocoatl's runtime primitives, not customer testimonials. Connect the relevant repositories, MCP servers, and delivery endpoints, then adapt them to your own work.

▶ Trigger: schedule, every 7d

Release pulse

A coordinator agent pulls the past week of git activity, opens issues for the next 72 hours, and produces a paragraph of release notes. It posts the draft to a team channel for review. A top-level Interrupt node can hold the run for an explicit human decision before a later node writes anything; that parked decision reappears after a daemon restart and resumes without replaying completed nodes.

activity-collector → issue-summarizer → release-writer → reviewer
⊛ Trigger: external integration publishes NewSupportEmail

Support triage

An email integration publishes a lattice event for each new message. The matching Automation classifies the request, attaches the relevant history from the customer's previous tickets, and routes the thread to the right teammate with a one-line summary at the top. It also drafts an acknowledgement reply.

classifier → history-retriever → responder
▶ Trigger: schedule, every 24h

Daily briefing

A planner agent reads the team's calendar, the last 24 hours of activity, and any unresolved Automation interrupts. It produces a five-bullet briefing on each interval: what shipped, what's blocked, and what needs a person.

calendar-reader → activity-summarizer → briefing-writer
▣ Trigger: session-mode, on demand

Bug bisection

When a test starts failing, you open a directory session and tell the agent which test is broken. It runs git bisect inside the sandbox, identifies the offending commit, opens the diff in the app, and proposes a fix. You review and merge.

bisector (single-agent session)
◇ Trigger: external watcher fires a Skill for ContractUploaded

Contract review

An external watcher publishes the contract event through a Skill. The matching Automation parses the document, flags non-standard clauses, summarizes payment terms, and posts the findings to a review channel. Legal reads the summary, not the contract.

parser → clause-reviewer → summary-writer

Build your own.

Define agents in YAML. Create live Automations in Settings with a runnable Input → Agent starter graph, or use the HTTP API for programmatic CRUD. Edit and run them alongside Skills and MCP servers; legacy workflow YAML is first-boot seed data. Use the session app to run repository work and review its result.
