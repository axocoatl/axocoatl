Changelog

Released versions.

Published Axocoatl releases appear here after their GitHub release exists. The canonical source, including work not assigned to a release, is CHANGELOG.md.

v1.5.0 Unreleased

Native Sessions run on Ollama 0.40, and a restored data directory starts again.

Native execution accepted only an Ollama reporting exactly 0.20.6, while Homebrew and ollama.com ship 0.40.6. Native Sessions now run on Ollama 0.40.6 and later 0.40 releases, and on a later 0.x release once the contract probes pass, with GGUF models in llama.cpp's llama-server only. The probes are two small requests to your own server: a prompt longer than the context must be refused before generation, and a one-token limit must stop after one token. A data directory restored from a backup or brought to a new Mac, which 1.1.0 through 1.4.0 refused to start on, starts again.

Changed

  • Native Sessions accept Ollama 0.40.P with P 6 or later, and a later 0.x release (0.41 or later) once both contract probes pass for each model: doctor and onboarding warn that it is newer than the audited 0.40.6, and the run's receipt names it as unaudited. They refuse 0.20.6, older releases, a new major release, pre-releases and local builds, each with what to do. A model that is not GGUF, or that Ollama runs with its MLX runner, is refused.
  • axocoatl onboard is the one setup command: it sets up a writer (Claude Code, Codex, local models or OpenRouter) and a different reviewer, asking before each change, and ends ready or with the steps left. It installs Podman with Homebrew on an Apple-silicon Mac, or with apt, dnf, pacman or zypper on Linux; on an Apple-silicon Mac without Homebrew it points to the podman.io installer, on an Intel Mac to the Podman 5.8 package, and on another Linux it says what to install; it refuses Ubuntu 22.04 and older. On a Mac it then creates and starts the Podman machine. With 48 GB of memory or more it suggests qwen3-coder:30b writing and gpt-oss:20b reviewing (gpt-oss:120b from 96 GB); a fix run calls them in turn.
  • axocoatl doctor reports the sandbox, the models, the writers and the daemon, each with its fix, and ends with whether Axocoatl is ready.
  • The daemon follows CONTAINER_CONNECTION and CONTAINER_HOST as Podman does. When the Podman they select does not answer, it no longer starts without removing its leftover containers: its start fails, naming the variable, whenever the data directory holds any Podman Session, closed ones included.
  • When its install directory is not on PATH, the installer asks before adding one line to the startup files your shell reads. AXOCOATL_VERSION installs a given release, and AXOCOATL_INSTALL_BASE_URL names where its archive is.
  • Commands on the home page, /install, the README and the docs' first-run pages that did not run as written are fixed, a lint checks their shape, and the pages say what is not yet verified.

Added

  • axocoatl connect openrouter signs in to OpenRouter in the browser and stores the key it gets, with no key to paste.
  • api_key_secret names a stored secret in place of a hosted provider's api_key.
  • The Ollama version each native model ran on is in the run's record and its receipt.
  • axocoatl doctor checks the Ollama version, each configured model and the data directory's ownership record; axocoatl service status shows why the service last failed to start; the docs have an Uninstall page.
  • A clean-machine new-user gate blocks a release; the only way past it is a logged manual override that only GitHub logins listed in the repository can start.

Fixed

  • A data directory that was copied or moved starts again: the daemon records its new location once, and 1.4.0 starts on it after that.
  • A Session keeps working in a repository restored or copied at the same path.
  • Onboarding and doctor read your subordinate ids from /etc/subuid and /etc/subgid on Linux, and print the exact command to add a free range, instead of passing while keep-id containers failed. When newuidmap or newgidmap is missing, they name the package that ships them, or its reinstall when that package is installed.
  • A run leaves no node_modules in a repository that had none; on Linux one owned by a subordinate uid made your own npm install fail.
  • Hardened commands can rename files into other directories (Landlock ABI 2, Linux 5.19, and later), so Rust checks can pass in loadout runs.
  • One upstream error from the reviewer's model no longer ends a run.
  • Safari opens the workbench from a 127.0.0.1 bookmark or sign-in link.
  • On Linux, connect claude-code and connect codex no longer type a line break into the program's terminal when they stop, which showed as an extra blank line.
  • Preview WebSockets stay open beside a cookie that is not ASCII, which in Safari stopped the live reload of every Session's Preview.
  • The workbench no longer reloads itself without end when its API answers 401 while its page still loads: it reloads at most once a minute, then says this browser is signed out and how to sign in again.

Security

  • The route to Ollama on this computer refuses Ollama 0.40's new endpoints, and a Session opens it only when Ollama reports its cloud features disabled.
  • Dependencies move to zip 9 for RUSTSEC-2026-0367, -0368 and -0369, to rustls-webpki 0.103.16 for RUSTSEC-2026-0382, and to webpki-roots and webpki-root-certs 1.0.10 for RUSTSEC-2026-0381 and -0383.
  • The workbench's vendored markdown-it moves to 14.3.3 for GHSA-vfgh-jcmw-g37q and GHSA-gfr2-rv44-r23c. The documentation site's build moves to vite 8.3.4 for GHSA-587h-7wmj-h5pm; nothing of it ships in Axocoatl.
  • A cookie that is not ASCII no longer signs Safari out of the workbench: the daemon reads the Cookie header as bytes, one cookie at a time.
  • A Preview app's server can no longer set a cookie for localhost through the Preview proxies: they remove the Domain attribute from its Set-Cookie headers.
  • Known issue: in Safari on macOS, the script of a Preview opened full page can still set a cookie for localhost that reaches the workbench and every other Session's Preview. It cannot sign in or read the workbench's cookies, but enough such cookies to fill the about 200 KB Safari sends with a request can sign that browser out of the workbench's API (with Path=/api, until localhost's data is removed in Safari's settings) or out of the whole workbench (with Path=/; signing in again works until the Preview writes them again), and with Path=/ws they stop its live updates. For Sessions whose code you do not trust, use a Chromium-based browser (details). Measured in Playwright's WebKit, not in Safari itself.
v1.4.0 2026-10-14

Every run is signed, and Claude Code or Codex is one command.

When a loadout run finishes, passing or not, the daemon signs a receipt with an Ed25519 key kept in your data directory: an in-toto statement in a DSSE envelope that lists the files the run changed with their SHA-256, as the required checks judged them when they ran, and the sandbox and network policy, the checks, the review, the models and the verdict. axocoatl receipt verify checks it offline against the keys you trust and the files in a checkout. It proves which key signed which facts, not that the change is correct.

Added

  • Signed receipts of every finished loadout run, axocoatl run --receipt FILE, and axocoatl receipt show, verify and key. A route's body check is in the receipt.
  • Keep as PR commits only what the receipt covers, adds Axocoatl-Run and Axocoatl-Receipt trailers, and puts the receipt in the pull request's description.
  • The Run outcome panel shows the run's receipt, and Settings shows the public key line to copy.
  • Built-in loadouts fix-claude-code and fix-codex: axocoatl run fix-claude-code --task "…" --model reviewer=… runs fix with the pinned Claude Code or Codex as the writer. fix-codex sends the OpenAI API key when one is stored, else your ChatGPT sign-in, and says which.

Changed

  • A loadout file of yours that declares a built-in id is refused with how to rename it, instead of the built-in running silently.
v1.3.2 2026-10-14

Model calls through a route are read before they leave.

A route checked a request's method, path and query and passed its body unread, so a request the route allowed could ask the model provider to fetch a URL, search the web, connect to an MCP server or run a tool on its own servers, reaching hosts the Session's egress policy does not list. Claude Code's WebSearch tool sent such a request through the route Axocoatl adds for it.

Security

  • A route to api.anthropic.com, api.openai.com, chatgpt.com, openrouter.ai, generativelanguage.googleapis.com, api.mistral.ai, api.x.ai or ai-gateway.vercel.sh reads each request body before it adds the credential, and refuses with 403 provider_fetch_refused, recorded in the Session's network record, one that offers a tool the provider runs, names MCP servers, turns on a provider's web search or asks for content from a URL. An allowed body is sent byte for byte.
  • The route to Ollama on this computer carries only inference and model listing, and refuses a cloud model, which Ollama runs on ollama.com.

Added

  • provider_fetch on a route: refuse turns the check on for another host, allow turns it off, and validation warns about allow on a model API host.

Changed

  • Claude Code runs without its WebSearch tool, and Codex without its hosted web search and image generation, while the route to their model API checks bodies.
  • An e2e check whose e2e.config.ts uses gateway() from ai, as e2e init writes it, is refused by default on a route to ai-gateway.vercel.sh with 403 ai_sdk_gateway_refused, and admission warns about it. Build the model with the gateway's OpenAI-compatible API instead (the e2e check).

Fixed

  • A Session whose folder was deleted, moved, or replaced by a file or a link no longer blocks other Sessions and runs, and can be closed and deleted. The daemon starts again when a Session folder became a symbolic link.
  • A run in a repository moved to another path works in the new path, not the old one.
  • Keep as PR pushes to a private HTTPS remote with Apple's git, whose credential helper is set in its installation's configuration.
v1.3.1 2026-10-13

Codex runs with your ChatGPT plan, and the token stays on your computer.

axocoatl connect codex runs the official Codex sign-in in a throwaway Podman container and stores the sign-in as the secret codex-chatgpt. A loadout's Codex writer with credential: codex-chatgpt sends its requests to chatgpt.com through a route that adds the sign-in on your computer; the Session container holds only a placeholder.

Added

  • axocoatl connect codex, with the browser sign-in or --device-auth, and --codex PATH for a Codex CLI on your computer.
  • The credential field on a loadout Agent, naming the stored credential its route sends.
  • The daemon refreshes the sign-in before it expires and after a 401, stores the rotated tokens and never logs a token.
  • axocoatl connect codex --status shows the stored sign-in, and --refresh asks the running daemon to refresh it now; neither shows a token. --sign-in-timeout gives the sign-in 1 to 60 minutes (30 by default).

Measured

  • On 2026-10-11 a fix run of the pinned Codex 0.160.1 with a ChatGPT plan passed against OpenAI's service: its 6 requests were answered 200, and no token-shaped string appeared in the container, the daemon's log, the record, the JUnit report or the output. The run cost $0.0014.
v1.3.0 2026-10-07

A whole run in one file, headless, with a record you can verify.

A loadout is a versioned YAML file that declares the Agents and their models, the required checks with their timeouts, the required reviewer, the egress allowlist and routes, the budgets and the prompt. axocoatl run <loadout> --task "…" runs it against the running daemon in a Session under network: egress (or none) with commands as non-root users, and exits 0 on a pass, 1 on a failed check and 2 when something needs a person. --junit and --record write JUnit and the run's whole record as one file that axocoatl record verify checks.

Added

  • Built-in loadouts: fix (one writer, required checks, review by a different model for up to three rounds, and the writer's answer to every finding, recorded), qa (one browser explorer whose findings each need a reproduction the host re-runs, against a clean reference build when you give one) and the opt-in audit (read-only area workers in parallel, then integration). What a run did not cover is listed, never passed over.
  • The Claude Code and Codex CLIs as a loadout's writer, inside the Session as the non-root writer user. Their credential, stored with axocoatl connect claude-code (it runs claude setup-token and stores the token without ever showing it) or axocoatl secret set from standard input or an environment variable, is added on your computer by a route; the container holds a placeholder, and every model call is in the network record.
  • tester-army/e2e as a required check, with its report in the run's Outcome and its model calls through a route.
  • Keep as PR: a passing run's changes on a new branch with your own git, without touching your checkout, and opt-in a pull request with gh. Never a force-push, never the default branch.
  • Per-check timeouts up to 30 minutes, one retry of a transient provider error on the same model, and an opt-in route to an Ollama server on this computer.

Changed

  • The claim that Axocoatl targets small local models first is withdrawn: nothing measured it. Results measured with Claude Code subagents are labeled as such, never as Axocoatl results.
  • Before a Session written by 1.2.0 is converted to segment files, its directory is copied once to backups/before-segments/ in the data root.
v1.2.0 2026-10-03

Agents' commands reach only the hosts you list.

With sandbox.network: egress a Session container has no network interface other than loopback. An Agent's commands reach only the hosts and ports listed under sandbox.egress, through a proxy in its own container; the daemon decides each connection and writes every connection it allows to the Session's network record before the connection opens.

Added

  • Routes under sandbox.egress.routes: the daemon ends TLS for the route's host, checks each request's method, path and query, and adds the route's credential as a header. The credential never enters a container.
  • Workload users (sandbox.workload, the default under egress with rootless Podman): Agents' commands run as a non-root user and read-only helpers as another, with no capabilities. Agents' tool calls and required checks also run under a seccomp filter from the execution supervisor, on top of Podman's profile.
  • web_search through a SearXNG container that Axocoatl runs with local Podman, or through your own instance, and web_fetch, which reads one public page and refuses private and local addresses. In native Sessions each call is written to the network record.
  • The browser and browser_check tools: headless Chromium in a per-Session container with no network interface other than loopback and no Workspace mount. axocoatl browser install builds its image.

Fixed

  • axocoatl onboard and axocoatl doctor check the Ollama server the way native Sessions do, and onboarding suggests installed models instead of defaulting to llama3.2.
  • axocoatl service install records where Podman is and, on macOS, keeps a log in ~/Library/Logs/Axocoatl/daemon.log.
v1.1.2 2026-10-02

The local API asks for a token.

When Axocoatl runs on your own machine without configured credentials, its API and WebSockets now require a per-daemon token. Open the sign-in link from axocoatl url once per browser.

Security

  • A random token in the data directory (mode 0600) is required on every API, WebSocket and A2A route; the browser keeps it in an HttpOnly cookie.
  • A loopback listener also holds its port on the other loopback address family.
  • Configured credentials compare in constant time and never match an empty value.
v1.1.1 2026-10-01

Read-only shells cannot open TCP connections.

The shell of a read-only helper or required reviewer can neither write, create, rename or delete repository files nor connect or bind over TCP. The kernel enforces both. UDP still follows the sandbox's network setting.

Added

  • Landlock network rules for read-only shells (Linux 6.7 or later); on older kernels a read-only Agent gets no shell and keeps its read-only file tools.

Fixed

  • The release workflow finds its own draft before publishing it.
  • The marketing site builds and deploys while a release's films are still being recorded.

Workspace knowledge and recorded team execution.

Keep source-linked decisions and findings across Sessions. Native execution retains exact activation inputs, accepted contributions, tools, checks, and controls inside the same workbench.

  • A Knowledge inspector and graph, with a bounded source index for Rust, JavaScript, TypeScript, TSX, and Python definitions and import syntax.

Axocoatl is installed and configured once for the current OS user. Repositories become Workspaces only when you choose Open workspace… in the app.

  • axocoatl onboard no longer creates an unrelated starter-project folder. It writes one owner-only user configuration and platform data directory instead.

v1.0.0 2026-08-26

The durable coding workbench.

Axocoatl 1.0 is one local-first workbench for coding agents. A folder-anchored Session keeps the accepted request, context relation, output, bounded Route evidence, and final lifecycle in durable History, while current repository changes remain ordinary Git for you to review and commit.

Added

  • One Session-centered product surface for conversation, Files, Source Control, Preview, Terminal, Agent activity, and Settings.
  • Durable Session History with structured context, bounded tool evidence, search, Markdown and JSON export, exact Stop, and turn-boundary rewind for autonomous single-Agent Sessions.
  • Explore several ways: independent local attempts, Outcome and Route comparison, shared repository Checks, optional Judge evidence, and Keep this one as an ordinary uncommitted Git change for final review.
  • Reviewed Session environments. Repository setup is a visible decision before execution; local Podman and a configured E2B Cloud backend retain distinct, honest boundaries.
  • Settings for Agents, Skills, MCP servers and approvals, and durable manual, interval, event, or Skill-triggered Automations.
  • Checksum-verified native release archives for macOS and Linux on Intel and Arm, plus separately published Rust crates.

Changed

  • The browser app now has one interactive route at /. Older dashboard, Chat, Studio, and Variants destinations are consolidated into the Session workbench instead of competing product shells.
  • Eligible 0.1.x single-Agent Session transcripts are recovered into canonical History through a bounded, crash-safe compatibility path. Current state storage uses symlink-resistant, identity-checked writes and keeps control-plane data outside local repository execution.
v0.1.4 2026-06-13

The coordinator run view.

Added

  • A coordinator's work is now a live view in the dashboard: a goal decomposed into subtasks, each auctioned to the best-suited worker by capability and budget (the winning worker and the runner-up bids shown), the workers running in parallel, and the final synthesis. Workers are driven by the coordinator rather than the lattice, so this is the surface that shows the team.
  • Prebuilt aarch64-unknown-linux-gnu (ARM Linux) binaries. The workspace moved to rustls, so it cross-compiles without a system OpenSSL, and that target now ships alongside the others.

Fixed

  • Tool calls that some local models (e.g. qwen3-coder) emit as <function=…> text instead of structured calls are now parsed, so those models can actually drive tools — write files, run commands — instead of doing nothing.
v0.1.3 2026-06-11

Local-first fixes.

Fixed

  • Coordinator workers now run on a configured model instead of gpt-4o. Spawned workers inherited the gpt-4o default, so on a local-only Ollama provider every worker returned a 404 and the coordinator could never synthesize. Declared workers now use their own model; ad-hoc workers inherit the coordinator's.
  • bash_background no longer kills the dev server it is asked to start. A trailing & double-backgrounded the command and SIGHUP'd it on shell exit, leaving the port stuck. The tool now strips a single trailing & (leaving && and a mid-command & untouched).
  • The demo config's coder agent moved to qwen3:8b. qwen2.5-coder:14b returns tool calls as text through Ollama rather than structured calls, so a coder session could not execute them; qwen3:8b emits structured tool_calls.
v0.1.2 2026-06-11

Coordination and memory.

Added

  • Coordinator role: an agent with role: coordinator decomposes a goal into subtasks, assigns each to a worker by a capability and budget auction, runs them in parallel, and synthesizes the result. Symbolic HTN planning when methods are provided, otherwise LLM decomposition. Live orchestration state is checkpointed internally; a terminal Completed, Cancelled, Failed, or Interrupted Session turn is not auto-resumed.
  • Agent-editable core memory: small blocks the agent curates as it works, rendered into its context every turn. Agent-driven recall (recall_search, recall_timeframe) and a background sleep-time pass that promotes durable facts up into the core blocks.
  • Automatic context compaction: long conversations summarize toward the model window instead of being snipped, so early context survives.
  • OpenAI-compatible servers: point the openai provider at LM Studio, MLX, or vLLM via base_url, with the agent's model sent per request. Stdio MCP servers now receive their env vars.

Changed

  • Tier 3 is now agent-editable core memory; the old shared long-term fact store is retired.
  • overflow_policy controls the local token-budget guard (abort default, or warn); context compaction is automatic and independent of that guard.
v0.1.1 2026-06-09

The cockpit.

Added

  • Variants: fan one prompt into N parallel attempts, each a real agent in its own git worktree, and keep the one you like.
  • A conversation-forward session cockpit: an N-surface layout (files, activity, browser, terminal, agent graph) that starts as just the conversation. Agent edits land as change cards; a running dev server lands as a preview card.
  • Unified conversation UI across Chat and Sessions; persisted session transcripts with Retry and Rewind.
  • Git-native sessions: a live Source Control pane (status, diff, commit, discard, branch switch) inside the cockpit.
  • Multi-turn tool-calling verified across all six providers.
v0.1.0 2026-06-03 · first public release

The runtime that runs.

Added

  • Stigmergic multi-agent coordination via EventLattice: agents activate themselves off accumulated signals, with no central orchestrator.
  • Workflow execution: CLI, HTTP, and IPC paths. Entry agents activate directly; downstream agents cascade via TaskCompleted events.
  • Per-Agent token budgets, four-tier persistent memory with neural Tier 4, and checkpointed Agent state.
  • Directory sessions with podman-sandboxed bind-mounts, full PTY terminal support, and durable Session records.
  • MCP integration: bundled server catalog, install flow, permission gate, and a Tools view in the dashboard.
  • Provider matrix: Ollama, OpenAI, Anthropic, Mistral, and Gemini; OpenRouter was usable through the OpenAI-compatible path.
  • Always-on system service (systemd / launchd) via axocoatl service install.
  • Interactive axocoatl onboard + axocoatl doctor.
  • Dashboard: Sessions cockpit, Studio lattice canvas, Automations editor, Chat, Files, Skills, MCP, Agents.
