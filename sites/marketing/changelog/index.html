Changelog

Released versions.

Published Axocoatl releases appear here after their GitHub release exists. The canonical source, including work not assigned to a release, is CHANGELOG.md.

v1.3.0 2026-10-06

A whole run in one file, headless, with a record you can verify.

A loadout is a versioned YAML file that declares the Agents and their models, the required checks with their timeouts, the required reviewer, the egress allowlist and routes, the budgets and the prompt. axocoatl run <loadout> --task "…" runs it against the running daemon in a Session under network: egress with commands as non-root users, and exits 0 on a pass, 1 on a failed check and 2 when something needs a person. --junit and --record write JUnit and the run's whole record as one file that axocoatl record verify checks.

Added

  • Built-in loadouts: fix (one writer, required checks, review by a different model for up to three rounds, and the writer's answer to every finding, recorded), qa (one browser explorer whose findings each need a reproduction the host re-runs, against a clean reference build when you give one) and the opt-in audit (read-only area workers in parallel, then integration). What a run did not cover is listed, never passed over.
  • The Claude Code and Codex CLIs as a loadout's writer, inside the Session as the non-root writer user. Their credential, stored with axocoatl secret set from standard input, is added on your computer by a route; the container holds a placeholder, and every model call is in the network record.
  • tester-army/e2e as a required check, with its report in the run's Outcome and its model calls through a route.
  • Keep as PR: a passing run's changes on a new branch with your own git, without touching your checkout, and opt-in a pull request with gh. Never a force-push, never the default branch.
  • Per-check timeouts up to 30 minutes, one retry of a transient provider error on the same model, and an opt-in route to an Ollama server on this computer.

Changed

  • The claim that Axocoatl targets small local models first is withdrawn: nothing measured it. Results measured with Claude Code subagents are labeled as such, never as Axocoatl results.
  • Before a Session written by 1.2.0 is converted to segment files, its directory is copied once to backups/before-segments/ in the data root.
v1.2.0 2026-10-03

Agents' commands reach only the hosts you list.

With sandbox.network: egress a Session container has no network interface other than loopback. An Agent's commands reach only the hosts and ports listed under sandbox.egress, through a proxy in its own container; the daemon decides each connection and writes every connection it allows to the Session's network record before the connection opens.

Added

  • Routes under sandbox.egress.routes: the daemon ends TLS for the route's host, checks each request's method, path and query, and adds the route's credential as a header. The credential never enters a container.
  • Workload users (sandbox.workload, the default under egress with rootless Podman): Agents' commands run as a non-root user and read-only helpers as another, with no capabilities. Agents' tool calls and required checks also run under a seccomp filter from the execution supervisor, on top of Podman's profile.
  • web_search through a SearXNG container that Axocoatl runs with local Podman, or through your own instance, and web_fetch, which reads one public page and refuses private and local addresses. In native Sessions each call is written to the network record.
  • The browser and browser_check tools: headless Chromium in a per-Session container with no network interface other than loopback and no Workspace mount. axocoatl browser install builds its image.

Fixed

  • axocoatl onboard and axocoatl doctor check the Ollama server the way native Sessions do, and onboarding suggests installed models instead of defaulting to llama3.2.
  • axocoatl service install records where Podman is and, on macOS, keeps a log in ~/Library/Logs/Axocoatl/daemon.log.
v1.1.2 2026-10-02

The local API asks for a token.

When Axocoatl runs on your own machine without configured credentials, its API and WebSockets now require a per-daemon token. Open the sign-in link from axocoatl url once per browser.

Security

  • A random token in the data directory (mode 0600) is required on every API, WebSocket and A2A route; the browser keeps it in an HttpOnly cookie.
  • A loopback listener also holds its port on the other loopback address family.
  • Configured credentials compare in constant time and never match an empty value.
v1.1.1 2026-10-01

Read-only shells cannot open TCP connections.

The shell of a read-only helper or required reviewer can neither write, create, rename or delete repository files nor connect or bind over TCP. The kernel enforces both. UDP still follows the sandbox's network setting.

Added

  • Landlock network rules for read-only shells (Linux 6.7 or later); on older kernels a read-only Agent gets no shell and keeps its read-only file tools.

Fixed

  • The release workflow finds its own draft before publishing it.
  • The marketing site builds and deploys while a release's films are still being recorded.
v1.1.0 2026-09-30

Workspace knowledge and recorded team execution.

Keep source-linked decisions and findings across Sessions. Native execution retains exact activation inputs, accepted contributions, tools, checks, and controls inside the same workbench.

Added

  • Versioned Markdown workspace knowledge with source hashes, typed links, backlinks, proposals, revision conflicts, and explicit import/export.
  • A Knowledge inspector and graph, with a bounded source index for Rust, JavaScript, TypeScript, TSX, and Python definitions and import syntax.
  • Native Session Team & budget, exact graph controls, recoverable unfinished work, embedded process supervision, and eligible OpenRouter-credit execution.
  • Required checks on Session team turns, and retained Ways comparison and decision history after cleanup.

Axocoatl is installed and configured once for the current OS user. Repositories become Workspaces only when you choose Open workspace… in the app.

Fixed

  • Native ordinary Agent turns use their reviewed invocation allowance for tool iteration, with a finite safety ceiling. Every call still requires durable grant admission.
  • axocoatl onboard no longer creates an unrelated starter-project folder. It writes one owner-only user configuration and platform data directory instead.
  • Config-aware commands now resolve that user configuration from any working directory. An explicit project-local YAML path is still available when requested.
  • Hosted-provider credentials use a masked prompt and a private 0600 configuration file. Combined daemon setup rejects shell-only credential placeholders that the service could not inherit.
v1.0.0 2026-08-26

The durable coding workbench.

Axocoatl 1.0 is one local-first workbench for coding agents. A folder-anchored Session keeps the accepted request, context relation, output, bounded Route evidence, and final lifecycle in durable History, while current repository changes remain ordinary Git for you to review and commit.

Added

  • One Session-centered product surface for conversation, Files, Source Control, Preview, Terminal, Agent activity, and Settings.
  • Durable Session History with structured context, bounded tool evidence, search, Markdown and JSON export, exact Stop, and turn-boundary rewind for autonomous single-Agent Sessions.
  • Explore several ways: independent local attempts, Outcome and Route comparison, shared repository Checks, optional Judge evidence, and Keep this one as an ordinary uncommitted Git change for final review.
  • Reviewed Session environments. Repository setup is a visible decision before execution; local Podman and a configured E2B Cloud backend retain distinct, honest boundaries.
  • Settings for Agents, Skills, MCP servers and approvals, and durable manual, interval, event, or Skill-triggered Automations.
  • Checksum-verified native release archives for macOS and Linux on Intel and Arm, plus separately published Rust crates.

Changed

  • The browser app now has one interactive route at /. Older dashboard, Chat, Studio, and Variants destinations are consolidated into the Session workbench instead of competing product shells.
  • Eligible 0.1.x single-Agent Session transcripts are recovered into canonical History through a bounded, crash-safe compatibility path. Current state storage uses symlink-resistant, identity-checked writes and keeps control-plane data outside local repository execution.
v0.1.4 2026-06-13

The coordinator run view.

Added

  • A coordinator's work is now a live view in the dashboard: a goal decomposed into subtasks, each auctioned to the best-suited worker by capability and budget (the winning worker and the runner-up bids shown), the workers running in parallel, and the final synthesis. Workers are driven by the coordinator rather than the lattice, so this is the surface that shows the team.
  • Prebuilt aarch64-unknown-linux-gnu (ARM Linux) binaries. The workspace moved to rustls, so it cross-compiles without a system OpenSSL, and that target now ships alongside the others.

Fixed

  • Tool calls that some local models (e.g. qwen3-coder) emit as <function=…> text instead of structured calls are now parsed, so those models can actually drive tools — write files, run commands — instead of doing nothing.
v0.1.3 2026-06-11

Local-first fixes.

Fixed

  • Coordinator workers now run on a configured model instead of gpt-4o. Spawned workers inherited the gpt-4o default, so on a local-only Ollama provider every worker returned a 404 and the coordinator could never synthesize. Declared workers now use their own model; ad-hoc workers inherit the coordinator's.
  • bash_background no longer kills the dev server it is asked to start. A trailing & double-backgrounded the command and SIGHUP'd it on shell exit, leaving the port stuck. The tool now strips a single trailing & (leaving && and a mid-command & untouched).
  • The demo config's coder agent moved to qwen3:8b. qwen2.5-coder:14b returns tool calls as text through Ollama rather than structured calls, so a coder session could not execute them; qwen3:8b emits structured tool_calls.
v0.1.2 2026-06-11

Coordination and memory.

Added

  • Coordinator role: an agent with role: coordinator decomposes a goal into subtasks, assigns each to a worker by a capability and budget auction, runs them in parallel, and synthesizes the result. Symbolic HTN planning when methods are provided, otherwise LLM decomposition. Live orchestration state is checkpointed internally; a terminal Completed, Cancelled, Failed, or Interrupted Session turn is not auto-resumed.
  • Agent-editable core memory: small blocks the agent curates as it works, rendered into its context every turn. Agent-driven recall (recall_search, recall_timeframe) and a background sleep-time pass that promotes durable facts up into the core blocks.
  • Automatic context compaction: long conversations summarize toward the model window instead of being snipped, so early context survives.
  • OpenAI-compatible servers: point the openai provider at LM Studio, MLX, or vLLM via base_url, with the agent's model sent per request. Stdio MCP servers now receive their env vars.

Changed

  • Tier 3 is now agent-editable core memory; the old shared long-term fact store is retired.
  • overflow_policy controls the local token-budget guard (abort default, or warn); context compaction is automatic and independent of that guard.
v0.1.1 2026-06-09

The cockpit.

Added

  • Variants: fan one prompt into N parallel attempts, each a real agent in its own git worktree, and keep the one you like.
  • A conversation-forward session cockpit: an N-surface layout (files, activity, browser, terminal, agent graph) that starts as just the conversation. Agent edits land as change cards; a running dev server lands as a preview card.
  • Unified conversation UI across Chat and Sessions; persisted session transcripts with Retry and Rewind.
  • Git-native sessions: a live Source Control pane (status, diff, commit, discard, branch switch) inside the cockpit.
  • Multi-turn tool-calling verified across all six providers.
v0.1.0 2026-06-03 · first public release

The runtime that runs.

Added

  • Stigmergic multi-agent coordination via EventLattice: agents activate themselves off accumulated signals, with no central orchestrator.
  • Workflow execution: CLI, HTTP, and IPC paths. Entry agents activate directly; downstream agents cascade via TaskCompleted events.
  • Per-Agent token budgets, four-tier persistent memory with neural Tier 4, and checkpointed Agent state.
  • Directory sessions with podman-sandboxed bind-mounts, full PTY terminal support, and durable Session records.
  • MCP integration: bundled server catalog, install flow, permission gate, and a Tools view in the dashboard.
  • Provider matrix: Ollama, OpenAI, Anthropic, Mistral, and Gemini; OpenRouter was usable through the OpenAI-compatible path.
  • Always-on system service (systemd / launchd) via axocoatl service install.
  • Interactive axocoatl onboard + axocoatl doctor.
  • Dashboard: Sessions cockpit, Studio lattice canvas, Automations editor, Chat, Files, Skills, MCP, Agents.
