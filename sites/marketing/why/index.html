Why Axocoatl

A final answer is not the job.

Axocoatl makes the folder-anchored Session the durable unit of agent work: accepted requests, context, output, bounded tool activity, and final lifecycle state persist while repository changes remain ordinary Git decisions.

The problem

A transcript is not the job.

Repository work spans files, commands, previews, failures, restarts, and review. The Session record explains what was accepted and executed; the working tree says what exists now.

A final answer cannot replace either one. The product has to keep the execution record reviewable, expose current repository state, and make the handoff between them explicit.

The product decision

Keep the record beside the repository.

The conversation is the Session spine. Its durable record explains accepted Turns and execution; Files, Terminal, Preview, and Source Control expose the Workspace as it exists now.

What it is

A workbench, not a framework kit.

One installed executable starts the local Rust daemon and serves the workbench in the browser you already use. Files, editor, Source Control, Terminal, Preview, History, and focused review open around the active Session instead of competing as separate products.

The daemon supervises agent actors, connects providers and tools, owns durable Session history, manages checkpoints and memory, and creates sandboxes. You do not have to assemble those primitives into a usable coding product or install a bundled browser runtime.

Durable

Keep the thread

Accepted turns, context relations, bounded tool evidence, output, and final lifecycle state stay attached to the Session.

Inspectable

Show the work

Open Files, Preview, Terminal, and Source Control around the Session. History keeps accepted Turns and bounded tool evidence; Source Control shows current Git state.

Extensible

Bring the stack

Configure Agents, Skills, MCP servers, and Automations in Settings. Configure Axocoatl once for the current OS user; explicit project-local YAML remains an advanced operator path.

When uncertainty matters

One answer is the default.

Most Sessions can stay on the direct path: use the Agent or configured team that fits the work, inspect the result, and review the Git changes. When implementation choices are genuinely ambiguous, turn on Explore several ways inside that same Session.

Each Way starts from the same task and repository snapshot. Run common repository Checks; compare Outcome, Route, available diff, cost, and an optional Judge; then Keep one passing result. Ways strengthens a difficult decision without redefining ordinary work.

Repository control

The final response does not own Git.

The stricter several-Ways path makes the handoff explicit: Keep returns one checked result to the primary Session checkout without committing it. Last turn filters the current Git diff to paths attributed to that durable Turn; it is not a frozen per-turn patch.

Open source on purpose

The runtime is yours.

Axocoatl is Apache-2.0 licensed. There is no Axocoatl account, hosted control plane, or product telemetry. The source is the product, and local-first is a permanent constraint rather than a temporary packaging choice.

This does not mean nothing ever reaches a network. Providers, MCP servers, web search, webhooks, the optional remote sandbox, Podman image or package downloads, and the one-time Hugging Face embedding download can use the network. sandbox.network: none blocks only code and commands inside the local Podman sandbox; daemon-side integrations remain separate paths.
