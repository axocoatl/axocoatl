Install

Run it on your hardware.

Install the prebuilt release on macOS 11 or newer, on GNU/Linux with glibc 2.35 or newer, or inside WSL2 on Windows (not yet verified). Then axocoatl onboard sets up a writer and a reviewer, and asks before each download or change. Every Session and run uses Podman as its sandbox. Onboarding installs Podman with Homebrew on an Apple-silicon Mac, or with apt, dnf, pacman or zypper on Linux. On an Apple-silicon Mac without Homebrew it points to the podman.io installer, on an Intel Mac to the Podman 5.8 package, and on another Linux it says what to install; it refuses Ubuntu 22.04 and older. On a Mac it then creates and starts the Podman machine.

Recommended

Install the latest release.

The installer detects macOS or GNU/Linux on x86_64 or ARM64, downloads the matching GitHub release, and requires and verifies its published SHA-256 file. Before download it requires Linux to report glibc 2.35 or newer and macOS to report version 11 or newer.

curl -fsSL https://axocoatl.ai/install.sh | sh

Run it in Terminal on macOS, in a Linux shell, or inside WSL2 on Windows, not in PowerShell. It installs to /usr/local/bin when that is writable, else to ~/.local/bin; when that directory is not on your PATH, it asks before adding one line to the startup files your shell reads in a new terminal and a new login, and prints the line instead when it cannot ask. Review the installer source before piping it to a shell.

What the 1.5.0 release gate verified
  • From this install command to passing runs on macOS 26.6 on Apple silicon (48 GB), with Axocoatl, Podman and Ollama uninstalled first (the downloaded models kept): onboarding installed Podman and Ollama with Homebrew and set up local models, Claude Code, Codex and OpenRouter
  • On Ubuntu 24.04 on arm64, in a VM, as a new user: onboarding installed Podman with apt and connected OpenRouter in the browser for the models the runs used; in CI, on Ubuntu 24.04 on x86_64 and arm64, onboarding with no terminal against a scripted model server
  • fix passed on Node.js, Python, Rust and Go repositories on each; fix-claude-code and fix-codex on Node.js and Python; every receipt verified
What is not yet verified
  • Intel Macs
  • Macs with less than 48 GB, for local models
  • Ubuntu 22.04, Debian 12 and Fedora with SELinux
  • WSL2 on Windows
Before you start

What it needs, and what it downloads.

Every run has a writer, which changes the code, and a reviewer, a different model that only reads. axocoatl onboard sets both up and writes them as the defaults for axocoatl run.

Requirements
  • Rootless Podman for every Session and run. On a Mac it runs in a Linux virtual machine. Onboarding asks before installing Podman with Homebrew on Apple silicon or with a package manager it knows on Linux, and otherwise names the installer; it asks before creating the machine. Docker is not supported; Podman can run alongside it.
  • A writer: Claude Code (a Claude Pro or Max plan, and the claude CLI on this computer), Codex (signed in with your ChatGPT plan), or a local model through Ollama
  • A reviewer: a local model through Ollama 0.40.6 or a later 0.x release (GGUF models; a release newer than the audited 0.40 line serves a model only after the contract probes pass for it, and the receipt marks it unaudited), or a hosted one paid with OpenRouter credits
  • For --keep pr: git, the gh CLI signed in, and a GitHub remote
Memory for local models
  • Models already on your Ollama server come first: when they include a pair that fits this computer, onboarding suggests those
  • Otherwise, 48 to 95 GB: onboarding offers the local pair, qwen3-coder:30b writing and gpt-oss:20b reviewing; a fix run calls the reviewer only after the writer and the checks finish. The pair ran end to end on a 48 GB Mac in the 1.5.0 release gate
  • Otherwise, less than 48 GB: onboarding has no default local pair, and first offers OpenRouter for the reviewer or both, or Claude Code or Codex as the writer
  • gpt-oss:120b, the reviewer we measured, needs about 96 GB of memory or more
What gets downloaded
  • The Podman machine image on a Mac: about 0.9 GB
  • The Claude Code image: about 0.6 to 0.9 GB; the Codex image: about 0.8 to 1.2 GB
  • Local models: qwen3-coder:30b 18.6 GB, gpt-oss:20b 13.8 GB (gpt-oss:120b 65.4 GB)
  • The first daemon start downloads an 87 MB embedding model from huggingface.co
  • A run's sandbox pulls its base image and packages the first time

First run

Configure Axocoatl, then open your work.

onboard sets up Axocoatl once for the current OS user: Podman and its machine where it can install them (otherwise it says what to install), the writer (Claude Code or Codex signed in through your browser, or local models), and a reviewer. It asks before each download or change, and writes the user configuration and data location; it does not create a project folder, Workspace, Session, or repository. doctor checks the sandbox, the models, the writers and the daemon and reports the exact fix for each failure. dev starts the daemon, IPC server, and browser app.

In the local app, choose Open workspace… to authorize the repository you want to use (a Workspace is a repository folder you named and authorized), then create a Session, one durable work item with its conversation and record. Review its proposed runtime and setup command before anything in the repository runs. Before the first native turn, open Team & budget, set the limits and expiry, and Apply.

Headless

Run a loadout from your shell.

A loadout is a YAML recipe for one run: the Agents and their models, the checks that must pass, the reviewer, the network, the budgets and the prompt. axocoatl run hands one to a running daemon (axocoatl dev or the service) and never starts one. It prints a summary, writes JUnit, a record bundle and the run's signed receipt when asked, and exits with a code a script can act on: 0 pass, 1 a check failed, 2 needs attention.

The built-in fix loadout runs one writer, your repository's check command and a review by a different model. With a local or OpenRouter writer it uses the writer and reviewer onboarding set up; with Claude Code or Codex as the writer, run fix-claude-code or fix-codex instead, with the same flags (below). --model writer=… or --model reviewer=… chooses others for one run.

The run detects the repository's language from package.json, pyproject.toml or requirements*.txt, go.mod or Cargo.toml, runs in that language's official image, and installs the dependencies, such as npm ci or pip install -e '.[test]', with only that ecosystem's package registries open for that step; then the writer works, and the host runs the check, such as npm test, pytest or go test ./.... Claude Code or Codex

Put an external agent in the sandbox.

The built-in fix-claude-code and fix-codex run fix with the Claude Code CLI or the Codex CLI as the writer. It runs inside the Session container as a non-root user; its credential stays on your computer, and the daemon adds it on the host to each model request the route allows. Claude Code needs a Claude Pro or Max plan and the claude CLI on this computer; Codex signs in with your ChatGPT plan. Both run in an image that adds the program to your repository's toolchain, with the dependencies installed first, so the repository's own check, such as npm test, pytest or go test ./..., runs as it does for fix.

  1. Set it up with onboarding

    Run axocoatl onboard and choose Claude Code or Codex as the writer. It builds the program's Session image with Podman, signs you in through your browser without showing you a token, and sets up a reviewer. To do the same by hand: axocoatl recipe build claude-code and axocoatl connect claude-code (it runs claude setup-token), or axocoatl recipe build codex and axocoatl connect codex (your ChatGPT sign-in, in a browser).

  2. Run it

    axocoatl run fix-claude-code --task "Paging skips the last item"
axocoatl run fix-codex --task "Paging skips the last item"

    The host runs the checks and the review on what the program leaves, as for any writer. The review uses the reviewer onboarding set up; --model reviewer=… names another. The run says which stored credential it sent.

  3. Or write your own loadout

    To change the model, the budgets or the checks, save a loadout with runtime: claude-code or runtime: codex in the loadouts directory beside your configuration: ~/Library/Application Support/Axocoatl/loadouts/ on macOS, ~/.config/axocoatl/loadouts/ on Linux. The docs have one to copy.
