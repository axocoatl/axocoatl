Install

Run it on your hardware.

Use a prebuilt release on GNU/Linux with glibc 2.35 or newer, or on macOS 11 or newer. Windows runs through WSL2. Axocoatl needs Podman for the default local Session sandbox.

Recommended

Install the latest release.

The installer detects GNU/Linux or macOS on x86_64 or ARM64, downloads the matching GitHub release, and requires and verifies its published SHA-256 file. Before download it requires Linux to report glibc 2.35 or newer and macOS to report version 11 or newer.

curl -fsSL https://axocoatl.ai/install.sh | sh

Review the installer source before piping it to a shell.

Requirements
  • GNU/Linux with glibc 2.35+, or macOS 11+
  • Windows through WSL2
  • Rootless Podman for local Session sandboxes and loadout runs
  • A reviewed local Ollama or OpenRouter-credit profile for Axocoatl's own Agents
  • For Claude Code: the claude CLI on your computer, to sign in

First run

Configure Axocoatl, then open your work.

onboard configures Axocoatl once for the current OS user. It writes the user configuration and durable data location; it does not create a project folder, Workspace, Session, or repository. doctor validates configuration and data access, checks provider prerequisites and Podman readiness, and reports the exact fix for failures. dev starts the daemon, IPC server, and browser app.

In the local app, choose Open workspace… to authorize the repository you want to use (a Workspace is a repository folder you named and authorized), then create a Session, one durable work item with its conversation and record. Review its proposed runtime and setup command before anything in the repository runs. Before the first native turn, open Team & budget, enter explicit limits and expiry, review the provider profile, and Apply.

Headless

Run a loadout from a shell or CI.

A loadout is a YAML recipe for one run: the Agents and their models, the checks that must pass, the reviewer, the network, the budgets and the prompt. axocoatl run hands one to a running daemon (axocoatl dev, axocoatl serve or the service) and never starts one. It prints a summary, writes JUnit and a record bundle when asked, and exits with a code a script or CI job can act on: 0 pass, 1 a check failed, 2 needs attention.

The built-in fix loadout runs one writer, your repository's check command and a review by the model you name as reviewer. A data directory an earlier Axocoatl used needs axocoatl session upgrade --confirm before its first run.

axocoatl run reference →
a fix run with two local models
axocoatl dev    # in one shell; leave it running

# in another, in the repository
axocoatl run fix --task "…" \
  --model writer=ollama:qwen3-coder:30b \
  --model reviewer=ollama:gpt-oss:120b \
  --junit axocoatl-junit.xml \
  --record run.axorecord.jsonl
axocoatl record verify run.axorecord.jsonl
Claude Code or Codex

Put an external agent in the sandbox.

The Claude Code CLI or the Codex CLI can be a loadout's writer. It runs inside the Session container as a non-root user; its credential stays on your computer, and the daemon adds it on the host to each model request the route allows.

  1. Build the recipe image

    axocoatl recipe build claude-code or axocoatl recipe build codex builds a Session image with the pinned CLI through Podman and records it in the data directory. Run it with the daemon's --config or AXOCOATL_DATA_DIR.

  2. Sign in, without handling a token

    axocoatl connect claude-code runs claude setup-token and stores the token it prints without showing it. axocoatl connect codex runs codex login in a throwaway container and stores your ChatGPT sign-in; with --api-key it also stores the OpenAI API key OpenAI issues with that sign-in, when it issues one.

  3. Write a loadout

    Save a loadout with runtime: claude-code or runtime: codex in the loadouts directory beside your configuration: ~/Library/Application Support/Axocoatl/loadouts/ on macOS, ~/.config/axocoatl/loadouts/ on Linux. The docs have one to copy.

  4. Run it

    axocoatl run fix-claude-code --task "…" \
  --model writer=anthropic:<model> \
  --model reviewer=ollama:gpt-oss:120b

    The host runs the checks and the review on what the program leaves, as for any writer.
