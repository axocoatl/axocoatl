Axocoatl v1.1 · open source · local-first

Agent work
that holds up.

Axocoatl is a local-first harness for coding agents in real repositories, on local models through Ollama or hosted models through OpenRouter. A lead Agent writes; read-only helpers answer its questions and review its work. A team can require checks and a review that the host runs before a turn completes. Every activation, tool call, and budget decision stays with one durable Session, next to the repository, Terminal, Preview, and Git review.

Lead and helpers

One writer. Helpers that read.

New configurations start with a Lead that edits files and two read-only helpers it can delegate to: Scout answers questions about the code, Reviewer reviews a change. Each helper starts in an empty conversation, answers one task, and hands the answer back. Several can run at once. You approve every limit in Team & budget before the first request.

Add required checks and the host runs them after the Agents finish, each between two captures of the repository. Add a required review and the host runs a read-only reviewer on the result; requested changes go back to the lead for a bounded number of rounds. The turn completes only when they pass on the exact final tree. Helpers get no file-writing tools, and their shell runs under a Linux Landlock write restriction where available; otherwise they get no shell.

Compare real Ways.

The lead and its helpers, or one Agent, remain the direct path. When the implementation is genuinely uncertain, the same Session can give one task and repository snapshot to several Agent/model pairs. Each Way works in an isolated checkout and sandbox.

The smaller front door

One executable. Your browser.

Install one axocoatl executable. It starts the local Rust daemon and serves the workbench to the browser you already use. The workbench assets are embedded, so using Axocoatl requires no separate frontend install or bundled browser runtime. Podman remains the local sandbox requirement for repository Sessions.

Configure Axocoatl once for the current OS user; onboarding creates no project. Tools run in a rootless Podman container. Network access is on by default; set network: none for repositories you don't trust. Remote providers, integrations, downloads, and E2B Cloud are explicit network paths. Local-first is the default, not an offline guarantee.

Small local models get specific handling: an Ollama stream that ends early is retried once, older tool output is replaced by a short placeholder in later requests, and a request that would overflow the context window is trimmed instead of failing.
