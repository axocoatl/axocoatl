One durable work surface

A final answer is not enough.

Repository work crosses context, files, commands, previews, failures, restarts, and review. Axocoatl keeps the accepted work and execution record with one folder-anchored Session while the current repository remains visible beside it.

Turn

Accept first

Each Turn records its request and context before the Agent starts. Output, bounded tool evidence, failure, cancellation, and interruption remain attached to the Session.

Route

Show the execution

Open Files, Terminal, Preview, and Source Control around the conversation. History keeps the bounded Route and final lifecycle; the working tree shows what exists now.

Git

Review the change

Run repository Checks, inspect paths and hunks, and filter Source Control to the latest attributed Turn. Stage and commit only when the result holds up.

When the decision needs evidence

Compare real Ways.

One Agent or a configured team remains the direct path. When the implementation is genuinely uncertain, the same Session can give one task and repository snapshot to several Agent/model pairs. Each Way works in an isolated checkout and sandbox.

Run the same repository Check. Compare Outcome, Route, available diff, cost, and an optional Judge while the decision is open. Keep one passing, non-empty result for Git review, or finish without keeping any of them.

The smaller front door

One executable. Your browser.

Install one axocoatl executable. It starts the local Rust daemon and serves the workbench to the browser you already use. The workbench assets are embedded, so using Axocoatl requires no separate frontend install or bundled browser runtime. Podman remains the local sandbox requirement for repository Sessions.

Configure Axocoatl once for the current OS user; onboarding creates no project. Remote providers, integrations, downloads, and E2B Cloud are explicit network paths. Local-first is the default, not an offline guarantee.
