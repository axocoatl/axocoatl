What you can rely on

Mechanisms, not promises.

Trust here means things the host does whatever the model says: where tools run, who may write, which checks must pass, what a run may spend, and what gets recorded.

Isolation built in

Tools run in a sandbox

Every Session's tools run in a rootless Podman container. Read-only helpers cannot write or connect out: they get no file-writing tools, and the kernel blocks their shell from changing the repository or opening TCP connections (Landlock, Linux 6.7 or later); otherwise they get no shell. Per-Agent write scopes share one checkout, and every change is checked against complete, digest-verified snapshots. Network access is on by default; set network: none for repositories you don't trust.

A complete record

The host decides, and keeps it

Required checks run on the exact final files, by the host, not the model. A required review runs a read-only reviewer the host starts. Budgets you approve are charged with what each call actually used and carry across restarts. Every model call, tool call, budget decision and check stays in the Session.

Any model, per Agent

Local or hosted

Each Agent has its own provider and model: local models through Ollama, hosted models through OpenRouter, with budgets enforced on both. Anthropic, OpenAI, Gemini and Mistral adapters are included on the compatibility path. Small local models get specific handling: a stream that ends early is retried, and a request that would overflow the context is trimmed instead of failing.

Team & budget → Required review → reviewer
Cross-model review

A local writer. A stronger reviewer.

Give the reviewer template a different model, on the same machine or through OpenRouter, and make it the team's required reviewer. After the lead finishes and your checks pass, the host starts the reviewer in a fresh conversation on the exact result. Requested changes go back to the lead; the turn completes only when the reviewer approves.

Reviewers raise false alarms too. Tell the lead to check each reported defect against the requirements before changing code, and to fix only the ones the requirements support.

One writer

The lead writes. Everything else reads.

A new Session starts with one Agent, the lead, under limits you approve in Team & budget. You can let it delegate to read-only helpers: Scout answers questions about the code, Reviewer reviews a change. Each helper starts in an empty conversation and hands one answer back. Helpers cost extra tokens; one Agent is the cheaper choice for small tasks.

Add required checks and the host runs them after the Agents finish, between two captures of the repository. Add a required review and the host runs a read-only reviewer on the result for a bounded number of rounds. The turn completes only when both pass on the exact final tree.

The record sits beside the repository.

Each Session keeps its conversation, accepted Turns, Agent activity, and budget decisions, while Files, Terminal, Preview, and Source Control show the repository as it is now.

Turn

Each Turn records its request and context before the Agent starts. Output, tool evidence, failure, cancellation, and interruption remain attached to the Session.

Review the change

When the decision needs evidence

Compare real Ways.

When an implementation is genuinely uncertain, the same Session can give one task and repository snapshot to several Agent/model pairs. Each Way works in its own checkout and sandbox. Run the same Check, compare Outcome, Route, diff and cost, and Keep one result for Git review, or none.

Your machine or your infrastructure

One executable. Your browser.

Install one axocoatl executable. It starts the local Rust daemon and serves the workbench to the browser you already use; the workbench assets are embedded. Podman is the local sandbox requirement for repository Sessions. Run it on a laptop, or as a service on a machine you control.

Configure Axocoatl once for the current OS user; onboarding creates no project. Hosted providers, integrations, downloads, and E2B Cloud are explicit network paths. Local-first is the default, not an offline guarantee.

Run it on a real repository.

Install Axocoatl, open a Workspace, pick a model for each Agent, and let the host's checks decide when the work is done.
