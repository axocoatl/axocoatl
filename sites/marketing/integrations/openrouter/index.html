Use OpenRouter with your agents.

Add one provider credential, then assign any model identifier available to your OpenRouter account to the configured agents that work inside your Sessions.

First run

Configure OpenRouter once.

Run axocoatl onboard and choose OpenRouter. The API-key prompt is masked. A supplied key is stored with the provider and starting Agent in the current user's owner-only Axocoatl configuration.

Onboarding creates no project folder or repository. After axocoatl dev opens the workbench, choose Open workspace… and select the repository you want to use. Model availability, pricing, routing, and account access remain controlled by OpenRouter.

first run
axocoatl onboard  # choose OpenRouter
axocoatl doctor   # verify configuration
axocoatl dev      # open the workbench
Use it in the workbench

Choose the model for the job.

Agents are configuration records. Assign OpenRouter, a direct hosted provider, or Ollama to each role, then select the right Agent from the Session.

Roles

Different agents, different models

Use a focused model for a narrow builder and a larger model for a coordinator or difficult repository task.

Hybrid

Local and hosted together

Keep one Agent on Ollama and another on OpenRouter. Optional Ways can compare configured agents when the decision merits it.

Cost

Configure prices honestly

Within Ways, when remote pricing is not configured, Axocoatl marks the known subtotal as incomplete instead of treating the call as free.

Advanced configuration

Keep environment injection explicit.

If you prefer process-environment injection, leave the key blank during onboarding or manage an explicit YAML configuration. Export OPENROUTER_API_KEY in the process that starts Axocoatl and pass an explicit configuration path when it is not the user default.

Axocoatl does not load dotenv files automatically. Protect environment files, explicit configurations, shell history, and backups as secrets.

advanced axocoatl.yaml
providers:
  openrouter:
    api_key: "${OPENROUTER_API_KEY}"

agents:
  - id: builder
    provider: openrouter
    model: "${OPENROUTER_MODEL}"
Attribution

The client identifies Axocoatl.

Calls to the OpenRouter endpoint include HTTP-Referer: https://axocoatl.ai and X-Title: Axocoatl. These headers identify the calling application. They do not imply a directory listing, rank, partnership, or endorsement.
