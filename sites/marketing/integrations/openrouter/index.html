Integration

Axocoatl × OpenRouter.

One OpenRouter config block, with a model id pinned per agent. Model availability and access come from your OpenRouter account. Axocoatl can also retry once against one configured backup on an initial rate limit.

Why pair them.

OpenRouter exposes models from multiple upstream providers through one OpenAI-compatible endpoint. Use a model id available to your account, and choose different ids for different agents or attempt lanes without adding a separate Axocoatl provider adapter for each upstream.

Axocoatl handles the orchestration. OpenRouter handles the inference. Pair them and you get a self-supervising runtime on your infrastructure that can use an OpenRouter model for one agent and a local Ollama model for another.

Configure the provider.

Add an openrouter block to your axocoatl.yaml: 

providers:
  openrouter:
    api_key: "${OPENROUTER_API_KEY}"

agents:
  - id: researcher
    provider: openrouter
    model: "${OPENROUTER_RESEARCH_MODEL}"
  - id: summarizer
    provider: openrouter
    model: "${OPENROUTER_SUMMARY_MODEL}"      # Two current catalog ids, one config.

Put OPENROUTER_API_KEY=… in your .env, and set the two model variables to ids currently available to your OpenRouter account. Restart the daemon.

Or do it through onboard.

Select OpenRouter when the interactive setup wizard asks which provider to configure:

axocoatl onboard
Patterns

Three setups we recommend.

Cost-tier routing

Use openai/gpt-4o-mini on every agent by default. Promote individual agents to another model id when they need a different capability. The agent configuration or attempt lane selects the model; the lattice does not choose it dynamically.

Local + cloud hybrid

Ollama for cheap, repetitive agents (summarization, classification). OpenRouter for the one agent that needs frontier intelligence. Same workflow, two providers.

One rate-limit backup

Primary provider = OpenRouter. Fallback = direct Anthropic credentials. If the initial OpenRouter request returns the runtime's rate-limit error before streaming starts, the daemon retries once on that configured provider/model. Other failures are returned.

OpenRouter attribution.

Axocoatl's OpenRouter client attaches the documented HTTP-Referer: https://axocoatl.ai and X-Title: Axocoatl attribution headers. Those headers identify the calling app to OpenRouter. Directory eligibility and listing are controlled by OpenRouter; Axocoatl does not claim a current directory position or traffic rank.

We're not optimizing for that leaderboard at the expense of the local-first commitment. Ollama remains the default recommendation in axocoatl onboard. OpenRouter is the cloud option for teams who don't want to manage their own LLM keys per provider.
