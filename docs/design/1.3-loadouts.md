# Axocoatl 1.3.0: loadouts, headless runs, fix/qa/audit, external agents, e2e, Keep as PR

Status: approved scope, one release, built in parallel workstreams from the skeleton commit
on `release/1.3.0`. This document is the contract between the workstreams. Where it and the
skeleton code disagree, the code's types win and the owner of the file fixes this document.

Base: `release/1.3.0` at `e450fd8` (1.2.0 plus the unreleased fixes: reasoning models,
per-request reservations, null browser arguments, 1,024 tool rounds, team continue,
segmented Session stores).

### Invariants every workstream keeps

1. **Isolation is never weakened.** Global defaults do not change (`sandbox.network` stays
   `bridge` unless the person sets it). A loadout Session runs under `network: egress` (or
   `none`) with the hardened workload (`writer_user` / `helper_user`, non-root, commands
   under the supervisor's `--harden`). A loadout cannot ask for `bridge` or `image`. If the
   host cannot provide that (rootful Podman, no egress sidecar, E2B backend), the run fails
   with exit 5 and says why; it never falls back.
2. **Credentials never enter a container.** Model and service credentials reach upstreams
   only through egress routes; the container holds a placeholder. Secrets are read from
   stdin by `axocoatl secret set`, never from argv, never logged, never in the record.
3. **Every connection is recorded.** Every model call of an external agent, e2e's agent, the
   explorer's browser and the host Ollama route lands in the Session's network record.
   Nothing reaches the host unless an explicit route allows it.
4. **Nothing is silently a pass.** A failed helper, slot, area, provider call, check or
   reproduction is recorded and surfaced in the Outcome (`not_covered`, `checks`,
   `attention`), and changes the exit code.
5. **Claims are measured.** Numbers measured with Claude Code subagents are labeled as such
   and never presented as Axocoatl results.
6. **No `todo!()`/`panic!` stubs.** Unfinished hooks return explicit "not implemented"
   errors (`DaemonError::NotImplemented`, `RunError::NotImplemented`, per-module
   `NotImplemented` variants). HTTP maps them to 501. A workstream is done when none of its
   stubs remain.
7. **Do not edit** `crates/axocoatl-exec/src/{protocol,supervisor,lib,main}.rs` or `build.rs`
   (any byte change forces an embedded-supervisor rebuild and re-pin). If a workstream
   truly must, it says so in its result.

## 1. Loadout file

Schema `axocoatl.loadout/1`. Parser, validation and resolution:
`crates/axocoatl-config/src/loadout.rs` (implemented in the skeleton, owner `core`).
Unknown fields are refused everywhere (`deny_unknown_fields`). Files are at most 64 KiB.

### 1.1 Fields

| Field | Type | Rules |
|---|---|---|
| `schema` | string | exactly `axocoatl.loadout/1` |
| `id` | string | `[a-z][a-z0-9-]{0,63}`; a user loadout may not reuse `fix`, `qa`, `audit` |
| `version` | u32 | the loadout's own version, from 1 |
| `name`, `description` | string | name non-empty |
| `kind` | `fix` \| `qa` \| `audit` \| `custom` | selects the run driver |
| `opt_in` | bool | listed, but runs only when named explicitly (`audit`) |
| `params` | map name → `{kind: model\|text\|url, required, default, description}` | names `[a-z][a-z0-9_-]{0,31}`; a required param has no default; model defaults parse as `provider:model` |
| `agents[]` | see below | 1 to 8 |
| `checks[]` | see below | 0 to 16, unique names |
| `review` | `{model, rounds 1-3, tools (read-only), instructions, max_output_tokens, adjudicate (default true)}` | reviewer tools ⊆ `read_file, list_dir, grep, glob, workspace_knowledge` |
| `egress` | `{allow: [EgressAllowYaml], private_destinations: [cidr]}` | same shapes as `sandbox.egress` |
| `routes[]` | `EgressRouteYaml` (same as `sandbox.egress.routes`) | `credential` names a `credentials` entry or a stored secret |
| `budgets` | `{agent: Limits, reviewer: Limits?, wall_clock: "60m"}` | Limits = `{activations, invocations, tokens, cost_usd}`, each ≥ 1 (cost 0-10,000); reviewer limits required with `review` |
| `prompt` | string | must contain `{task}`; other placeholders: `{repo}`, `{target_url}`, `{reference_url}` |
| `sandbox` | `{network: egress\|none (default egress), workload: hardened}` | `bridge` and `image` refused; `none` refuses `egress.allow` and `routes` |
| `environment` | `{image \| recipes: [..], setup}` | image xor recipes; `setup` is the exact command a run approves |
| `qa` | `{target_url, reference_url?, repro_dir, fail_on_findings (default true)}` | qa only |
| `audit` | `{min_areas, max_areas, fail_on_findings (default false)}` | audit only; 2 ≤ min ≤ max ≤ 8 |

`agents[]`:

| Field | Rules |
|---|---|
| `id` | `[a-z][a-z0-9-]{0,31}`, unique |
| `role` | `writer`, `explorer`, `planner`, `worker`, `integrator` |
| `model` | `{provider, model}` or `{param: name}` (a `model` param); an external writer's provider is the one whose API its program calls (`anthropic` for `claude-code`, `openai` for `codex`, `AgentRuntime::model_provider`), refused otherwise by validation (literal) and resolution (parameter) |
| `runtime` | `native` (default), `claude-code`, `codex`; external runtimes only for `writer` |
| `tools` | required for native Agents |
| `writes` | omitted = every path (writer only); `[]` = read-only; planners, workers and integrators must be `[]` |
| `instructions`, `max_output_tokens`, `reasoning_effort`, `budget` (Limits), `depends_on` | `depends_on` names other Agents of the loadout |

`checks[]`: `{name, run, timeout}` where `run` sets exactly one of `argv: [..]`,
`shell: "cmd" | {param}`, `detected: true` (the Session's detected check command, or
`--check`), `e2e: {args, model_route, model}`; `timeout` is a duration (`90s`, `3m`, `1h`),
default 3 minutes, at most 30 minutes.

Per-kind rules (`validate_kind`):

- `fix`: exactly one Agent, a writer; a `review`; at least one check; no `qa`/`audit`.
- `qa`: exactly one Agent, an explorer listing `browser` and `browser_check`, whose
  `writes` is exactly `["<repro_dir>/**"]`; a `qa` section; no review, no `audit`. No
  scouts, no merge, no verifier.
- `audit`: exactly one planner, one worker, one integrator; none lists `write_file` or
  `edit_file`; an `audit` section with areas within 2-8.
- `custom`: at most one writer; no `qa`/`audit` sections.

Warnings (`LoadoutWarning {code, field, message}`): `same_model_reviewer` when the review's
model equals a writer's model, statically and again after parameters resolve.

### 1.2 Parameters and resolution

`resolve_loadout(&Loadout, &ParamValues, task, repo) -> ResolvedLoadout` replaces every
`{param}` reference. Unknown parameter names are refused (a typo never runs with a
default). Missing required parameters are `LoadoutError::Param` (exit 3). Model values are
`provider:model`, split at the first `:` (`ollama:qwen3:32b`,
`openrouter:anthropic/claude-sonnet-5.5`). `axocoatl run --model writer=...` is sugar for
`--param writer_model=...`. `detected` and `e2e` checks resolve to `argv: None`; the daemon
fills `detected` from the Session (or `--check`) and `e2e` expands through
`loadout::e2e::expand_e2e_check`.

`fix.yaml` (owner `review-qa`):

```yaml
schema: axocoatl.loadout/1
id: fix
version: 1
name: Fix
kind: fix
params:
  writer_model:   { kind: model, required: true, description: provider:model of the writer }
  reviewer_model: { kind: model, required: true, description: provider:model of the reviewer (use a different model than the writer) }
agents:
  - id: writer
    role: writer
    model: { param: writer_model }
    tools: [read_file, list_dir, grep, glob, write_file, edit_file, bash]
    instructions: >-
      You own this change. ... When the host sends you review findings, answer every
      finding in an ADJUDICATIONS block: its id, accept or reject, and the reason.
checks:
  - { name: tests, run: { detected: true }, timeout: 3m }
review:
  model: { param: reviewer_model }
  rounds: 3
  tools: [read_file, list_dir, grep, glob]
  adjudicate: true
  instructions: >-
    ... Number each finding F1, F2, ... with file:line and the defect. End with
    VERDICT: APPROVE or VERDICT: CHANGES. Change nothing.
budgets:
  agent:    { activations: 4, invocations: 400, tokens: 4000000, cost_usd: 10 }
  reviewer: { activations: 3, invocations: 120, tokens: 1500000, cost_usd: 3 }
  wall_clock: 60m
prompt: |
  {task}
sandbox: { network: egress, workload: hardened }
```

## 3. Storage and loading

- **Built-in loadouts**: compiled in; `builtin_loadouts()` parses them; a parse failure is a
  bug caught by the config tests. Source `LoadoutSource::Builtin`.
- **User loadouts**: `*.yaml`/`*.yml` directly in `<config dir>/loadouts/` where the config
  dir is the directory of the configuration file the daemon started with (on macOS
  `~/Library/Application Support/Axocoatl/loadouts/`). `load_user_loadouts(dir)` reads at
  most 128 files, sorted, regular files only (symlinks refused), ≤ 64 KiB. A file that fails
  to parse or reuses a built-in id is listed with its error and cannot run. Read on each
  `GET /api/loadouts` and each run admission (no cache; the file set is small). The digest
  is SHA-256 of the exact bytes; the run manifest keeps the exact text, so a later edit of
  the file never changes what a finished run's record says it ran.
- **Run record**: `{data root}/loadout-runs/{run_id}/` (`run_id` = `run-<uuid v4>`):
  `manifest.json` (written once, `RunManifest`), `events.jsonl` (append-only, one synced
  JSON line per `RunEvent`, ≤ 256 KiB per line, ≤ 100,000 events), `outcome.json` (written
  once). Through `SecureDir` like every other store (no symlinks, owner-only, atomic
  create). Runs are never evicted; deleting the Session does not delete the run record
  (it is the audit trail); a later `axocoatl record` sub-command may delete one explicitly
  (out of scope for 1.3).
- **Session binding**: `Session.loadout = Some(SessionLoadoutBinding {run_id, loadout,
  network, workload})`. Persisted with the Session. Every place the daemon reads
  `self.config.sandbox.network` or the workload plan *for a Session* goes through one
  helper, `AxocoatlDaemon::session_sandbox_policy(&Session) -> (network, WorkloadPlan,
  EgressPolicyConfig)` (core, `bootstrap.rs`), which returns the global values for an
  unbound Session (unchanged behavior) and the bound values otherwise
  (`WorkloadPlan::Hardened { required: true }`).
- **Secrets**: `{data root}/secrets/<name>`, 0600, atomic replace, name rule as
  `is_valid_credential_name`; values ≤ 8 KiB without control characters (the broker's
  `MAX_SECRET_BYTES` rule). A route credential name resolves to `credentials.<name>` in the
  config first, then to `CredentialSource::File(secret_path(..))` when that file exists.

## 4. A run, end to end

1. **Admission** (`admit_loadout_run`, core). Look up the loadout (built-in or user; an
   `opt_in` loadout runs only when named, which `axocoatl run audit` does). Resolve
   parameters (exit 3 on error). Canonicalize `repo`; find or create its Workspace (the
   existing path-based find-or-create). Create a native Session with `loadout` binding
   (network from `sandbox.network`, `workload: hardened`). Environment: the loadout's
   `environment.image` or the recipe image (`recipes`), and exactly the loadout's `setup`
   (or `--setup`) marked approved and reviewed; a detected command such as `npm ci` is
   never approved by a run. Wait for the environment to become Ready (bounded by the wall
   clock); `failed` → exit 5 with the bounded setup output. When the loadout has a
   read-only Agent or reviewer with a tool that reads the Workspace (every audit Agent),
   probe the Ready container exactly as a helper's commands run (`cd` into and list the
   repository, launched by the supervisor through the helper's view): a view that cannot
   enter it (a repository another user owns), or a container or kernel that cannot give
   the view (no Landlock ABI 3; a container from an earlier build without root's
   `CAP_DAC_READ_SEARCH`) → exit 5 naming why. The helper's view (supervisor
   `--helper UID:GID --writer UID:GID --workspace PATH`): the supervisor starts as root
   and launches the command as `helper_user` with `CAP_DAC_READ_SEARCH` alone (ambient,
   bounding set, locked `SECBIT_NOROOT` and `SECBIT_NO_SETUID_FIXUP`, no-new-privileges),
   in a Landlock domain that handles reading and every write right (ABI 3, Linux 6.2):
   read/list/execute beneath the Workspace, and elsewhere only what any user may read
   at launch (system directories walked entry by entry: a sealed, all-readable
   directory gets one rule; otherwise its readable entries do, and it gets a list-only
   rule when nothing beneath it is private), plus devices and global `/proc` files;
   never `/home`, `/root`, `/tmp`, `/var/tmp`, `/dev/shm`, `/run` or `/proc/<pid>`.
   Writes: the file tools (no `WriteRestriction`) only open `/dev/null` for writing
   and get no scratch directory (`HOME=/nonexistent`, no `TMPDIR`); the shell (a
   `WriteRestriction`, whose `writable` roots a helper does not get) everything
   beneath a per-command scratch directory (`HOME`, `TMPDIR`, removed afterwards) and
   write-only opens of `/dev/null`, `/dev/zero`, `/dev/tty` and `/dev/urandom`. Its
   seccomp filter adds `AF_UNIX` sockets (connected pairs, `SOCK_STREAM` and
   `SOCK_SEQPACKET`, allowed: Rust's `std::process` uses the latter), `inotify_add_watch`,
   `fanotify_init`, `fanotify_mark` and the `setxattr`/`removexattr` family, which
   Landlock does not cover and the capability would extend, and every System V IPC and
   POSIX message queue call (`shm*`, `msg*`, `sem*`, `mq_*`: objects outside any
   Landlock path, shared by the container's users and kept after the command); the file
   tools' filter also refuses `chmod`, `chown` and `utime` calls of every form and
   `socket` of every family (they run without the shell's Landlock TCP rule, so this
   keeps them off the egress relay on `127.0.0.1:3128` on any kernel). The Workspace is
   opened `O_NOFOLLOW` and must be a directory, and the supervisor refuses `--helper`
   without `--harden`. The standard pipes the
   supervisor made for the command are handed to the helper, so `/dev/stderr` opens.
   So a Linux `0700` repository (`mktemp -d`, `umask 077`) reads as any other; an
   idmapped view is not possible under rootless Podman (`mount_setattr` needs
   `CAP_SYS_ADMIN` over the Workspace's filesystem). Write the manifest (with
   `repo_head` and `dirty_paths` from host git). Idempotent on `request_id`.
2. **Driver task** (server, core): `tokio::spawn` with a `DaemonRunHost` (AppState clone);
   `driver::run_to_outcome(host, ctx)` calls `driver_for(kind).drive(host, ctx)`, then
   builds the Outcome, calls `RunOutcome::decide`, writes `outcome.json` and the `Ended`
   event. A daemon restart while a run is unfinished marks it `failed` with the reason
   "the daemon restarted during the run" (its turns are interrupted by existing recovery);
   it is never resumed silently.
3. **Team**: `team_plan::team_edit(resolved, slots, with_checks_and_review, rev)` builds the
   `SessionTeamEdit`:
   - one slot per `SlotPlan` (`slot_id`, `template_id: None`, provider/model from
     `ModelSpec`, `instructions`, `writes`, `max_output_tokens`, `required`,
     `reset_history: true`, limits from `budget`/`budgets.agent` with
     `cost_microunits = cost_usd × 10⁶`, `expires_at_ms = now + wall_clock`);
   - native Agents' definitions come from the loadout, not from configured Agent templates:
     core adds an inline-definition path to Apply in `bootstrap_session_team.rs`
     (`template_id: None` plus the loadout definition retained as the slot's definition
     evidence, tools from the loadout);
   - `required_checks` = each resolved check's argv, `check_options` = name, `timeout_ms`,
     `report` (aligned by index);
   - `required_review` = reviewer template synthesized from `review` (role Worker, `writes:
     []`, the review tools), `max_rounds = rounds`, `limits` = `budgets.reviewer`;
   - `dependencies` from `depends_on`.
   Applying goes through the existing preview → apply path, so every grant, write scope and
   readiness rule of 1.2 applies unchanged.
4. **Turn**: `send_turn(session, resolved.prompt)`; `wait_turn` until a terminal state or the
   deadline (deadline → `stop_turn`, `budget_exhausted = true`).
5. **Observation**: `TurnObservation` from the turn and control-plane projections: nodes and
   their generations (answers bounded to 64 KiB each), `TurnCheckView` → `CheckResult`,
   `TurnReviewView` + `ReviewProof`s → `ReviewOutcome`, usage.
6. **Outcome** (§6) and the exit code (§5.2).

Per-kind drivers:

- `fix` (`FixDriver`, review-qa): `run_single_turn`, then adjudications (§7.1), warnings.
- `qa` (`QaDriver`, review-qa): `run_single_turn`, parse the explorer's report, re-run each
  reproduction (§7.2), coverage → `not_covered`.
- `audit` (`AuditDriver`, audit): a plan, the areas (one or more turns), follow-ups while
  each reads something new, and an integration, each a turn in one Session (§7.3).
- `custom` (`SingleTurnDriver`, core).

## 5. `axocoatl run`

### 5.1 Contract

```
axocoatl run <loadout> (--task <text> | --task-file <file|->)
             [--repo <dir>] [--junit <file>] [--record <file>]
             [--model <role>=<provider:model>]... [--param <name>=<value>]...
             [--check <cmd>] [--setup <cmd>] [--keep none|branch|pr]
             [--json] [--url <daemon url>] [-c <config>]
```

- Talks to the **running daemon** over HTTP. URL: `--url`, else `AXOCOATL_URL`, else
  `http://<server.host>:<server.port>` from the config file. Token: `AXOCOATL_TOKEN`, else
  the local API token read with `axocoatl_server::auth::read_local_token` from the data
  root, sent as `Authorization: Bearer`. It never starts a daemon and never bootstraps one
  in-process. Unreachable or 401/403 → exit 4.
- `--repo` defaults to the current directory; canonicalized by the daemon.
- `axocoatl loadouts list|show` take `--url` and `-c <config>` like `run`; `axocoatl
  loadouts validate <file>` works without the daemon (exit 0 valid, 3 invalid).
- Flow: `POST /api/runs` (fresh `request_id` per invocation) → print run id, Session id and
  warnings (stderr) → poll `GET /api/runs/{id}/events?after=` (long-poll, 1 s) printing one
  line per `Phase`, `TurnStarted/Ended`, `Warning` (each warning once), `NotCovered`,
  `ProviderRetry` to stderr → when `finished`, `GET /api/runs/{id}` → print the summary to
  stdout (or, with `--json`, the Outcome as the only thing on stdout: one JSON document,
  every other line on stderr) → `--keep branch|pr` on a passing run calls
  `POST /api/sessions/{session}/keep-pr` and prints the branch, commit and PR URL (stderr
  with `--json`; a keep failure prints the reason and exits 2) → write `--junit` from
  `GET /api/runs/{id}/junit` and `--record` from `GET /api/runs/{id}/record` (after Keep,
  so the file holds the `keep` event; both written even when the run fails, atomically:
  temp file then rename) → exit with `outcome.exit_code`. A run that was never admitted
  (refused, daemon unreachable, bad flags; no run id) still gets `--junit` from
  `run_junit::render_refused_run_junit`: the `run` suite's `verdict` case an `<error>` of
  type `busy` (exit 7), `usage` (3) or `error`, with `axocoatl.exit_code`; `--record` has
  nothing to write and stderr says so.
- Ctrl-C: `POST /api/runs/{id}/stop`, wait up to 30 s for the Outcome, write `--junit` and
  `--record`, exit 6.
- The summary always lists: verdict, each check (state, exit code, report counts), review
  verdict and rounds, adjudications (id, decision, reason), findings (with "fails on clean
  build" shown as such), every not-covered entry with its reason, the notes, warnings (the
  same-model warning included), usage (`RunUsage::text`: "known subtotal" when incomplete,
  "cost unknown (reserved up to $X)" when `cost_known` is false, and "$X (includes cost
  computed from reported tokens at list prices)" when `cost_computed`), the record id.

### 5.2 Exit codes (`axocoatl_session::run_outcome::exit_code`)

| Code | Meaning |
|---|---|
| 0 | pass: every required check passed, review (if any) approved, every finding adjudicated, nothing not covered, no finding the loadout fails on |
| 1 | a required check failed or timed out on the final candidate |
| 2 | needs attention: review not passed, missing adjudication, anything not covered, a check that never ran on the final candidate, turn needs attention/blocked, budget or wall clock exhausted, findings (`fail_on_findings`), Keep failed |
| 3 | usage: bad flags, unknown/invalid loadout, missing/unknown parameter, `opt_in` loadout not named |
| 4 | daemon unreachable, or the token refused |
| 5 | infrastructure: environment failed, sandbox could not be hardened/egressed, provider not configured, any daemon error, any `NotImplemented` |
| 6 | interrupted by the person |
| 7 | busy: another run or Session's turn holds the Workspace (admission `409` with `code: workspace_busy`, or the next turn could not start); retry later |

Precedence: 5 > 6 > 1 > 2 > 0 (`RunOutcome::decide`, implemented and tested). 7 replaces 5
when the run's error is only a busy Workspace (`RunError::Busy`, verdict `error`).

### 5.3 JUnit shape (`render_junit`, core)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<testsuites name="axocoatl" tests="7" failures="2" errors="0" skipped="1" time="512.3">
  <properties>
    <property name="axocoatl.run_id" value="run-…"/>
    <property name="axocoatl.loadout" value="fix@1 sha256:…"/>
    <property name="axocoatl.verdict" value="needs_attention"/>
    <property name="axocoatl.exit_code" value="2"/>
    <property name="axocoatl.usage" value="1200 input + 300 output tokens, $0.0123"/>
  </properties>
  <testsuite name="checks" tests="1" failures="0">
    <testcase classname="axocoatl.check" name="tests" time="41.2"/>
  </testsuite>
  <testsuite name="check:e2e" tests="2" failures="1">        <!-- one per check report -->
    <testcase classname="e2e.checkout" name="pays with a saved card">
      <failure message="expected …">…</failure>
    </testcase>
  </testsuite>
  <testsuite name="review" tests="1" failures="0">
    <testcase classname="axocoatl.review" name="required-review"/>   <!-- failure when not passed -->
  </testsuite>
  <testsuite name="adjudications" tests="2" failures="1">
    <testcase classname="axocoatl.adjudication" name="round 1 F1"><system-out>accept: …</system-out></testcase>
    <testcase classname="axocoatl.adjudication" name="round 1 F2"><failure type="missing" message="the writer did not answer F2"/></testcase>
  </testsuite>
  <testsuite name="findings" tests="2" failures="1" skipped="1">
    <testcase classname="axocoatl.finding.checkout" name="B1 total ignores coupon"><failure type="confirmed" message="…"/></testcase>
    <testcase classname="axocoatl.finding.search" name="B2 …"><skipped message="fails on clean build"/></testcase>
  </testsuite>
  <testsuite name="coverage" tests="1" failures="1">
    <testcase classname="axocoatl.coverage" name="gift cards"><failure type="not_covered" message="provider_refusal: classifier stop"/></testcase>
  </testsuite>
</testsuites>
```

After `coverage` comes one more suite, `run`, with one case `verdict`: passing for
`pass`, `<failure type="checks_failed|needs_attention">` with the attention reasons,
`<error type="interrupted|error|busy">` otherwise (`busy` for exit 7), so a CI view of the file alone never shows a
run that needs attention as green. The run's notes are that case's `<system-out>`, one
`note: ` line each, whatever the verdict. Warnings are properties `axocoatl.warning.<code>`;
usage is the property `axocoatl.usage`, worded as the summary words it
(`RunUsage::text`), so a cost the run does not know is never shown as a price, and a cost
computed from reported tokens is never shown as a provider's charge.
`render_junit_with(outcome, fail_on_findings)` takes the loadout's `fail_on_findings`
explicitly (the daemon reads it from the manifest's loadout text); `render_junit(outcome)`
reads it from the Outcome's attention reasons.

Rules: check `failed`/`timed_out` → `<failure>`, `not_run`/`unavailable` → `<error>`;
review not passed → `<failure>`; adjudication `missing` → `<failure type="missing">`,
`reject` → passing case with the reason in `<system-out>`; findings: `confirmed` and
`reproduced` → `<failure>` (only when `fail_on_findings`, else `<system-out>`),
`fails_on_clean_build`/`not_reproduced` → `<skipped>`, `repro_error`/`missing` →
`<error>`; an audit area's `unreadable_findings` entry → `<failure type="findings_unreadable">`
named `<area> (findings unreadable)` in `findings`, the worker's last answer in
`<system-out>`; every `not_covered` entry → `<failure type="not_covered">` (never skipped:
never a silent pass). Text is XML-escaped, control characters other than tab/newline removed,
each message ≤ 4 KiB, the document ≤ 8 MiB (excess cases summarized in one `truncated`
case).

### 5.4 Record bundle (`record_bundle`, core)

One JSON Lines file, `application/vnd.axocoatl.record+jsonl`, default name
`<run_id>.axorecord.jsonl`:

```
{"schema":"axocoatl.record-bundle/1","run_id":"run-…","session_id":"ses-…","created_at_ms":…,"axocoatl_version":"1.3.0"}
{"section":"manifest","data":{…RunManifest…}}
{"section":"loadout","data":{"text":"…exact YAML…","digest":"…"}}
{"section":"outcome","data":{…RunOutcome…}}
{"section":"session","data":{…Session record…}}
{"section":"team","data":{…SessionTeamView, each slot with reset_history, tools, definition…}}
{"section":"turn","data":{…control-plane projection of one turn…}}        (one per turn)
{"section":"history","data":[…the Session's versioned History export…]}
{"section":"network","data":{…one network-record event…}}                (one per event, all of them)
{"section":"run_event","data":{"seq":1,"event":{…RunEvent…}}}           (one per event)
{"section":"end","lines":N,"sha256":"<SHA-256 of every byte before this line>"}
```

Sections appear in `BUNDLE_SECTIONS` order. The writer streams (bounded memory) and holds
no daemon lock across the whole write. The header's `created_at_ms` is the Outcome's
`finished_at_ms` (`record_bundle_header`), never the download time, so `--record`,
`GET /api/runs/{id}/record` and the panel's download of a finished run are the same
bytes while its record and Session do not change (Keep appends a `keep` event; closing
the Session changes `session`); an unfinished run's bundle carries the time it was read.
`team` is `session_team_record`: the team view with each applied slot's
`reset_history` (whether Apply started it from a fresh conversation), `tools` (its
retained definition's) and, for a loadout's Agent, its inline `definition`. `history`
is the versioned export (`export_versioned_session_json`: one `{"history_version":
"execution_v2", "turn": …}` entry per turn) when the Session's History holds native
execution, as every loadout Session's does, else the legacy export. `verify_bundle`
checks the header schema, section order, `lines` (section lines between header and end)
and the digest;
`axocoatl record verify <file>` prints the summary and exits 0, or 2 on mismatch. No
credential value can appear: routes never record credentials and the bundle reads only
recorded evidence.

### 5.5 Core implementation notes (contract details settled while building)

- **Run record order.** The driver records `RunEvent::Ended` and then writes
  `outcome.json`; once `outcome.json` exists the record takes no more events. A page of
  `GET /api/runs/{id}/events` says `finished` only when the run had ended before its
  events were read and the page holds the rest of them (`limit` not reached), so a
  client that stops at `finished` has seen `Ended`. `?wait_ms=` (default 1000, at most
  5000) bounds the long poll; the server reads the record with the daemon released
  between reads.
- **Admission.** The loadout Session is native, `mode: custom` with no configured Agents
  (the run applies the loadout's own team before the first turn), bound with
  `SessionStore::bind_loadout` before its environment is first prepared (a Session is
  bound once, only to `egress`/`none` + `hardened`). Admission refuses E2B and rootful
  Podman (`podman info … Rootless`) before creating anything, and a `network: none`
  loadout whose Agents list `web_search`, `web_fetch`, `browser` or `browser_check`
  (also refused by `validate_loadout`). A qa run's `target_url`/`reference_url` must be
  `http://localhost:<port>` (the port becomes a Session exposed port) or a host under
  `browser.allow` (else 422 → exit 3). A failed environment still creates the run: its
  manifest, an `Ended` event and an Outcome with the setup output (exit 5), so `--junit`
  and `--record` are written. Admissions are idempotent on `request_id` within the
  daemon process; the same id with another body is 409.
- **Token floor.** Admission refuses (usage error, exit 3) a run whose Agent or reviewer
  cannot make one model call within its `tokens` budget, before anything is created,
  naming the budget and the minimum (`team_plan::refuse_budgets_below_one_call` with each
  caller's `team_plan::call_floor` and `CallBudget::refusal_with`). The floor is what one
  call of the model needs as its provider shows it before the run
  (`team_plan::AdmissionObservations`): a native Ollama model's loaded context (observed as
  its first call observes it) plus the output bound, since such a call reserves its whole
  context; a native OpenRouter model's smallest call as Team & budget checks it
  (`NativeOpenRouterObservation::minimum_call_bounds`), read from OpenRouter's public
  catalog (`GET /models`, no key, `axocoatl_llm_openai::catalog_call_floor`): the
  4,096-token prompt allowance within the model's `context_length`, plus the output bound
  and the reasoning allowance of the Agent's effort or the model's default, never the whole
  context window, since a call reserves its own request; and an external writer's pinned
  model (`external_agent::models`): the most one call of the program can use (the context
  the program keeps plus the model's output limit, within the model's window: 400,000
  tokens for Codex 0.160.1's models, the 1,000,000- or 200,000-token window for Claude
  Code's). For Claude Code, `PINNED_MODELS` lists each Claude API model that has not
  retired (Anthropic's model overview, model pages and deprecations page, 2026-10-08;
  Claude Mythos Preview aside, whose window they do not state) and
  `CLAUDE_CODE_ALIASES` maps Claude Code 2.1.292's aliases to the model each runs, read
  as text from the `aliases` of the model catalog bundled in its linux-arm64 binary (not
  run), which it resolves them by when no `ANTHROPIC_DEFAULT_*_MODEL` is set and it has
  no served model list (`GET /v1/models` is not on its route): `opus` → `claude-opus-5-5`, `sonnet` → `claude-sonnet-5-5`, `haiku` →
  `claude-haiku-4-5`, `fable` → `claude-fable-5-1`, `best` → `claude-fable-5-1`
  (`claude-opus-5-5` without Fable) and `opusplan` → `claude-sonnet-5-5`
  (`claude-opus-5-5` in plan mode); every target a resolution can reach has the same
  window and output limit. A trailing `[1m]` resolves only where the model's window is
  already 1M tokens. `default` (the account's or organization's model) is not pinned.
  The refusal names the model an alias runs. OpenRouter's catalog is read once per
  admission (`e2e::OnceCatalog`) and also serves the e2e model check. A floor that cannot be known
  (an Ollama model that cannot be observed, a catalog that cannot be read or does not
  list the model) leaves a native caller the validation minimum (2,048 plus the output
  bound); an external writer whose model is not pinned is not checked, and the run
  carries the warning `external_model_not_pinned` on `agents.<id>.model`, which also
  says whether its cost will be known.
- **Inline definitions.** `SessionTeamSlotEdit.definition: Option<InlineAgentDefinition
  {source, tools, runtime, reasoning_effort}>` and `ReviewSetting.inline:
  Option<InlineReviewer {name, provider, model, instructions, definition}>` carry a
  loadout's Agents and reviewer through the ordinary preview → apply path (absent keeps
  the historical serialized shape; human graph edits refuse `definition`). Top-level
  loadout slots are `Autonomous`; the reviewer is a read-only `Worker` shown under
  `template_id: "loadout-reviewer"`. An Agent or reviewer without `max_output_tokens`
  gets 8,192 (`team_plan::DEFAULT_MAX_OUTPUT_TOKENS`): a native Agent always runs with an
  explicit sampling maximum. **External runtimes**: the retained `AgentConfig` of a
  `claude-code`/`codex` writer has `provider` = the runtime id and `model` = the
  program's model, and no tools; workstream agents branches on that provider.
- **Check options.** Apply validates `check_options` with
  `check_options::validate_check_options`. Until runtime's option-aware `turn_checks`
  constructor lands, options whose timeout is the default (3 minutes) and that name no
  report are accepted (names label the Outcome); any other timeout or a report is
  `NotImplemented` (501, exit 5), never ignored. The integrator replaces that refusal with
  the runtime call.
- **Host interface.** `RunHost` gained defaulted methods (`recorded_events`,
  `network_summary`, `stop_requested`, `finish`, `tool_calls`) so fakes in other
  workstreams keep compiling; `tool_calls` returns a turn's recorded tool calls with
  their arguments and outcome (`ToolCallRecord`, from the Session's invocation audit,
  the host's repository captures left out; `None` for a host without that record); `apply_team` applies on the Session's current configuration revision.
  `CheckLabel::of_edit` names the applied checks. `DaemonRunHost::send_turn` starts the
  turn as `/ws` does; `wait_turn` polls the control-plane projection (with the new
  `review_rounds: Vec<ReviewProof>`) every 500 ms, releasing the daemon between reads,
  and fails the run as infrastructure when the turn could not start.
- **Errors.** `DaemonError::NotFound` (unknown loadout or run) is 404; the CLI maps 404
  and 422 to exit 3, 401/403 to 4, any other error status to 5.
- **Session reads.** `GET /api/sessions/{id}` returns one Session (with `loadout`).
- **Data root.** Loadout Sessions need native Session history: a data root the daemon
  created itself has it, and so does one that existed before the first start but has no
  `.axocoatl-daemon.lock`, no prepared conversion and empty Session stores; one that holds Sessions from an earlier Axocoatl, or that an
  earlier daemon used, needs `axocoatl session upgrade --confirm` (daemon stopped, after
  a cold backup) before its first run, and until then `create_loadout_session` refuses
  every run ("loadout runs need native Session history").
- **Workspace busy.** Admission never waits for the Workspace: when its operation lock is
  held, the run is refused at once, before a Session or a run is created, naming what
  holds it (the open Sessions whose turn is running or needs attention, with their run
  and turn, `workspace_in_use`): `DaemonError::WorkspaceBusy`, `409` with
  `code: workspace_busy`, exit 7; retry later. Every other request a person waits on
  takes the Workspace operation through `bootstrap_workspace_operation.rs`, and each
  holder names itself (and the Session it acts for) while it holds it, so a refusal
  says what holds it:
  - lifecycle actions (Session creation, Close, Delete, Reopen, environment changes
    and repairs, runtime-cleanup confirmation, the Session stops before several Ways)
    never wait for another Session's work: `take_lifecycle_workspace_operation`,
    `take_session_lifecycle_operation` and, for Close, Delete and environment
    changes, `take_session_lifecycle_workspace` take it before anything changes or
    refuse at once, naming the holder (another Session's turn, file or Git change,
    Ways, creation or run admission). Close and Delete wait only for their own
    Session's work: its own registration (its turn, stopped, until the running
    command reaches a safe point; `prepare_session_cleanup_with` in
    `CleanupWorkspace::Lifecycle` mode, at most `SESSION_LIFECYCLE_CLEANUP_TIMEOUT`,
    30 s), its running Ways or Ways checks (interrupted) or its legacy turn (asked
    to stop), and its runtime while it starts (each at most `OWN_WORK_RELEASE_WAIT`,
    15 s). In that mode the cleanup takes the Session's cleanup gate and, between
    turns, the Workspace with `try_lock` before it closes admission, so a refusal
    (another lifecycle action of the Session, or a Workspace another operation took)
    changes nothing;
  - other requests (attachments, file and Git changes, Ways reads, checks, judge and
    Keep) are refused at once while any open turn of the Workspace holds it, and wait
    at most `WORKSPACE_OPERATION_WAIT` (10 s) for an operation that is not a turn,
    then are refused, naming it.
- **Leaked Session volumes.** A Session's runtime volumes (`axo-egr-`, `axo-egi-`,
  `axo-svc-`, `axo-ca-`) carry the runtime authority label of the daemon that made
  them (`io.axocoatl.runtime-authority`, the digest of its data root), as its
  containers do; every daemon since these volumes exist (1.2.0) sets it. Close removes
  them. A Node project's dependency volume (`axo-ses-<id>-node-modules`, a Way's named
  after its container) outlives Close for Reopen and is removed by Delete; since 1.3.0
  the start path creates it with the same label (`podman volume create --ignore`, role
  `node-dependencies`) before the container mounts it, so one made earlier has none. At
  start, right after every container of its authority is removed and before any Session
  can start (or, when Podman is not running then, in `ensure_deferred_local_cleanup`
  before the first local Session starts), `reap_leaked_runtime_volumes`
  (`bootstrap_runtime_volumes.rs`, `axocoatl_isolation::runtime_volumes`) lists both
  kinds with their label and removes, never forced: the runtime volumes of its own
  authority whose Session (or, for a Way's volume, `attempt-<session key>-…`, the Way's
  Session) is closed, deleted or unknown to its data root, and the dependency volumes of
  its own authority whose Session is deleted or unknown. An open Session's runtime
  volumes and an open or closed Session's dependency volume are kept, another
  authority's are never touched, and a volume without the label is removed only when
  its name is a Session of this data root: a closed or deleted one's runtime volume, a
  deleted one's dependency volume. A Session record the daemon did not load at start (it
  could not, or hid it) counts as a closed Session (`SessionStore::record_ids`). A
  Session is a deleted one of this data root when the store has no record of it but the
  data root still holds its native History
  (`UpgradedFormatOwnership::holds_session_history`: Delete keeps the journals), which
  no other data root has; a Way's unlabelled volume whose Session is gone cannot be
  traced and is kept. The counts go to the log and, through the IPC request
  `RuntimeVolumes`, to `axocoatl doctor` ("Session volumes: …").
- **Restart.** A loadout Session's mode is `Custom` with no Agents (its run applies the
  loadout's team), which startup validation accepts only with its `loadout` binding;
  so a run's Session loads again after a restart and gets its loadout's network
  additions back.
- **Closing turns.** Once the run has everything its Outcome needs, before the Outcome is
  written, `close_open_turns` stops each turn the run started that was not observed
  completed (phase `closing_turn`), as a person's Stop does, waits for it to settle and
  stops it once more, so the run's Session no longer holds the Workspace and the next run
  on the repository is admitted. The Outcome keeps each turn as it was observed. A Stop
  that fails is logged; the next admission then names the Session that still holds the
  Workspace.
  An audit also stops a turn that ended needing attention before its next Apply
  (`closing_turn` too); the line says what the audit does about it by the turn's
  purpose (`audit::closing_detail`): for areas and follow-ups, that their areas without
  a result are listed as not covered; for a plan turn, which has no areas, that a
  planner without a usable plan gets its one retry and a second attempt without one
  leaves the whole scope not covered (resmoke9's out2 said "its areas" of a plan turn);
  for an integration and a re-ask, what their own rules do.
- **Restart.** At startup unfinished runs end failed ("the daemon restarted during the
  run; it was not resumed"), and loadout Sessions get their loadout's egress additions
  back from their run manifest (`SessionEgressPoints::set_loadout_overlay`). A reload of
  the network lists re-applies each Session's additions; an addition that no longer fits
  the configured lists is dropped (the Session gets less, never more).

## 6. Outcome extensions

`RunOutcome` (schema `axocoatl.run-outcome/1`) adds to what a Session turn shows:

- `checks: Vec<CheckResult>` — one per required check of the final turn, with `report`
  parsed from the check's JUnit or e2e `report.json` (§8.2).
- `review: Option<ReviewOutcome>` — reviewer identity, every round (`verdict`, `passed`,
  `findings_text`, `findings` split into ids, `continued`, `candidate_sha256`).
- `adjudications: Vec<Adjudication>` — every finding of every round whose findings the host
  sent back to the writer, with the writer's `accept`/`reject` and reason, or `missing`.
- `findings: Vec<Finding>` — qa explorer findings with `repro: ReproResult`
  (`classification` ∈ `confirmed`, `fails_on_clean_build`, `reproduced`, `not_reproduced`,
  `repro_error`, `missing`) and audit findings (integrated, with `area`). An audit
  finding's `location` is checked as it is read (`audit_plan::split_location`): a line
  counts only when what follows the first `:` starts with a number above 0 (after an
  optional `L` or `line`), alone or before a column, range or space; then `location`
  stands as written and `line` is that number. Otherwise `location` is the file alone
  and `line` is `null`, never the model's placeholder (resmoke9's re-ask answered
  `ingest/feed.go:line_number` from prose that named no line, which the host kept), so
  the summary and JUnit show the file only; a location naming no file (`N/A`,
  `unknown`) is dropped, and `line` is absent without a location.
- `not_covered: Vec<NotCovered>` — every area, helper, slot or node that ended without a
  result, with `FailureClass` (`provider_refusal`, `provider_failure`, `provider_rejected`,
  `budget`, `blocked`, `not_reached`, `runtime_limit`, `stopped`, `other`) and detail.
- `unreadable_findings: Vec<UnreadableFindings>` — audit areas whose files were read but
  whose worker's findings could not be read even after its re-asks (`area`, `detail`, the
  `answers` as written, each bounded, and the last node and turn); each needs attention
  ("Findings unreadable for <area>"), apart from coverage; absent when empty.
- `notes: Vec<String>` — what the run noticed that is neither a gap nor a warning, in
  words (an audit worker's `NOT_REACHED` list, the files the host gave the area `rest`
  or assigned by directory, a planned area left without files, a file too large to
  read); never changes the verdict; absent when empty.
- `warnings: Vec<RunWarning>` — `same_model_reviewer` and any other run warning.
- `usage` — tokens, `cost_microunits` (what the run's grants were charged), `complete`
  (false: the numbers are a known subtotal), `cost_known` (false when a call's cost is not
  known: a Codex writer on a model without a price, a call that ended before its provider
  reported one, or grants that could not be read; `cost_microunits` then counts those
  calls' reservations, which stay charged; absent in records written before it, read as
  true), `cost_computed` (true when part of the cost is Axocoatl's computation from a
  program's reported tokens at its model's price, a Codex writer's, rather than a
  provider's report; absent when false), `retries`.
- `network` (record summary: events, allowed/refused connections, route requests
  per host), `keep`, `attention` (reasons in words), `verdict`, `exit_code`, `error`.

The same-model warning appears in five places: loadout validation (`LoadoutWarning`), the
API (`RunAccepted.warnings`, `SessionTeamView.warnings`, `LoadoutSummary.warnings`), the
web UI (Team and budget review and the run outcome panel), `axocoatl run` output, and the
record (`RunEvent::Warning` and `outcome.warnings`).

## 7. Built-in loadout behavior

### 7.1 fix (review-qa)

- One turn: writer + required checks + required review (1.2 machinery: checks run on the
  exact candidate between two captures; the reviewer starts only after readiness passes;
  `CHANGES` with rounds left sends the findings back to the writer in a new epoch).
- Reviewer prompt (`session_dispatch_turn_review.rs`): the host appends the rule "Number
  each finding `F1`, `F2`, … at the start of its line" to the reviewer's bounded prompt.
- Revision note to the writer: the host appends "Answer every finding below in an
  `ADJUDICATIONS` block: a fenced JSON array of `{"id":"F1","decision":"accept"|"reject",
  "reason":"…"}`, one entry per finding, then fix each finding you accept."
- `split_findings(findings_text)`: lines starting with `F<n>` (optionally bold/bulleted)
  start a finding; text until the next id belongs to it; no ids → one finding `F1` with the
  whole text. At most 64 per round.
- `parse_adjudications(answer)`: the block after the last `ADJUDICATIONS` heading, fenced
  or not (`headed_block`, §7.4), or, with no heading, the whole answer when it is exactly
  a JSON array; invalid JSON → every finding of that round `missing` with reason
  "unreadable adjudications block".
- `adjudicate(rounds, writer)`: for each round with `continued == true`, the writer
  generation that started after that round answers it; one `Adjudication` per finding;
  unknown ids ignored (recorded in detail), duplicates take the first. The final round's
  findings are adjudicated only when the host sent them back.
- Warn (never refuse) when the reviewer's resolved provider:model equals the writer's.
- `ReviewRound.findings` filled from `split_findings`.

### 7.2 qa (review-qa)

- One turn: the explorer alone (no helpers, no review, no merge, no verifier); `writes`
  limited to `repro_dir/**`.
- `repro_dir`: `write_file` creates no directories, so before the explorer's turn the
  driver creates a missing `repro_dir` in the repository (`prepare_repro_dir`, each
  component opened from its parent's handle without following links, created
  owner-only; a `preparing` phase says so). Admission (`check_repro_dir`) and the driver
  refuse a run whose `repro_dir` or a component of it is a symbolic link or not a
  directory (exit 3), so nothing is created or written through a link.
- The explorer's final answer carries (each block read as §7.4 says; with no heading,
  the whole answer as an object with `findings` and `coverage` keys):
  - `FINDINGS`: JSON array of `ReportedFinding {id, title, area?, severity?,
    expected, actual, repro}`;
  - `COVERAGE`: JSON array of `CoverageEntry {area, status: covered | not_reached |
    blocked, reason?}`.
- For each finding: `repro` must be a path under `repro_dir` that exists in the checkout
  (else `missing`). The host runs `run_repro(target_url)` and, when `reference_url` is
  configured, `run_repro(reference_url)`, each one `browser_check` of that file (one worker,
  no retries) in the browser container; `classify(target, reference)`:
  fails on target and passes on reference → `confirmed`; fails on both →
  `fails_on_clean_build` (listed as "fails on clean build", not confirmed); fails on target
  with no reference → `reproduced`; passes on target → `not_reproduced`; any error →
  `repro_error`.
- `reference_url` and `target_url` must be reachable by the browser container: a Session
  exposed port (`http://localhost:<port>`) or a host under `browser.allow`; otherwise the run
  is refused at admission (exit 3).
- Not covered: each coverage entry `not_reached`/`blocked`; when the explorer node failed
  (classifier stop/refusal → `provider_refusal`, provider failure, budget, round limit) every
  area not reported `covered` plus one entry "remaining app" naming the class; no COVERAGE
  block at all → one entry "whole app (no coverage report)". Never a silent pass.
- `fail_on_findings` (default true): `confirmed`/`reproduced` findings need attention.

### 7.3 audit (audit)

Turns in one Session (each with its own Team and budget Apply): the plan, the areas
(one turn or more), the follow-ups (rounds while each reads something new), the
re-asks (at most 2 rounds), the integration (with its retry or re-asks).

1. **Plan**: slot `planner` alone; request = prompt + "Answer with one `AREAS` block of
   `min_areas`-`max_areas` areas". `parse_plan` → 2-8 areas with unique names `[a-z][a-z0-9-]
   {0,31}`, non-empty scope. An invalid plan gets one host retry turn with the parse error,
   and a planner without an answer (a provider failure, say) gets one retry turn with the
   plan request again, its failed node accounted for by the driver (`KindReport::
   accounted`) so the Outcome does not list it again; a planner stopped by the wall clock
   or a person, or refused by its provider (400-403), is not retried. A second attempt
   without a plan ends the run needing attention with not covered "whole scope", which the
   attention line words as "The whole scope was not covered".
2. **Assignment** (`audit::files`, host-verified coverage): after the plan the host
   lists the repository's files on the host (`list_repository`): in a Git work tree
   `git ls-files --cached --others --exclude-standard -z` through `git_host::
   repository_git` (every command-bearing setting overridden), else, or when Git cannot
   list it, a walk that skips `fs_tools::GLOB_SKIPPED_DIRECTORIES` (what `glob` skips) and
   links; regular files only, nothing inside `.git`, at most 20,000 (`MAX_LISTED_FILES`;
   past it `not_covered {area: "unlisted files"}`). Each file has a kind: empty, binary
   (a NUL byte in its first 8,000 bytes, Git's rule), too large (over 256 KiB,
   `MAX_AUDITED_FILE_BYTES`) or text. `assign` gives each file to the first area whose
   paths match it (`area_holds`: the pattern matches, or a literal pattern names the file
   or a directory above it; a leading `./` or `/` means the root); a file no area's paths
   match goes to the area whose paths' literal leading directories share the most
   directories with the file's (the first such area on a tie), else to a host-made area
   `rest` (`rest-2`, … when the planner used the name), whose scope says so. A planned
   area left without files is not run. Then `split` divides every area whose text files
   need more `read_file` calls than one worker activation makes (`ReadBudget`: one read
   per default window of each text file, the window being `read_file_window` of the
   worker's model context as admission observed it, `RunContext::agent_contexts`, 64 KiB
   when unknown; one activation makes its `invocations` less a fifth held back, at least
   4, at two invocations a read, at most `MAX_TURN_READS`, 200) into numbered sub-areas
   `<area>-1`, `<area>-2`, … (`<area>-part<n>` when another area has that name): as few
   as hold its reads, of consecutive files in path order, each within the budget; a file
   is never split. Each sub-area keeps the area's scope and paths, and its worker's
   instructions say which part of which area it reads. The plan as executed (a split
   area replaced by its sub-areas) and the assignment are `assigned` phase events (a
   summary, then one line per area with its files, bounded); each split (with the reads,
   window and budget it was judged by), the files given to `rest` or by directory and the
   areas not run are notes. A listing that fails leaves the whole scope not covered.
3. **Areas**: one slot `worker-<name>` per area of the plan as executed, instantiated
   from the `worker` Agent, read-only (`writes: []`) with `read_file`, `list_dir`,
   `grep` and `glob` and no shell (through rc9 it had `bash`, under Landlock; in
   resmoke9 two workers spent 39 minutes on 80 and 81 `bash` calls printing "final audit
   confirmation" scripts, and out1's tests worker made 85; no Agent of the built-in audit
   has `bash` now),
   `reset_history: true` (fresh context), no dependencies between them, all `required`,
   so the controller runs them in parallel; each worker's instructions name its area's
   scope, paths and the text files it must read (`file_list`: one per line up to 8 KiB,
   else the directories they are in with counts, as deep as fits, and the instruction to
   read all of them), how the host checks reads, and the `FINDINGS` and `NOT_REACHED`
   blocks. One turn runs at most `MAX_WORKERS_PER_TURN` (16) workers whose planned reads
   (each worker's, at most its budget) add up to at most `MAX_TURN_READS` and whose
   instructions add up to at most 128 KiB (`worker_turns`); more run in further turns of
   the same purpose, whose requests say which of the areas they audit. A turn's record
   holds a bounded number of tool calls: an areas turn whose workers asked for 501 small
   reads at once on Podman recorded 430 and declined the rest, which is why a turn is
   planned at 200. No required checks or review on audit turns.
4. **Follow-ups**: a text file is read (`files::unread`, `files::Coverage`) when the
   bytes returned by the succeeded `read_file` calls of it (paths relative to the
   repository or absolute inside it), among the tool calls the Session recorded
   (`RunHost::tool_calls`) for the activations of its area's worker that answered,
   cover every byte of it, whatever its size: each call covers the window its kept
   result reports, from its `offset` (the call's own when the result names none, as for
   a read from the start) for its `returned_bytes`. A call whose result the Session did
   not keep whole covers nothing. (1.3.0 rc7 counted any read starting inside a file of
   up to 64 KiB, so a `limit: 64` read of an 802-byte file passed a run that never saw
   its defect; `resmoke7_run_9_a_partial_read_of_a_small_file_is_followed_up`.) Empty
   and binary files need no read; a too-large file is a note. `grep`, `glob`, `list_dir`
   and `bash` read nothing for coverage. When an area's text files are not all read
   after a turn, the host runs a follow-up round (purpose `audit_follow_up`, its own
   Apply, in turns as in step 3) with a fresh read-only activation of every such worker,
   whose instructions name exactly its unread files ("Read these files and report
   additional findings in the same format"). Rounds go on while each worker's last
   follow-up read bytes of its files that no earlier read returned (`files::Coverage::
   covered_text` grew); a worker whose follow-up read nothing new gets no more. There is
   no fixed count: the run's wall clock and the progress rule bound them. A worker
   without a result gets its first follow-up too, unless its failure would repeat
   (`budget`, `stopped`, `provider_rejected`), its record of tool calls cannot be read,
   or the `worker` Agent has no `read_file`. A follow-up's findings join the area's
   report with ids `<area>-followup<n>-<id>`; failed worker nodes go to
   `KindReport::accounted`. The wall clock or a person's stop ends the follow-ups.
   `read_file` itself: a read without `limit` returns the calling Agent's default window,
   64 KiB or a quarter of its model's context counted at one token per byte when smaller
   (`fs_tools::read_file_window`; the provider's live context, which for a native Ollama
   model is its loaded context; a `limit` above it reads the window); the window travels
   as a hex dump (`od`), so `returned_bytes` and `next_offset` count the file's own bytes
   even when it is not UTF-8, a window that would end inside a character ends before it,
   and only `content` is decoded (U+FFFD, `invalid_utf8: true`).
   Then each area's coverage is a `coverage` phase event (examined of total, read,
   `not read: empty`, `not read: binary`, `not read: too large`, unread), and what is
   not covered is listed: a worker that never answered (`the area worker has no result:
   …`, its failure class), findings left out beyond 200 (`other`), a record of tool calls that cannot be read (`other`, "not known"), and each
   text file still unread, by file (`"<path>: not read (<why>)"`; up to 100 per area,
   then one entry naming the rest's directories), whose class says why: the worker's
   failure class, `not_reached` when its last follow-up read nothing new, `budget` or
   `stopped` when the wall clock or a stop ended them. An area whose worker's turn never
   started (a later areas turn the wall clock or a stop prevented) is one entry. A worker's `NOT_REACHED` list is a note
   (`"<slot> listed as not reached: …"`), never a gap: the host's coverage decides.
   Notes are `note` phase events and the Outcome's `notes`. The attention line counts
   distinct areas, not entries.
   **Re-asks** (`Audit::reask_workers`, before the coverage above is concluded): a worker
   with an accepted answer that `parse_area_report` refuses gets up to `MAX_REASKS` (2)
   re-asks, one round each, at most `MAX_WORKERS_PER_TURN` to a turn of purpose
   `audit_reask` (`REASK_PURPOSE`). Each is a fresh read-only activation of
   `worker-<area>` whose slot has no tools (`reask_slots`: `agent.tools` cleared) and
   whose instructions (`reask_instructions`; the loadout's worker instructions left out,
   since they ask for reads) quote every unreadable answer of that worker, fenced, with
   its parse error, the last re-ask's error, and the exact instruction: write the findings
   it describes as one `FINDINGS` JSON array in the documented format, `[]` when none, and
   call no tool. Like follow-ups they stop at the wall clock or a stop, an `applying_team`
   and a `reask` phase record each, a re-ask node without a result goes to
   `KindReport::accounted`, and one that ends `budget`, `stopped` or `provider_rejected`
   gets no next re-ask. A re-ask's tool calls are never read for coverage. A readable
   answer restates the unreadable ones: its findings take the ids the first of them would
   have had (`<area>-<id>`, or `<area>-followup<n>-<id>`), its `NOT_REACHED` is dropped.
   Coverage and findings are separate: an area whose findings are still unreadable is not
   `not_covered`; it is a `findings_unreadable` phase and a
   `run_outcome::UnreadableFindings {area, detail, answers, node_id, turn_id}` in
   `KindReport::unreadable_findings` → `RunOutcome::unreadable_findings` (every answer
   the host could not read, re-asks included, each bounded to 24 KiB), and `decide` adds
   the attention line "Findings unreadable for <area>[, <area>…]". The summary lists them
   under "Findings unreadable:", JUnit as `<failure type="findings_unreadable">` cases
   `<area> (findings unreadable)` of the `findings` suite (the last answer in
   `<system-out>`), and the Run outcome panel in its own section; the integrator still
   receives the answer as text (`AreaBody::Unreadable`).
5. **Integrate**: slot `integrator` alone; request = the accepted worker findings (each
   bounded to 24 KiB, truncation noted; an area whose worker left files unread says how
   many) + the list of not-covered entries; `parse_integrated`
   → `findings`. An integrator without an answer gets one retry turn (purpose
   `audit_integrate` again) unless the wall clock, a stop or a 400-403 refusal ended it;
   an answer `parse_integrated` refuses gets up to `MAX_REASKS` re-asks (`audit_reask`),
   each a fresh integrator slot without tools (`integrate_reask_slots`) sent the integrate
   request again plus every unreadable answer quoted with its error and the instruction to
   answer with the `FINDINGS` block only and call no tool. Failed integrator nodes go to
   `KindReport::accounted`. When the answer is still unreadable (or the wall clock or a
   stop left no re-ask), or the integrator still has no result with class
   `provider_failure`, `provider_refusal` or `provider_rejected`, the host merges
   (`audit::host_merge`): the union of the area reports' findings in area order, each
   keeping its area and source `audit_worker`, without a finding whose `(file, line,
   normalized title)` an earlier one has (file: the location before the first `:` that a
   digit follows, `./` dropped; line: that number; title: lowercase alphanumeric words);
   the note "findings merged by the host: <why>, … (<n> findings, <m> kept)" is recorded
   and `KindReport::last_turn_accounted` is set, so the integrator's last turn does not
   count as a turn that needs attention. This is not an attention item: in the 1.3.0
   measured runs the merge step never added a finding. Without a result for another
   reason (the wall clock, a stop, any other class), the workers' findings are reported
   unmerged and `not_covered {area: "audit integration"}` (`run_outcome::INTEGRATION`, no
   area name since it has a space) is recorded; the attention line counts only areas and
   adds "The integration was not read; the area findings are reported unmerged".

A person's stop (`POST /api/runs/{id}/stop`, Ctrl-C) starts no further Apply or turn:
areas not started, files no follow-up read and an integration not run are
`not_covered {class: stopped}`, the workers' findings are reported unmerged, and `drive_audit` returns the
report with `KindReport::stopped` instead of an error, so the Outcome keeps the turns,
not-covered entries, findings and usage observed so far, with the verdict `interrupted`.
`run_to_outcome` marks usage incomplete when a turn's usage is, or when the record holds
a `TurnStarted` turn it never observed.

Budgets: each slot gets `budgets.agent` (or its `budget`) for each turn it is in; the
run's wall clock bounds every turn. The split estimate assumes each read takes its own
model call; a model that asks for several reads at once uses fewer invocations, and one
that reads less than its budget allows is followed up. Docs state the measured trade-off exactly: on an audit larger than one context,
orchestrated read-only area workers had recall +11 points (99% vs 87%) and precision −8
points at about 3× the tokens and the same wall time, measured with Claude Code subagents
on Claude Opus (not through Axocoatl), and the +11 is a sensitivity analysis (the study's
preregistered exclusion rule excluded 9 of 10 attempts), not a preregistered result.

### 7.4 How answers are read (review-qa, audit)

The prompts ask for a heading and a fenced block; the parsers also read what models write
instead (`review_adjudication::headed_block`, shared by `qa_repro` and `audit_plan`):

- A heading is a line naming the block in any case, with optional Markdown heading, list,
  quote, emphasis or code marks and a colon, words joined by a space, `-` or `_`
  (`## Findings`, `**findings:**`, `- Not reached`). After it, the block is the first JSON
  object or array that starts a line before the next heading or fence (on the heading's
  line after the colon, right below it, or after a line of text), else the fenced block
  that follows, else the text that follows, which the parser then reports as not valid
  JSON. Of several headings, the last with a JSON value or a fenced block wins. A heading
  with nothing after it is an error.
- An XML-style tag of the heading's name (any case, the same word rules) is a heading:
  `<FINDINGS>` opens the block, text after it on its line starts it, and `</FINDINGS>`
  ends it and opens nothing. A JSON value followed on its last line by a closing tag
  (`[...]</FINDINGS>`) is read as the value.
- Without the heading: `ADJUDICATIONS` reads the whole answer when it is exactly a JSON
  array; qa reads the whole answer when it is an object with `findings` and `coverage`
  keys; audit's `AREAS` and `FINDINGS` read the last fenced block that is an object with
  `areas` or `findings`, else the whole answer when it is that object or a bare array (a
  worker's object may also carry `not_reached`). Audit object keys match in any case,
  ignoring `_`, `-` and spaces (`FINDINGS`, `NOT_REACHED`, `notReached`).
- A block that is present but is not the JSON it should be is an error with the parser's
  message, never a guess: its adjudications are `missing`, its qa report or audit area
  is not covered, and an invalid plan gets the one retry.

## 8. External agents, secrets, e2e

### 8.1 External agents (agents)

- Loadout: `runtime: claude-code` or `codex` on the writer; `model` is the program's model
  name (`{provider: anthropic, model: claude-…}` / `{provider: openai, model: …}`).
  `tools` are ignored (the program brings its own). The retained definition's `provider`
  is the runtime id (`claude-code`, `codex`) and its `model` the program's model (§5.5).
  The writer's model names the provider whose API its program is configured to call
  through the route Axocoatl adds (`AgentRuntime::model_provider`: `anthropic`, `openai`);
  `validate_loadout` refuses another provider for a literal model and `resolve_loadout`
  for a parameter (`--model writer=openrouter:…` exits 3), so the identity a run records
  is the one that ran. The run driver's observation names the writer's node
  (`NodeObservation.model`, which the fix driver's same-model check compares with the
  reviewer) as `team_plan::model_identity` names the loadout's writer:
  `observation_from_control_plane` and the Team view (`team_warnings`, whose slots are
  rebuilt from retained definitions) map a definition whose provider is a runtime id
  through `external_agent::definition_identity` to `{provider: anthropic | openai, model,
  runtime: claude-code | codex}`, never `{provider: <runtime id>, runtime: native}`. The
  same-model check (`run_outcome::same_model_warning`, and `ModelSpec::same_model` in
  validation and resolution) compares `axocoatl_core::model_key`s: a vendor's API name and
  OpenRouter's `vendor/model` name of one model are the same model (case, `.` against `-`,
  a snapshot date, `-latest` and an OpenRouter `:variant` left out), so a reviewer on
  `openrouter:anthropic/claude-haiku-4.5` is warned about for a Claude Code writer on
  `anthropic:claude-haiku-4-5`, and one on `openrouter:openai/gpt-5.5` for a Codex writer
  on `openai:gpt-5.5`. A Claude model (`anthropic:` or `openrouter:anthropic/`) is keyed by
  family then version (`anthropic/claude-haiku-4-5`, whichever order the id writes them
  in), and on `anthropic:` a Claude Code alias is keyed as the model it runs
  (`axocoatl_core::CLAUDE_CODE_ALIASES`, moved from `external_agent::models`, which
  re-exports it; `best` and `opusplan` as their default model) with a `[1m]` suffix left
  out, so `anthropic:haiku` and `openrouter:anthropic/claude-haiku-4.5` are the same
  model either way round. `external_agent::models::resolve` still reads an alias and
  `[1m]` itself before comparing, so admission names the alias and never pins `[1m]` on a
  model whose window is smaller. Other providers' names (Ollama's) match only themselves.
- Image: `environment.recipes: [claude-code]` (or `[codex]`), built with
  `axocoatl recipe build claude-code` (pinned versions, recorded image id, trusted for
  Sessions by that id like the browser image).
- Execution (`run_external_activation`, hooked from `bootstrap_native_activation.rs` where
  the native port would start its tool loop for an Agent whose retained definition has an
  external runtime): the activation is admitted, granted and captured exactly like a native
  writer (Before capture, After capture, write-scope check). The program runs through the
  in-sandbox supervisor as the hardened writer user under `--harden`, with the activation's
  wall-clock timeout, stdout to a bounded file (≤ 16 MiB), its JSON parsed into
  `ExternalItem`s retained as the activation's evidence (assistant text = the answer; tool
  calls/results bounded previews) and the final answer accepted as the node's output.
- `axocoatl connect claude-code` (`axocoatl-cli/src/connect_cmd/`) obtains that token:
  it runs `claude setup-token` in a pseudo-terminal the size of the user's terminal
  (`relay::program_size`: at least 40×24; in a smaller one Claude Code, which redraws
  only the rows that fit, can leave the token's first rows undrawn while drawing the
  rest), resized on `SIGWINCH`. Claude Code 2.1.271 (read from its bundle) draws the
  token with its own Ink renderer: a `Text` in the `warning` color in a box with
  `paddingLeft: 1`, hard-wrapped by wrap-ansi at the box's width, each row placed by
  `CR` + `CSI n C` + `CSI n B` (or `CSI n G` after `CR LF` in a full redraw), and later
  frames write only changed cells. So the output filter (`redact::TokenFilter`) runs
  every byte through a terminal model (`screen::Screen`: cursor, autowrap, wide
  characters, CSI movement, erasure, insertion, scrolling with stable row numbers, the
  alternate screen, SGR renditions) and matches runs of token characters by the cells
  they land in, holding output only while `sk-ant-` is incomplete. A run continues on
  the next row when the cells right of its end and left of the new character are
  blank or frame characters, the rendition is the run's, and the run reached the right
  edge (6 columns of padding and border at most) or the new row starts in the run's
  column (an unstyled run's continuation then is masked but not stored); cells a
  renderer skipped as unchanged are read from the model. Each token cell is shown as the
  next cell of `[token hidden by axocoatl]`, so the layout never changes. From a resize
  until an absolute move, an erase or a quiet output, continuations are lenient and
  tokens are "suspect" (used only when no other was read, then the last). OSC, DCS, APC,
  PM and SOS strings are held whole; clipboard writes (OSC 52, 5522, iTerm2 `Copy`, and
  DCS passthroughs of them) and strings holding a token are dropped. A token is cut where
  `sk-ant-` starts again, and a wrapped continuation followed on its row by more text
  after a blank is dropped when the rest is still a whole token; the stored value must
  be `sk-ant-oat01-` and 32 to 499 base64url characters (the bundle fixes no length). The
  keystroke relay stops the moment the program exits (a waiter thread reaps it) and
  checks its stop flag after `poll`/`select` and before each read, so nothing typed
  during the token check is read away from the shell. Every buffer that may hold the
  token is overwritten when emptied or freed; the `Authorization` value is a
  `Bytes::from_owner` over a zeroizing buffer, and the verifying client keeps no idle
  connection.
- Credentials: `axocoatl secret set claude-code-oauth` reads the output of
  `claude setup-token` from stdin, and warns (still storing it) when the value has
  whitespace inside it, starts with `Bearer `, looks like JSON, holds several tokens or,
  for a Claude Code route's secret, does not start with `sk-ant-oat01-`. A program's
  model call answered `401` through its route (the route meter reads the `response`
  event of a credentialed request) names the rejected stored credential and how to store
  it again, first in the provider failure and so in the not-covered reason. The route for Claude Code: host `api.anthropic.com`,
  credential `claude-code-oauth`, `inject: {header: Authorization, format: "Bearer {}"}`,
  rules for the Messages API paths the pinned version uses, `env_placeholders:
  [CLAUDE_CODE_OAUTH_TOKEN]`; environment `DISABLE_TELEMETRY=1`,
  `DISABLE_ERROR_REPORTING=1`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`,
  `DISABLE_AUTOUPDATER=1`. Codex: `axocoatl secret set codex-openai`, route
  `api.openai.com` with Bearer injection, `env_placeholders: [OPENAI_API_KEY]`. Routes come
  from `external_agent::routes_for(runtime)` and are merged into the run Session's policy by
  `loadout::egress::loadout_policy` (core). The Session CA is trusted through the existing
  trust env (`NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`).
- The routes stay minimal: each allows only the model-call path the pinned version was
  seen to send (`POST /v1/messages`, `POST /v1/responses`), since every request a rule
  allows gets the credential. Claude Code 2.1.292 also sends `GET
  /api/claude_code/policy_limits` and `GET /api/claude_code/settings`; the route refuses
  and records both, and a run passes without them (the pinned Podman tests allow only
  those two refusals). A loadout's own route for the same host replaces the added one.
  Each route of a loadout Session carries its `RouteOrigin` (configured, the loadout's,
  or added for an external writer, `EgressPolicyConfig::route_origins`), so a refused
  request's 403 hint, and the `route_not_for_binding` hint, name the loadout's route or
  the writer's added route instead of a `sandbox.egress.routes[N]` the configuration does
  not have.
- Accounting: the activation reserves its grant's full token limit up front, and its full
  cost limit when the run's cost will be known; usage the program reports settles it; no
  report → usage incomplete and the reservation stays charged (the 1.2 rule). Claude Code
  reports its cost (`total_cost_usd`, its own computation from list prices). Codex reports
  tokens but never cost: its run is priced from its reported tokens (uncached input, cached
  input, cache writes and output, reasoning included) at its model's price
  (`external_agent::models::computed_price`): the configuration's `pricing` entry for that
  exact model name when there is one, else the pinned list price in
  `external_agent::models::PINNED_MODELS`, OpenAI's Standard price for prompts of at most
  272K input tokens on each Codex 0.160.1 API model (`gpt-6-astra`, `gpt-6.1-sol`,
  `gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5`),
  read 2026-10-08 from OpenAI's model pages (Codex 0.160.1 keeps a 272,000-token context
  for each and `codex exec` sends no service tier, so a run is billed at those rates). The
  call settles to that cost (`StreamEvent::CostObservation`; above what the grant still
  allowed it is an overrun, as a reported cost is), its work log says how it was computed,
  and the run's usage is `cost_computed`, which every rendering marks ("includes cost
  computed from reported tokens at list prices"). A Codex model without a price keeps its
  cost unknown: such an activation reserves only the cost left divided by the activations
  left (its own included), since a whole-grant reservation would leave a review's revision
  activation nothing to spend; its calls settle with `cost_known: false` and every
  rendering says "cost unknown (reserved up to $X)" rather than presenting the reservation
  as a price; admission warns about such a model (`external_model_not_pinned`). Route
  requests count against the grant's invocations; the host stops the program when they
  run out.
- Gaps to state honestly: per-call budget enforcement is the route's request count and the
  program's own report, not a per-call reservation; the program's internal tool calls are
  evidence, not Axocoatl-admitted tool calls.

### 8.2 e2e check (e2e)

- Loadout check `run: {e2e: {args, model_route, model}}`, `timeout` up to 30 min.
- Image: `environment.recipes: [e2e]` (Node ≥ 22.22.3 or ≥ 24.8, Chromium, `e2e@0.18.0`
  installed globally, pinned by version and integrity), owner e2e for the fragment.
- `expand_e2e_check` produces `["sh", "-c", <wrapper>]` and `RequiredCheckOptions {name,
  timeout_ms, report: {format, path: /tmp/axocoatl-check-reports/<name>/…}}`. The wrapper:
  forces `E2E_TELEMETRY_DISABLED=1`, sets the model and the route-backed base URL / key
  placeholder in the environment, runs `e2e <args>` writing JUnit and/or `report.json` under
  the report directory, then prints `AXOCOATL-CHECK-REPORT sha256=<hex>` of the report as
  its last stdout line and exits with e2e's status.
- `.e2e/cache` is read-only for the check: the Session container mounts
  `<workspace>/.e2e/cache` read-only over the read-write workspace mount when the loadout has
  an e2e check (`session_sandbox.rs`, e2e).
- The model key goes through `model_route` (a route with a credential from the secret
  store); the container sees a placeholder. e2e's agent needs tool calls and vision: for an
  OpenRouter model the admission checks the catalog's tool and image-input capabilities and
  refuses otherwise (exit 3); for other providers a warning says the capability is not
  verified.
- `collect_reports` (after the run's final turn): for each check with a `report`, read the
  report from the Session container (`read_sandbox_file`, ≤ 4 MiB), accept it only if its
  SHA-256 equals `report_marker(stdout)` of the final recorded run, parse with
  `parse_junit` / `parse_e2e_report_json`, attach as `CheckResult.report`. A missing or
  unbound report leaves `report: None` with `reason` set; the check's pass/fail still comes
  from its exit status.

## 9. Keep as PR (keep)

- `POST /api/sessions/{id}/keep-pr` with `KeepPrRequest {run_id, branch?, open_pr,
  remote?, title?}`; CLI `axocoatl run --keep branch|pr`; UI button in the run outcome panel
  (`<ax-keep-pr>`).
- Only for a finished run of that Session whose verdict is `pass` (else 409 with the
  reason).
- Paths: the run's changed paths = the Session's changes attributed to the run's turns
  (the "Last turn" attribution, across the run's turns) minus nothing; refuse when any of
  them is in the manifest's `dirty_paths` (it had uncommitted changes before the run).
- Commit with host git without touching the person's checkout: a temporary
  `GIT_INDEX_FILE` seeded from `HEAD`, `git update-index --add/--remove` of exactly those
  paths from the working tree, `git write-tree`, `git commit-tree -p HEAD` with the message
  (title + run id), `git update-ref` of the new branch (refuse if the branch exists). HEAD,
  the real index, the current branch and the working tree are unchanged. A run path whose
  status changed after the run ended is refused (§16).
- PR (opt-in): refuse when the branch name equals the remote's default branch or the
  current branch is pushed under the name; `git push <remote> <branch>:refs/heads/<branch>`
  without `--force` (and refuse if the remote ref exists); `gh pr create --head <branch>
  --base <default> --title … --body-file <tmp>`. Body (`pr_body`): verdict, check results
  table, review verdict and rounds, adjudications table, findings, not-covered list,
  warnings, record id (`run_id`) and how to verify the bundle. Host `git` and `gh` use the
  person's own credentials on the host; nothing runs in a container and no credential is
  read by Axocoatl.
- Record `RunEvent::Phase("keep", …)` and `outcome.keep` (the Outcome file stays written
  once: Keep results are recorded as events and exposed as `keep` in the status view).

## 10. Runtime policy (runtime)

- **Provider retry** (`provider_retry::decide`): 429, 5xx, timeout, connection reset → one
  retry after `Retry-After` (≤ 30 s) or 2 s, on the same pinned model and endpoint; 400,
  401, 402, 403, refusal, safety stop → no retry. Applies to native OpenRouter, native
  Ollama and any native provider path. The retry is a new provider call with its own
  reservation (refused if the grant cannot pay; then the failure stands); the failed call
  keeps its accounting per 1.2. Each retry is recorded on the activation's evidence and as
  `RunEvent::ProviderRetry` for loadout runs.
- **Not covered**: a failed helper (`delegate`), slot or area is recorded with a
  classifiable failure (status, refusal flag, recorded class) so `classify_failure` maps it
  to a `FailureClass`; the lead still receives its tool error as in 1.2, and the Outcome
  lists the helper as not covered. Never dropped. A stopped activation is `stopped`, not
  `blocked`: a read-only Agent's captures that a Stop cut short (the After capture is
  skipped) are no reason (`write_scope_violation`), with or without a shell, and a
  stopped writer's failure begins "it was stopped before the host could capture which
  files it changed" (`execution_content::STOPPED_BEFORE_CAPTURE`), class `stopped`. In
  resmoke9 a Stop during the areas turn listed two read-only workers with `bash` as
  `blocked` by "its repository captures cannot establish which files it changed".
- **Repeated calls** (`axocoatl-actor::tool_loop_repeats`, any native Agent): besides
  three rounds that only print and four identical rounds, when `REPEATED_CALL_LIMIT` (8)
  of the last `REPEAT_WINDOW` (10) calls with the same tool and arguments, or of the last
  10 `bash` commands with the same `command_pattern` (program name and first option,
  such as `python3 -c`), showed nothing new, wherever they fall, the next request goes
  without tools and asks for the final answer, saying "you repeated the same call (…) 8
  times without new results"; a response that calls a tool instead fails the activation
  with that reason, which follow-ups and re-asks then handle like any worker without a
  result. A result shows nothing new when at most one in four of its non-empty lines is
  new (seen in no earlier result of the activation and not in the call's own
  arguments); a successful `write_file` or `edit_file`, or a `bash` call that printed
  nothing, clears the counts; terminal polls never count. A replay of the recorded tool
  calls of the 1.3.0 re-smokes through the same rules (a script, not the daemon; 344
  activations, few of them writers) ends 14, all in audit runs: resmoke9 out5's auth and
  notify workers after 48 of 86 and 31 of 85 calls (`python3 -c`, `grep -n`) and out1's
  tests worker after 68 of 92 (`find`).
- **grep output**: at most 64 KiB of whole matching lines. A cut result keeps
  `truncated: true` and adds `returned_matches`, `total_matches`, `total_bytes`,
  `omitted_matches`, `omitted_bytes` (the same grep counted by `wc -lc` in the sandbox,
  its output never brought back) and a `message` saying what was left out and to narrow
  the search with a path or a more specific pattern.
- **Check timeouts**: `check_options[i].timeout_ms` (default 180,000 ms, 1 s to 30 min)
  flows into the admitted `RepositoryCheckDefinition.timeout_ms` and the condition
  permission's `max_timeout_ms` (cap raised from 180,000 to `MAX_CHECK_TIMEOUT_MS`);
  graphs admitted by 1.2 (all 180 s) still verify. The Team and budget API accepts
  `check_options`; the skeleton's refusal at Apply is removed.
- **Host Ollama route**: `sandbox.egress.host_ollama: {port, for}`. Under `network:
  egress`, containers reach `https://ollama.host.axocoatl.internal` (set as `OLLAMA_HOST`
  for the bound processes); the decision point recognizes the name without DNS, the broker
  ends TLS with the Session CA and forwards over plain HTTP to `127.0.0.1:<port>`, and every
  request and response is recorded like any route. Only loopback; off by default; refused
  under `bridge`/`none` with a warning; `validate_host_ollama` checks the port and bindings.

### 15.1 Decisions made at integration

- **Check egress.** Under `network: egress` a required check gets no egress credential,
  so e2e's model calls could not reach their route. `RequiredCheckOptions` and
  `RepositoryCheckDefinition` gain `egress` (serde default `false`, omitted when false,
  so every 1.2 definition and its digest are unchanged; `admitted_check_definitions`
  reads it back from the graph). `expand_e2e_check` sets it. `start_repository_check`
  mints a `GrantKind::Agent` credential for exactly that process (agent
  `required-check`, process = the condition run id) and holds it until the check
  settles, as a writer's shell does. Every other check still has no network.
- **Recipe images.** Admission sets a loadout Session's image to the recorded image id of
  `axocoatl recipe build <recipes>` (`AxocoatlDaemon::recipe_image`), and Session start,
  the image preflight and attempts trust an image when `sandbox.allow_untrusted_images`
  is set or it is exactly a recorded recipe image id (`session_image_trusted`).
- **External writers.** Team Apply turns an inline definition with an external runtime
  into `external_agent::external_agent_config` before the definition is prepared.
- **Admission.** qa runs call `loadout::qa::validate_qa_admission` (exit 3 on error);
  every run calls `loadout::e2e::verify_e2e_models`, whose warnings join the resolved
  loadout's warnings. The read-only `.e2e/cache` mount is decided before the Session's
  first container starts (`session_has_e2e_check` knows the run before its manifest is
  written).
- **Observation.** `ReviewOutcome.rounds` come from `ReviewProof::to_round` (findings split
  by id before the text is bounded). `usage.retries` counts
  `provider_retry::run_events` of the turn, and the server's run host appends those
  events to the run record once per turn when the turn ends.
- **Recording.** Kind drivers record their own Phase, Adjudication, Finding, NotCovered
  and Warning events; `run_to_outcome` records only warnings and not-covered entries
  not already in the record.
- **Keep.** `RunStatusView.keep` is the latest `keep` Phase event
  (`keep_pr::keep_result_of`); the Run outcome panel passes it to `<ax-keep-pr>` with
  the loadout id and reads the run again on `keep-pr-result`.

## 16. Known gaps (stated, not hidden)

- External agents' spend is enforced by up-front reservation, route request counts and the
  program's own usage report, not per call (§8.1).
- e2e's capability check is exact only for OpenRouter models; others get a warning.
- A daemon restart during a run fails the run rather than resuming it.
- Keep as PR commits only the run's attributed paths. It refuses a run path whose status
  changed after the run ended (inode change time, `git_host::changed_since` against the
  Outcome's `finished_at_ms`), so an edit made after the checks and review judged the files
  is refused rather than committed; an edit the person made to a run path while the run was
  still going cannot be told apart from the run's own.
- Web tools (`web_search`, `web_fetch`) run on the host and follow the global
  `sandbox.network` (refused only under `none`); a loadout under `network: none` refuses
  them at validation and admission. `request_network_access` is offered only when the
  global network is `egress`, so a loadout Session under a global `bridge` cannot ask a
  person for a host; a headless run has no person to ask.
- Run idempotency on `request_id` lasts for the daemon process's lifetime only.
