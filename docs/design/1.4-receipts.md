# Axocoatl 1.4: signed receipts

Status: proposed scope, built in parallel branches from `main` at `c8bced0` (1.3.1). This
document is the contract between the branches. Where it and the code disagree, the code's
types win and the owner of the file fixes this document. Decisions marked **(maintainer)**
are recommendations recorded for the maintainer to confirm.

## 0. Why

Axocoatl already records what happened in a run and already has the host, not the agent,
decide whether the work passed: required checks run on the exact final files, and a required
review by a different model whose findings the writer must answer. What it cannot do yet is
hand that verdict to someone else in a form they can check without trusting the person who
ran it. The record bundle proves it is intact (its last line is a SHA-256 of every earlier
byte), not who produced it: anyone who edits it can recompute the hash.

A receipt closes that gap. It is a small signed statement, made by the daemon when a run
finishes, that says which files the run changed (with the digest of each file's content as
the checks judged it), what the host enforced (sandbox, network policy, checks, review,
adjudications, budgets), which programs and models wrote and reviewed, and the verdict.
Keep as PR carries it into the pull request; a verifier checks the signature against keys
the receiving repository trusts and checks the pull request's files against the digests.

### Invariants

1. Isolation is never weakened; every 1.3 invariant in `1.3-loadouts.md` section 0 holds.
2. The signing key never leaves the data root: not in a log, record, message, API response,
   container or command line. Only the public key is shown.
3. A receipt never says more than the host observed. A field the host could not establish is
   absent or says so (`"source": "workspace_at_finish"`), never guessed.
4. Nothing new needs an account or the network. Signing and verifying work offline.
5. No AI attribution in commits; nothing is pushed or published without the maintainer.

## 2. Receipts (C)

### 2.1 Key

- One Ed25519 key per data root, made by the daemon the first time it signs (or by
  `axocoatl receipt key`), with `ring` (already a dependency of `axocoatl-daemon`):
  `Ed25519KeyPair::generate_pkcs8`, stored with the secret store (`secret_store::set_secret`)
  as the secret `receipt-signing-key` (PKCS#8 v2 bytes, base64; `0600`, written atomically,
  under the secrets lock). Reading it uses the same store. It is never a route credential:
  the egress broker refuses to send it (`MANAGED_VALUE_PREFIX`-style refusal or an explicit
  name check).
- Key id: `sha256:` + hex SHA-256 of the 32-byte raw public key. Display form: the first 16
  hex characters.
- `axocoatl receipt key` prints one line for a trusted-keys file and exits 0:
  `ed25519 <base64 raw public key> axocoatl@<hostname> <key id prefix>`. It makes the key when
  none exists (saying so), using the data root of `--config` or `AXOCOATL_DATA_DIR`.
- `GET /api/receipts/key` returns `{ "algorithm": "ed25519", "public_key": base64, "key_id": … }`.
- Rotation: `axocoatl receipt key --rotate` replaces it and prints the new line; old receipts
  stay verifiable with the old public key line. (Optional in 1.4 if time allows; if not, say
  how to rotate by removing the secret.)

### 2.2 Statement

An [in-toto Statement v1](https://github.com/in-toto/attestation/blob/main/spec/v1/statement.md):

```json
{
  "_type": "https://in-toto.io/Statement/v1",
  "subject": [ { "name": "src/lib.rs", "digest": { "sha256": "<hex>" } } ],
  "predicateType": "https://axocoatl.ai/receipt/v1",
  "predicate": { … }
}
```

- `subject`: one entry per path the run changed that exists after the run (the same paths
  Keep as PR attributes, `keep_pr::RunAttribution`), sorted by name, with the SHA-256 of the
  file's content (for a symlink, of its target, as the capture manifest records it). Source,
  in order of preference: the manifest of the final candidate's check capture
  (`BeforeCheck` of the last turn that ran checks), else the last writer activation's After
  capture, when complete (`manifest_complete`); else the files read on the host when the run
  finishes. `predicate.files.source` says which: `judged_capture`, `after_capture` or
  `workspace_at_finish`. Removed paths go in `predicate.files.removed`. A run that changed no
  file has an empty `subject`. Unattributable activations go in `predicate.files.unattributed`
  (with Keep's reason) and make `predicate.files.complete` false.
- `predicate` (field order fixed by the Rust struct; every map a `BTreeMap`):
  - `run`: `run_id`, `session_id`, `started_at_ms`, `finished_at_ms`, `axocoatl_version`,
    `task_sha256` (the task text itself is not repeated; it is in the record).
  - `repository`: `base_commit` (HEAD when the run started, from the manifest), `dirty_paths`
    (manifest), `origin_url` when the repository has an `origin` remote (read with host git
    the way Keep reads it; absent otherwise).
  - `loadout`: `id`, `version`, `digest`.
  - `agents`: per Agent slot: `id`, `role`, `runtime` (`native`, `claude-code`, `codex`),
    `program_version` for external programs (pinned versions), `provider`, `model` as resolved,
    `credential` name for external writers (never the value).
  - `sandbox`: backend, `network` (`egress` / `none` / `bridge`), `workload`, the egress
    allowlist hosts, and each route's host and rules as the Session policy recorded them
    (from the route's `canonical()`), including whether the provider-fetch guard was on (A).
  - `network`: the Outcome's `NetworkSummary` (requests, refused, hosts).
  - `checks`: per check: `name`, `state`, `exit_code`, `duration_ms`, and the command.
  - `review`: model, verdict, rounds used, number of findings; `adjudications`: per finding
    `id` and `decision`.
  - `verdict`, `exit_code`, `attention`, `not_covered` (count and areas), `warnings` (codes).
  - `usage`: tokens, `cost_usd`, `cost_known`, `cost_computed`.
  - `files`: `source`, `removed`, `complete`, `unattributed`.
- Serialization: `serde_json::to_vec` of the struct, no pretty printing. Signature
  verification covers the exact payload bytes, so verifiers never re-serialize.

### 2.3 Envelope

A [DSSE](https://github.com/secure-systems-lab/dsse/blob/master/envelope.md) envelope, media
type `application/vnd.dsse.envelope.v1+json`:

```json
{ "payloadType": "application/vnd.in-toto+json",
  "payload": "<base64 statement>",
  "signatures": [ { "keyid": "sha256:<hex>", "sig": "<base64 ed25519 signature>" } ] }
```

The signature is over DSSE's PAE: `"DSSEv1" SP len(type) SP type SP len(body) SP body`.
Ed25519 is deterministic, so signing the same statement twice gives the same bytes.

### 2.4 When it is made, where it is kept

- The driver signs right after `host.finish(&run.run_id, &outcome)` writes `outcome.json`
  (`crates/axocoatl-daemon/src/loadout/driver.rs`), for every finished run whatever its
  verdict. It is written once as `{data root}/loadout-runs/{run_id}/receipt.dsse.json`
  (`0600`) through `RunRecordStore`. A failure to sign is recorded as a run warning
  (`receipt_unavailable`, with why) and never changes the verdict or exit code, so a key
  problem cannot turn a failing run into a passing one or the reverse.
- `GET /api/runs/{run_id}/receipt` serves it (404 until the run finished, with a message).
- Record bundle: schema `axocoatl.record-bundle/2` adds a last section `receipt` (the
  envelope as JSON) after `run_event`. `axocoatl record verify` accepts `/1` and `/2`.
  A bundle of a run without a receipt has no `receipt` line.

### 2.5 CLI

- `axocoatl run … --receipt FILE`: writes the envelope when the run finished, as `--junit`
  and `--record` do (also on a failing run). When the run was never admitted there is nothing
  to sign: write nothing and say so.
- `axocoatl receipt show FILE|-`: the statement in words (run, verdict, checks, review,
  models, files, key id). Does not verify; says so.
- `axocoatl receipt verify FILE|- [--key LINE]… [--keys FILE] [--repo DIR] [--record BUNDLE] [--json]`:
  1. parses the envelope and statement (refusing unknown `_type`/`predicateType`);
  2. checks the signature against each trusted key (`--key` lines, `--keys` file in the
     `axocoatl receipt key` format, `#` comments); with no trusted key given it reports the key
     id and exits with "signature valid, signer not trusted" (its own exit code);
  3. with `--repo DIR`, hashes each subject path in that checkout and checks each removed path
     is absent; any difference is listed;
  4. with `--record`, verifies the bundle (`verify_bundle`) and that its `receipt` section is
     this envelope and names the same run.
  Exit codes: 0 valid and trusted (and matching, for the checks asked); 1 bad signature or
  malformed; 2 valid signature but untrusted signer; 3 usage; 4 files or record do not match.
- `axocoatl receipt key [--rotate]` (2.1).
- Never needs a running daemon, Podman or the network: `verify` and `show` are pure.

### 2.6 Keep as PR

- Before committing, Keep reads the run's receipt and hashes each path it is about to commit
  in the working tree. A path whose content differs from its subject (or a removed path that
  exists again) is refused: "`<path>` changed after the run's checks judged it; Keep commits
  only what the receipt covers". A run with no receipt keeps today's behavior and says the
  pull request has no receipt.
- The commit message gains trailers `Axocoatl-Run: <run id>` and
  `Axocoatl-Receipt: sha256:<SHA-256 of the statement payload>`.
- The pull request body gains a **Receipt** section near the top: signer key id, verdict,
  checks, review model and verdict, writer program and model, files covered, and how to
  verify; then the envelope, base64, inside
  `<!-- axocoatl-receipt:v1` … `-->`. The body cut (`MAX_BODY_CHARS`) never cuts this block.

### 2.7 Web UI

- Run outcome panel (`axocoatl-server/static/ui/run-outcome.js`): a "Receipt" line with the
  signer key id, files covered and a download link to `/api/runs/{id}/receipt`; when signing
  failed, the warning.
- Settings shows the public key line with a copy button, next to Loadouts (no new top-level
  destination; see `AGENTS.md`).

## 3. verify-receipt Action (D)

A composite action at `actions/verify-receipt/action.yml`, used as
`axocoatl/axocoatl/actions/verify-receipt@v1.4.0`:

- installs the pinned Axocoatl release for the runner (Linux x86_64 or ARM64) and checks the
  archive against the release's published checksum;
- reads the pull request body from `GITHUB_EVENT_PATH` and extracts the envelope block;
- reads the trusted keys from the BASE branch (`gh api …/contents/<keys-file>?ref=<base sha>`),
  never from the pull request's head, so a pull request cannot add its own key;
- runs `axocoatl receipt verify - --keys … --repo .` on the checked-out head and lists the
  pull request's changed files (`gh api …/pulls/<n>/files`); a changed file the receipt does
  not cover fails unless `allow-uncovered-files: true`;
- writes a job summary (verdict, checks, review, models, signer) and fails on any problem;
  `require-receipt: false` makes a pull request without a receipt pass with a notice.

It is verified end to end on a real GitHub pull request before it is documented as working.

## 4. Provider-fetch guard (A), built-in agent loadouts (B), site (E)

A, B and E are specified in their branches' task statements; their results are summarized
here when they land. Decisions recorded so far:

- **(maintainer)** A: on routes to known model APIs (`api.anthropic.com`, `api.openai.com`,
  `chatgpt.com`, `openrouter.ai`), the broker reads the JSON request body and refuses
  provider-side fetches (server tools, MCP connectors, URL-sourced images and files, web
  plugins) by default, with a per-route opt-out recorded in the Session policy.
- **(maintainer)** B: `fix-claude-code` and `fix-codex` become built-in ids; a person's own
  loadout file with either id is listed with an error that says how to rename it. A Codex
  writer's credential can resolve automatically to whichever of `codex-openai` and
  `codex-chatgpt` is stored, and the run records which one it used.
- **(maintainer)** C: a local Ed25519 key per data root (no account, offline); Sigstore
  keyless later. Receipts for every finished run, not only passing ones. Keep refuses files
  changed after they were judged.

## 5. Done means

- A real `axocoatl run fix …` produces a receipt; `axocoatl receipt verify --repo` passes on
  the untouched checkout and fails after a one-byte edit; Keep as PR opens a pull request whose
  body carries the receipt; the Action passes on that pull request and fails on a pull request
  with an extra commit or an untrusted key. Each of these is run, not only unit-tested.
- `./scripts/preflight.sh` is green; CHANGELOG, README, docs and marketing say exactly what
  ships.
