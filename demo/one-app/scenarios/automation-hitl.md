# Human-in-the-loop Automation

This film demonstrates a durable executable DAG that pauses for judgment and
continues from the operator boundary.

## Claim

The seeded **Spec review** Automation accepts runtime input, executes an Agent,
maps three review perspectives, takes a conditional branch, durably parks at a
top-level Interrupt, survives a daemon restart against the same data root,
resumes with operator guidance without replaying upstream nodes, and preserves
node-by-node run history and final content.

## Do not claim

- An Automation is not a Session transcript or a scheduled chat macro.
- Durability is proven at the top-level Interrupt boundary. A daemon crash in
  an arbitrary provider call or nested Subgraph Interrupt is not resumable by
  this scenario.
- The operator decision is not generated by the model and is not optional in
  the blocking branch.

## Start or reset

After closing previous demo Sessions and stopping the daemon:

```bash
./demo/one-app/prepare.sh --scenario signal-desk
AXOCOATL_DEMO_ROOT=/private/tmp/axocoatl-one-app-showcase-signal-desk \
  ./demo/one-app/start.sh
```

In a second terminal, after the daemon is healthy:

```bash
./demo/one-app/seed-runtime-demos.sh
```

The seeder creates or updates `spec-review-demo` in the canonical Automation
store.

## Browser actions

1. Open **Settings → Automations → Spec review · multi-perspective with HITL**.
2. Show the DAG at rest: Text input, architect, Map/reviewer body, conditional,
   Interrupt, and planner.
3. Choose **Run** and keep this seeded input exactly:

   ```text
   A real-time chat app that stores every message in plaintext and has no rate limiting.
   ```

4. Watch the graph advance through `spec-prompt`, `architect`, and
   `review-each`. Show that Map runs the security, performance, and UX reviews.
5. Wait for `approval-gate` to take the `blocking` edge and park `approve`.
6. Open **⏸ 1 waiting** and verify the prompt includes the reviewers' blocking
   evidence.
7. With the run parked, stop `start.sh` with Ctrl-C. Do not run `prepare.sh` and
   do not reseed Automations. Restart the exact same root with:

   ```bash
   AXOCOATL_DEMO_ROOT=/private/tmp/axocoatl-one-app-showcase-signal-desk \
     ./demo/one-app/start.sh
   ```

8. Reload the browser. Confirm **⏸ 1 waiting** rediscovers the same run id and
   `approve` node, with `spec-prompt`, `architect`, `review-each`, and
   `approval-gate` still completed rather than replayed.
9. Resume with:

   ```text
   Reject the plaintext design. Require encryption at rest, tenant isolation, per-user and per-IP rate limiting, abuse monitoring, retention controls, and a threat model before implementation.
   ```

10. Watch the planner run from the saved upstream outputs plus the operator
   value.
11. Reload once more. Open **Runs** and inspect the completed run, submitted
    Text input, branch, node outputs, checkpoints, and exact recorded
    `final_content` Result.

## Visible proof

- Runtime Text input is saved with the run.
- Map produces three perspective reviews rather than one generic response.
- The conditional chooses a labeled blocking route based on actual output.
- The run becomes interrupted and discoverable in the rail.
- The same pending Interrupt is rediscovered after daemon restart.
- Resume does not replay already completed upstream nodes; it continues to the
  planner and leaves a completed history record with final content.

## Durable and API evidence

While the run is parked:

```bash
export AXO_DEMO_URL='http://127.0.0.1:18080'
export AXO_DEMO_ROOT='/private/tmp/axocoatl-one-app-showcase-signal-desk'
curl -sS "$AXO_DEMO_URL/api/interrupts"
curl -sS "$AXO_DEMO_URL/api/automations/spec-review-demo/runs"
```

Copy the run id, then inspect it before and after Resume:

```bash
export AXO_RUN_ID='paste-the-run-uuid-here'
curl -sS \
  "$AXO_DEMO_URL/api/automations/spec-review-demo/runs/$AXO_RUN_ID"
sed -n '1,320p' \
  "$AXO_DEMO_ROOT/data/runs/spec-review-demo/$AXO_RUN_ID.json"
```

Capture the run JSON immediately before stopping the daemon and again after
restart but before Resume. The run id, completed upstream node outputs, branch,
and parked Interrupt must match. After Resume, `/api/interrupts` should no
longer list the parked node and the same run file should be terminal with the
operator value and completed planner `final_content`.

## Recording beats

1. Open on the complete DAG, then choose Run with the risky design visible.
2. Follow node pulses through architecture and the three mapped reviews.
3. Slow down on the labeled blocking branch and parked Interrupt.
4. Restart against the same root and show the same waiting run without replay.
5. Enter the operator's explicit remediation requirements and Resume.
6. Reload and end on the exact planner Result in completed run history.

Target 45–65 seconds after editing. Compress provider wait time, but keep the
Map, branch, Interrupt, and Resume state transitions in order.

## Cleanup

1. Resume or explicitly skip every pending Interrupt and wait for the run to
   become terminal. Capture the run file first.
2. Close any demo Session opened for navigation and stop `start.sh` with
   Ctrl-C.
3. Reset with `./demo/one-app/prepare.sh --scenario signal-desk`, restart the
   same Signal Desk root, and run `./demo/one-app/seed-runtime-demos.sh`
   against the fresh daemon.

## Known constraints

- A top-level Interrupt is persisted atomically with the interrupted run state.
- Restart recovery is valid only after that park is durable. A run orphaned
  during later provider/tool work is marked failed rather than fabricated as
  resumed.
- Cancelling an Interrupt continues with an empty value; it is not a whole-run
  rollback. This film uses Resume, not Cancel.
- The exact Agent prose can vary. The literal `BLOCKING` instruction in the
  reviewer config is what makes the blocking branch rehearsable.
